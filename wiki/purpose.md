# Purpose — 这个 wiki 为什么存在

> **三份配置的分工**（不要互相抄）：
> - `schema.md` / `AGENTS.md` —— wiki **怎么运作**：目录、页面类型、frontmatter、流程、铁律。
> - 本文件（`purpose.md`）—— wiki **为什么存在、该问什么、边界在哪、当前立场**。以月/季为单位变。
> - `overview.md` —— wiki **现在有什么、在跟什么**（版图快照 + 活跃线索）。每次沉淀都可能变。

## 目标

把 AI/Agent 工程与商业研究中**反复用得上的判断**编译一次，之后只保鲜、不重推。

单条准入标准：**一年后我还会引用它吗？** 会 → 沉淀；不会 → 不进 wiki（时效性动态留在 `briefs/`，或直接丢弃）。

## 关键问题（驱动本 wiki 的长期提问）

1. Agent 能力落到生产要跨哪些**具体**门槛？——不是 demo 能否做出来，而是逃逸缺陷率、事故率、人工介入率。
2. Agent 化之后，软件的**价值捕获点**从哪里移到哪里？（per-seat → outcome/consumption；UI 租金 → system of record）
3. 知识与规格如何在人和 agent 之间**保持不漂移**？（规格控制面、四类漂移、持续调和、自动退役）
4. Agent 需要什么样的**知识—记忆—行动架构**？（权威事实 → 派生表示 → 检索 → 记忆 → 编排 → 外部行动 → 验证调和）
5. 如何用 **evals 与反馈闭环**驱动工程与产品演化？（分钟级自测、小时级开发者反馈、天/周级外部反馈）
6. 泛主题（叙事结构、儿童学习媒介等）**只在能抽出可复用方法论时**进入。

## 范围

**在范围内**

- 技术 / AI：架构、Agent、LLM 工程、开发治理（SDD、文档漂移、AI 原生 SDLC、企业知识治理）
- 投资 / 商业研究：AI 对软件业价值链与估值逻辑的重构。同一实体可同时是技术标的与投资标的——一个 entity 页 + 多标签
- 方法论本身：知识组织、叙事与论证结构、评估（evals）
- 泛主题：仅当能抽出可复用判断（例：[[书与AI的优势边界及家庭组合]]）

**明确不在范围内**

- 逐日新闻、股价波动、融资快讯 —— 只能作为论点页下的**证据行**，不单独建页
- 操作性备忘（命令用法、环境配置、API 参数）
- 模型跑分与版本发布追踪 —— 除非它改变了某条已有判断
- 客户名、内部代号、未核实数据进入对外产物 —— 内部代号只允许出现在 `output/personal/`

## 演化中的核心论断（被证据修正时，直接改这里）

1. Agent 的瓶颈已从**能力**转到**治理与验证**：控制单元从逐项人工审查上移到身份、委托、风险门禁、可观测与事故反馈；在代码库一侧，则上移到 agent 所处的环境——guides、sensors 与定期清理。推论：补模型短板的方法折旧最快，解决信任、协调与责任的方法保值，与委派规模正相关的（认知债、意图规格化、prompt 架构评审、验证容量）升值；投入顺序由依赖关系定，折旧速度只定投入上限。限定（2026-11）：受控实验里，上下文文件这类 guides 在前沿模型上不提升单次成功率，收益主要落在 token 成本与回归可观测性；验证与周期清理仍不可省。（[[Anthropic-AI原生SDLC治理循环]]、[[agent-生产级落地的鸿沟]]、[[Harness Engineering]]、[[AI工程方法论的耐久度]]、[[全AI代码库的治理决策]]、[[上下文经济性]]）
2. 漂移的本质是**调和机制缺失**，不是文档写得不够；测试是证据、不是裁判。（[[代码与文档漂移的本质]]、[[论代码与文档漂移解决方案]]）
3. Agent 知识层必须区分**权威事实与派生表示**；检索方式按问题类型路由，而非在 Vector / Graph 间二选一。（[[从知识图谱到 Agent 编排]]、[[GraphRAG 与 Vector RAG]]）
4. AI 编码下，局部产出、实际任务速度、主观感知、维护负担与 release 价值**可能朝不同方向变化**（METR：2025 年初工具下实测慢 19%，自评却快 20%），不能用任何单一层的数字代表整体。体验下滑是过渡期阵痛还是结构性代价，尚无定论；需要产品与组织层面对冲。（[[生产力-体验悖论]]）
5. SaaS 的危险区不是"出现了 AI 竞品"，而是**只有功能层、没有 system of record**。（[[cowork-saas-资本市场冲击]]、[[system-of-record 与专有数据护城河]]）
6. 知识资产的复利来自**论点吸附证据**，而非条目堆积——这是本仓库自身的方法论押注。（[[llm-wiki-方法论]]）

## 当前重心（2026-11）

- 验证 SDD 的**转化命题**：默认收益假设已失去支撑——现有最大样本的观察证据指向反向（相关而非因果，
  原文未取得，见 [[SDD 收益主张的实证赤字]]）。原问法"补齐组织可行性证据"预设了净收益成立，不再适用。
  新问法：规格把符合性漂移转化为表达 + 生命周期漂移，**只有配套建了调和机制才划算**——需要"建了调和机制 vs
  只写规格"的对照数据。
- 用真实查询集验证检索路由（Vector / Text2Cypher / GraphRAG Global / 混合）的质量与成本。
- 跟踪 Demo→生产的**可量化**结果指标，而非渗透率口径。
- 代码库作为 agent 的运行环境：用全新会话重放代表性变更，测结构债的 token 税与治理回本（[[全AI代码库的治理决策]]、
  [[上下文经济性]]）；跟踪人侧理解与监督带宽能否被量化（[[LLM 输出的人类理解瓶颈]]）。
- 常驻 agent 的授权与算力：授权放在模型之外、对 agent 不可写，常驻程度由谁付算力决定（[[Agent 授权三层]]、
  [[agent-工具执行的运行时授权治理]]、[[常驻 Agent 的算力经济学]]）。
