# AI 工程方法论的耐久度

> 用户 2026-10-08 提出的判断框架（调研稿续篇 §7，逐项核验见
> [[2026-10-08-agentic-se-refactoring-methodology-补充研究-源摘要|源摘要]]），先用来盘点
> [[Agentic SE 时代的系统重构]] 的全部条目。本页的分档是**用户判断**，维护者补的部分标"综合"；
> 尺子与分档之间有几处对不上，列在文末，等用户裁定。立场仍在演化。

## 尺子：看存在理由，不看现在多有效

一条方法论会不会被更强的模型抹平，要看**它为什么存在**：

| 存在理由 | 模型变强后 | 典型条目 |
|---|---|---|
| 补模型现在的短板 | **抹平 / 大幅减弱** | prompt 技巧、context engineering 机制层 |
| 省计算的钱 | **部分贬值**：绝对成本降，相对优势长存 | 窄读取、省 token 的工具输出 |
| 解决人对系统的信任、协调与责任 | **保值** | 显式契约、验证网、characterization tests |
| 与委派规模正相关 | **升值** | 认知债管理、意图规格化 |

第一档是 bitter lesson 的作用区。Sutton（2019）的原意是：长期看，能随算力扩展的通用方法胜过注入人类知识的
专门方法。用户的引申是，押注模型弱点的工程投资，折旧期可能只有一两年（用户估计，无测量）。

推论：**折旧的单位是条目，不是支柱。**上下文经济性、文档、ACI 这些支柱里，都同时有折旧件和资产件。

## 盘点：重构方法论的四档（用户判断）

### 抹平 / 大幅减弱

- 上下文经济性的技巧层：极小文件、代码 SEO、文档精细分层
- context engineering 机制层：compaction、外置笔记、子 agent 压缩回传。这些正被 harness 与模型内建吸收，
  从方法论降格为基础设施。核验成立（[[2026-10-08-agentic-se-refactoring-methodology-补充研究-源摘要|源摘要]]）：
  Anthropic 2025-09-29 推出 context editing 与基于文件的 memory tool，2026-02-05 上线服务端 compaction API（beta）；
  Claude Code 先清旧工具输出、必要时再摘要，子 agent 只回传摘要；OpenAI 称 GPT-5.1-Codex-Max（2025-11-19）是首个
  "原生训练"跨多个上下文窗口做 compaction 的模型，Responses API 也有 compaction 端点。模型层的"原生训练"目前只有
  OpenAI 明说，Anthropic 一侧落在 API 与 harness 层。
- "在 ARCHITECTURE.md 里点名设计模式，激活预训练知识"一类 prompt 技巧（这条本来就没有实证，见
  [[Agentic SE 时代的系统重构]] §九）
- campaign 中"先在 2–3 个文件上调好 prompt 再全量"的调参仪式（⚠️ 分档有疑，见文末第 3 条）
- ACI 的省 token 部分（⚠️ 与下一档重复，见文末第 1 条）

### 部分贬值：每条切成折旧半 + 沉淀半

| 条目 | 折旧的一半 | 沉淀为资产的一半 |
|---|---|---|
| 上下文经济性整体 | 质量维度：长上下文退化在收窄 | 经济维度：窄读取的成本优势与模型能力无关（用户原文"永远便宜约 25×"偏强，见 [[上下文经济性]]） |
| 小步 PR / 爆炸半径 | 验证规模化后，安全变更的尺寸上限提高 | 不可逆操作的风险管理是治理问题 |
| seams / strangler fig | 接缝可以开得更大 | 新旧并行、可回退的迁移结构是风险工程 |
| 机器可消费文档 | 能从代码推断的内容会变冗余 | **代码里不存在的信息**：业务意图、历史约束、"为什么不"。不在场的知识无法被推断 |
| ACI / 为 agent 设计工具 | 省 token 的动机减弱 | 幂等性、可操作的错误信息——接口工程本体 |

"机器可消费文档"一行与本库已有的测量方向一致：ETH 评测里仓库概览类内容无益、成本 +20%，Anthropic 让
CLAUDE.md 只写删掉就会出错的内容（[[AI编码技术债的三层治理]]）。可推断的那一半现在就已经在贬值。

### 保值：存在理由是信任、协调与责任

- **显式契约、强类型、边界完整性**：契约是并行行为体之间的协调装置，行为体（人 + agent）越多越重要。
- **验证优先架构**：验证解决的不是"模型会不会写错"，而是"正确性无法由生成者自我证明"——这是信任结构问题；
  而且确定性检查比模型调用便宜几个数量级。
- **characterization tests 先行**：捕获只存在于运行系统里的真值，模型变强也拿不到不在场的信息。
  综合：会变的是生产成本——agent 越强，录制输入输出越便宜，所以这一条的性价比只升不降。
- **理解优先**（逆向提取业务规则再重写，Thoughtworks CodeConcise 路线）：被更强模型增强而不是淘汰。
- **prompt 纳入架构评审**：单个 prompt 触发的架构决策随模型能力变大，治理需求与能力成正比（⚠️ 按尺子应归
  升值，见文末第 2 条）。
- **任务可分解性**：并行、归因、回滚、审查的共同前提，是组织工程而不是模型工程。

### 升值：模型越强，问题越大

1. **认知债管理**：委派比例从"超过一半的人只能完全委派 0–20%"（Anthropic 内部调查）往上走的过程，就是团队
   理解流失加速的过程。用户称它是整个方法论里唯一与模型能力正相关恶化的风险（⚠️ "唯一"不成立，见文末第 2 条）。
   概念与治理见 [[AI编码技术债的三层治理]]。
2. **意图规格化（SDD 的内核）**：生成成本趋零后，瓶颈收敛为"把人想要什么说清楚"。Spec Kit / Kiro 的三步
   markdown 流程是仪式，会贬值；"意图是不可约减的人类输入"会随生成能力增强而更突出——这是 AaaS 论文
   "intent architect"判断里站得住的一半（原文给人的是三重角色：intent architect、agent coordinator、
   outcome auditor）。与 [[Specification-Driven Development]] 的关系：本库已有证据显示"写规格 ⇒ 返工下降"不成立
   （[[SDD 收益主张的实证赤字]]），这与"仪式贬值、内核升值"的切法相容——贬值的正是打包的流程主张。

## 对优先级顺序的重审

用户原文：调研稿的原顺序"验证网 → agent 接口层 → 边界重构 → campaign"按折旧速度重新着色——验证网与边界是
保值资产，接口层约一半折旧（只写代码里不存在的隐性知识），campaign 的调参仪式折旧最快；所以**顺序在更强模型的
世界里更成立：先投折旧最慢的**。

综合：套到 [[Agentic SE 时代的系统重构]] §七的六步修订版上（第 0、5 步是本库补的，用户未分档，下表这两行是维护者
的推断，置信度低）：

| 步骤 | 耐久度 | 理由 |
|---|---|---|
| 0. 度量与缩范围 | 保值 | 按 token 计价属经济维度；砍掉不必现代化的部分是责任判断 |
| 1. 验证网 | 保值 | 信任结构问题 |
| 2. agent 接口层 | 约一半折旧 | 可推断的约定会冗余；只写代码里不存在的隐性知识 |
| 3. 边界重构 | 边界与契约保值；按读取路径拆大文件部分贬值 | 拆文件同时服务质量维度（会收窄）与经济维度（不收窄） |
| 4. 批量 campaign | 调参仪式折旧最快；既有测试门禁与人审保值 | 见文末第 3 条：试点本身有保值的一半 |
| 5. 持续偿还 | 一半折旧、一半保值 | agent 不自发偿还有两个原因（[[Agent 不会自发偿还结构债]]）：选题需要跨文件语义判断（能力短板，会减弱）；agent 不承担未来成本、单次任务目标里没有重构（激励结构，不随能力消失） |

## 维护者注：尺子与分档对不上的地方（待用户裁定）

以下是按用户自己的尺子检查分档得出的，不是外部证据；分档暂按用户原文保留。

1. **ACI 的省 token 被放了两次。**第一档列了"ACI 的省 token 部分"，第二档又把它列为 ACI 的折旧半（"动机减弱"）。
   按尺子，省钱属于"部分贬值"，且用户自己在 §6 论证了经济维度不会被抹平——应只留在第二档。同理，第一档只该收
   **只为质量维度服务**的技巧；兼省读取体量的（如按读取路径拆分）归第二档。
2. **"认知债是唯一与能力正相关恶化的风险"与保值档的描述冲突。**用户写 prompt 架构评审"治理需求与能力成正比"——
   按尺子第四条这就是升值。验证也一样：生成吞吐越大，验证越稀缺，本库"实践层向'验证是瓶颈'收敛"的综合
   （[[Agentic SE 时代的系统重构]] §六）正是这个方向。建议改成：认知债、prompt 架构评审、验证容量都随委派规模
   升值；认知债的特殊之处是它**不可见**——不像验证瓶颈会表现为排队。
3. **campaign 试点不全是调参仪式。**"先 2–3 个文件再全量"有两个理由：调 prompt（补模型短板，会折旧），以及在
   系统性错误被乘以 N 之前先拦住（风险工程，保值）。Bun 在任何 agent 开跑前先花数小时写 Zig→Rust 惯用法对照指南，
   属于第四档的意图规格化，不是仪式。建议移到第二档。
4. **"先投折旧最慢的"作为投资规则不完整。**折旧快不等于不该投——只要回本期短于折旧期就值得。Thoughtworks 的
   单实验回本量级是几十次同类变更（[[Agentic SE 时代的系统重构]] §二，置信度低）；一个每周被改动十次以上的热点，
   一个季度内就能回本，一两年的折旧期不构成反对理由。原顺序本来就由**依赖关系**决定（没有验证网就不能安全委派后面的
   步骤），折旧着色是附加理由。建议改为：**依赖关系定先后，折旧速度定投入上限**——折旧快的件只做回本期短于折旧期
   的那部分。

## 什么证据会让本页改口

- 某类"补短板"的技巧在模型换代后**仍然**有可测收益（例如更强模型上，小文件对成功率的效应不降反升）→ 第一档的
  归类要退回第二档。
- 出现能可靠自证正确性的生成方式（例如生成即附可机检的形式化证明，且证明检查器独立于生成者）→ "验证 = 信任
  结构"的论证要改写；但这时验证只是换了执行者，没有消失。
- 长上下文退化在第三方测量里被抹平、且单位 token 价格降到可忽略 → [[上下文经济性]] 两个维度都要重估。
