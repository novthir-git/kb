# 2026-07-30 Thoughtworks《The Economic Benefit of Refactoring》源摘要

**原文**：Giles Edwards-Alexander（Thoughtworks），martinfowler.com "Exploring Gen AI" 系列，2026-07-30。
**存档**：`raw/sources/articles/2026-07-30-Thoughtworks-重构的经济收益.md`（要点式中文摘录；结果表测量值照录；
附录只保留重构步骤清单，未收录原始提示词）。

判断与跨源综合见 [[Agentic SE 时代的系统重构]]；"agent 不擅长选择与执行重构"作为证据行收在
[[Agent 不会自发偿还结构债]]。本页只做忠实摘录与口径标注。

## 一句话

**第一份把"为 agent 重构"的收益按 token 计价的实验**：对一个 agent 写成的 17,155 行文件做 15 步经典重构后，
让全新 sub-agent 重放同一个代表性变更，输入 token 从 159,564 降到 27,360（约 −83%）。

## 实验设计

- 对象：约 15 万行、全部由 agent 编写的应用（主要 Claude Code，部分 Cursor），作者基本不读、不审代码；
  数据访问层是单个 17,155 行的 Rust 文件，每个查询重复同样的 HTTP 请求与 JSON 编解码样板，但**边界清晰、
  接口需保持**。
- 假设：对 agent 代码库重构，就是**现在花 token，换以后每次变更更省 token**。
- 方法：利用"agent 不会学习"——每完成一步重构，就让全新 sub-agent 执行**完全相同**的代表性变更
  （在 Firestore 层新增一个三方法 trait，为假实现与真实实现各写一份），记录 token 与耗时后丢弃该变更。
- 重构手法全部取自 Fowler《重构》第 2 版（Extract Class / Extract Function / Move Function 等），
  以"可证明保持正确性的编辑序列"为严格定义且不改接口；每步都可单独测试，也都单独测过。

## 关键数据（摘自结果表）

| 步骤 | 最大文件行数 | 每次变更输入 token | 输出 token | 耗时（秒） |
|---|---|---|---|---|
| 基线 | 17,155 | 159,564 | 1,705 | 342 |
| 5 value ctors | 16,469 | 171,251 | 2,036 | 1,353 |
| 8 traits.rs | 13,845 | 132,558 | 1,723 | 446 |
| 12 store/ split | 9,269 | 104,080 | 2,050 | 490 |
| 15 store/ split（终） | 3,695 | 27,360 | 2,113 | 454 |

## 作者的发现

- 同一变更输入 token −132,204（约 83%）；按撰文时 Sonnet 5 每百万 token 3 美元计，单次约省 39.7 美分——
  作者紧接着说"Not a lot"，收益在于此后每个触及该层的变更都持续受益。
- **机制**：数据访问层总行数基本不变（最终拆成 19 个文件），节省来自 agent **能找到并只读所需的最小文件子集**；
  作者判断随机把文件切小不会有同等效果。前几步去重为最后的拆分铺路，符合重构的常规推进顺序。
- **输出 token 基本不变**：重构没有让变更本身变小。
- **过程观察**：Claude 不擅长**选择**重构，需要人主动引导，开发 harness 里原有的显式重构步骤从未促使它处理这个
  文件；做计划时 Claude.ai 看出应抽出整个 client 类，Claude Code 只提出 Extract Function。它也不擅长**执行**：
  用 Python 调 grep/sed 做机械改写，常被缩进搞乱；价值最大的一步首轮被跳过。全程约 8 小时，基本无人值守，
  只在 6 小时 40 分时人工重新引导过一次。

## 口径与证据边界

1. **单实验、单个 greenfield 应用、单名开发者**，作者自称只是"第一步"。
2. **Token 是估算值**：用 sub-agent 报告的字符数 ÷ 4 近似，作者称当时 Claude 没有可靠的实时计数。
3. **每步只测一次，无重复、无方差。** 第 5/6、8/9、12/13 步的测量值原文即完全相同（照录未改），
   原文未说明是否为复用测量。
4. **重构本身的 token 成本没有精确计量**，只给上界 500 万 token，且其中含两次制定计划与实验设计。
5. **美元估算只按输入价、未计 prompt 缓存**（原文另指出输出 token 单价是输入的五倍）：同一会话内重复读同一前缀时，缓存读价远低于全价，单次节省的美元数会相应缩小。
6. 综合（本 wiki 从表中读出，原文未强调）：
   - **耗时没有同步下降**：342 秒 → 454 秒，中途峰值 1,353 秒。单次测量噪声大，不能说重构让变更更慢，
     但也不支持"更快"。
   - **输出 token 在 1,705–2,460 之间波动**，终值比基线高约 24%；"基本不变"是作者就绝对量而言。
   - **回本量级**：若把 500 万 token 上界全部按输入价计，约 38 次同类变更回本；输出 token 更贵、上界又含
     非重构工作，真实回本点更可能在"几十次"这一量级而非精确值。
