# Simon Willison 对 Claude Code 团队的访谈 — 源摘要

## 来源定位

Simon Willison 于 2026-07-21 发布他在 AI Engineer World’s Fair 主持的访谈编辑稿，受访者为 Anthropic
Claude Code 团队的 Cat Wu 与 Thariq Shihipar。材料覆盖 Claude Code、Claude Tag、代码审查、evals、
提示与工具设计、安全、团队记忆和人的工作体验，是**团队内部一手实践陈述**；同时因指标与安全效果主要由
公司自报，应把它视为机制证据和研究线索，而不是独立效果评估。

## 核心判断

访谈的主线不是“AI 写了多少代码”，而是实现成本骤降后，瓶颈如何迁移：产品取舍转向真实留存，审查转向
按风险逐层放权，模型升级依赖产品级 eval，团队协作依赖共享上下文、长期主动任务和独立身份。综合：
AI 原生工程的竞争力越来越取决于**谁能把用户反馈、事故、权限和团队记忆编译进持续运行的控制循环**。

## 按原文结构的中文整理

### 1. 人的角色：从实现转向判断

- Cat 称模型进步让团队能委托更多琐碎实现，把注意力移向用户体验、产品方向与商业判断。
- 从想法到实现的周期缩短后，工程师更需要判断“什么值得做”；基础设施等领域仍高度依赖细节正确性。
- Thariq 主张在测试套件可靠时重新评估重写禁忌，把旧代码库当作可被蒸馏的规格。该主张是经验判断，
  不构成对遗留系统重写风险的普遍反证。

### 2. Claude Tag：多人、主动、带团队记忆

- Claude Tag 在 Slack 中支持多人共同引导同一任务，可长期监听 bug、主动发 PR，并记住频道级团队偏好。
- Cat 给出的窄口径是：Claude Code **产品工程团队**内部版本的 Claude Tag 当前提交 **65% 的产品 PR**；
  不是全 Anthropic 数据，也不是 PR 无人审查的比例。
- 团队还用它检索公开 Slack、连接事件数据、帮助市场人员理解代码功能。公开频道中的共同使用兼具社会学习作用。

### 3. 功能优先级：内部留存成为发布门槛

新功能先交给 Anthropic 员工和少量早期客户使用，只有达到内部设定的活跃用户和留存门槛才公开发布。
实现成本降低没有消除优先级问题，反而把决策重心从“能否实现”推向“用户是否持续使用”。

### 4. Code review：核心保留人工，外围按证据自动化

- 系统提示等关键区域仍由 code owner 人工批准；所有 PR 同时接受 review bot、CI/CD 和测试环境检查。
- 团队用了六个多月，从全部人工审查逐步扩展到部分外围文件由机器完整 review。
- 事故致因 PR 会转成 eval 用例并更新 reviewer。综合：自动放权的单位不是“整个团队”，而是文件范围、
  风险等级和已积累的回归证据。

### 5. Evals：能力、行为和失败案例进入同一套件

新模型作为旧模型替代品前需运行产品级 eval。团队既测修复 bug、通过测试等能力，也测过早停下等体验行为；
用户反馈和生产事故会继续生成测试。Cat 明确说现有覆盖并不完整，提示词变更也没有绝对置信度；她认为
构建高质量 eval 的主要约束通常是方法和技能，而非评测工具本身。

### 6. Prompt 与工具：少而准，但必须按模型验证

- 最前沿模型的 Claude Code 系统提示缩短约 80%，减少示例和绝对禁令，增加背景并留给模型更多判断空间；
  旧模型仍保留完整提示，因此不能把这条经验外推为通用 prompting 法则。
- 工具数量趋于减少，grep / glob 等独立工具被原生 Bash 取代；工具之间需要有清晰可区分的职责。
- 文件编辑工具得以保留，一项重要原因是产品可以确定性渲染 diff 和批准界面：工具设计同时服务模型、用户与审计。

### 7. 安全：动态权限、沙箱、独立身份与凭证注入

受访者称 auto mode 结合调用上下文判断动态权限，并与沙箱和网络控制协作。公司自报已做数千项 eval 和外部
红队测试；但 Cat 随后明确收窄为“不可能覆盖 100%”，且相关结果在发布时尚未公开。Claude Tag 可使用
独立身份；credential injection 让代理替 agent 注入 API 密钥并审计请求，使 agent 能使用凭证但不能读取凭证。

### 8. 人的体验与记忆实现

- Thariq 承认旧工作被压缩为提示会带来真实失落，并把“选择更有野心的任务”当作个人应对；这是组织内部叙事，
  不是体验问题已被解决的经验证据。
- Claude Tag 当前按频道保存共享记忆，每个会话可向主记忆贡献内容，底层是每频道一个 Markdown 文件。
  访谈没有披露写入准入、冲突调和、权限、撤销与遗忘机制。

## 关键口径与证据边界

| 口径 | 可以支持 | 不能支持 |
|---|---|---|
| Claude Tag 提交 65% 产品 PR | 团队 agent 已深度进入 Claude Code 产品工程流程 | 全 Anthropic 65% PR 由 agent 完成；这些 PR 无人工判断或门禁 |
| 外围代码逐步自动 review | 经长期评估后，可按低风险范围缩减人工逐项审查 | 核心变更已无人审查；自动 reviewer 从不漏检 |
| 前沿模型提示缩短 80% | 特定模型可从更少约束、更多背景中受益 | 示例与明确约束对所有模型都无效 |
| 数千项安全 eval 与外部红队 | Anthropic 建设了持续安全测试流程 | auto mode 已证明 100% 安全，或优于人工的口径已被独立验证 |
| 每频道一个 Markdown 记忆文件 | 文件化共享记忆可支撑当前团队场景 | 已具备完整的长期记忆治理、权限与遗忘机制 |

## 可复用论点

1. **发布门槛应从实现完成转向真实使用证据**：内部活跃度与留存可成为低成本功能泛滥的过滤器。
2. **审查自动化应按风险和证据逐层放权**：核心区保留 owner，外围区用历史事故、eval 和回归数据扩张边界。
3. **失败应被编译进系统**：用户抱怨、生产事故和审查漏检都要转为可重复的行为或能力 eval。
4. **Agent 工具也是治理接口**：工具的选择不仅影响模型成功率，也决定人能否批准、观察和审计行动。
5. **共享记忆先解决写入治理，再追求存储扩展**：Markdown 是否能扩展不是唯一问题，准入、冲突和遗忘同样关键。
