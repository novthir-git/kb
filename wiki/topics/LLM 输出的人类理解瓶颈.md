# LLM 输出的人类理解瓶颈

**核心论点**：agent 接手的"跑腿"活越多，人这一侧的瓶颈就越从"产出"转向**理解与监督的带宽**——
产出读不过来、核不过来。Karpathy 给的应对方向是：既然智能与代码变得充裕，就把廉价算力花在
**为人定制、用完即弃的呈现**上（受控英语 → 图示 → HTML 交互页 → 讲解视频）。

综合：方向站得住，但"更易读"≠"更对"。现有证据划出两条边界：

1. **保真度**：简化会丢事实，丢多少取决于内容里领域术语的密度（样本极小，低置信）。
2. **可验证性**：呈现越丰富，人和 LLM 都越难核对它（作者本人承认；帖子自带的速查图即含错误）。

本页是 [[生产力-体验悖论]] 中"从创造到验证"在**个人认知层**的延伸：那一页讲工作从写转向审，
本页讲审的带宽怎么扩容、扩容的代价是什么。组织 / 流程层的对应见 [[Anthropic-AI原生SDLC治理循环]]。

## 输出格式阶梯（两个版本）

| 级 | 2026-05-11 版（[原帖](https://x.com/karpathy/status/2053872850101285137)） | 2026-10-02 版（[[2026-10-02-Karpathy-理解LLM输出的格式阶梯\|存档]]） |
|---|---|---|
| 1 | raw text（读起来费力） | 受控英语：ASD-STE100，或"80% 程度的 ASD-STE100" |
| 2 | markdown（当前默认） | 图示 / 图片 |
| 3 | HTML（"正在形成的新默认"） | HTML 交互网页 |
| n | 交互式神经视频 / 模拟（扩散模型直接生成，"技术尚不存在"） | 定制讲解视频（如 3b1b 风格 + TTS 配音），"真的开始能用了" |

- 5-11 版的理由：音频是人给 AI 的首选**输入**，视觉是 AI 给人的首选**输出**（"约三分之一的大脑是视觉处理器"——
  原帖说法，未引研究）。
- 10-02 版的总结：LLM 越强，跑腿越自主，"我们的工作会沿抽象层上移到监督与理解"；智能与代码充裕后，
  可以索取"大型、定制、可丢弃的软件制品"。
- 两版之间的变化：底层从 raw text / markdown 换成受控英语——纯文本这一级内部也有优化空间；顶层从
  "技术尚不存在"变成"开始能用了"。

## 当前判断

1. **人侧瓶颈转向理解带宽**——中置信。与 [[生产力-体验悖论]] 记录的"从创造到验证""从创造到清扫"同向；
   但 Karpathy 两帖是个人经验与观点，没有测量。
2. **"要 HTML / 要图"是低成本、可立即采用的默认动作**——中置信。本仓库 `output/` 层即此实践；
   不确定的是它对**理解质量**（而非主观舒适度）的增益有多大，目前无测量。
3. **受控英语有保真代价，代价随领域术语密度上升**——低置信（样本极小）。代码讲解上，正式 ASD-STE100
   让 Claude 少提 46.8% 的计分事实，宽松的"Simple Technical English"只少 8.5%；术语少的散文上，各条件
   8/8 全保留（见证据点表）。综合：代码、产品名、行话密集的内容不要用正式 STE，宽松版或"80%"更稳。
4. **格式越丰富越难验证**——中置信。Karpathy 自己在 08-02 帖承认 LLM 无法高效原生感知视频、试玩游戏，
   难以自查视觉产出；10-02 帖自带的速查图被核查出词典条目错误。综合：从文字升到图、页、视频，
   **可读性上升，可核对性下降**——呈现越漂亮，越需要一个能回溯核对的文字 / 数据源。
5. **"可丢弃"的前提是有不可丢弃的源**——综合，中置信。定制呈现之所以可以随用随弃，是因为它是派生视图；
   若知识只住在呈现里，它就成了无人维护的第二事实源（[[代码与文档漂移的本质]] 原则一）。
   本仓库 `AGENTS.md` 对 `output/` 的约定（交付层不是知识层、原创稿必须回灌 wiki）与此一致。

## 悬而未决

- 讲解视频、交互页这类富格式的**保真度怎么测**？目前只有文字级的"计分事实"方法（Ghinda、StashBase），
  图示与视频没有对应方法。
- "理解带宽"能否量化（审阅时间、漏检率、复述准确率）？没有测量，就分不清格式阶梯提升的是理解，
  还是只提升了主观舒适度——与 [[生产力-体验悖论]] 里"感知 ≠ 实际"是同一个陷阱。
