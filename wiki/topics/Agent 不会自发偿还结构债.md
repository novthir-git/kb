# Agent 不会自发偿还结构债

## 论点

Coding agent **放大**代码库里已有的结构，包括坏结构：它会照着仓库里现成的模式写新代码，却几乎不会自发发起
**有针对性、有收益的**结构债偿还，即使重复已经出现第三、四次，即使 harness 里写着"记得重构"。（综合：它并非从不自发改结构——
修 issue 时也会做没人要求的顺手重构，但那类改动损害可编译性，算不上偿还，见第 1 层限定。）因此在 agent 的吞吐下，**结构债**会以同样
的速度累积，除非有**外部机制**来驱动偿还：人来选择重构，sensor 暴露问题，定期任务发重构 PR。

本页的"结构债"指技术债中可以从代码结构读出来的那部分：重复、超大文件、缺失的抽象、被绕开的既有抽象、
模块边界侵蚀。认知债与意图债见 [[AI编码技术债的三层治理]]。

论点分三层，证据强度不同：

1. **不会自发*发起*有针对性的偿还**：三个来源同向。Thoughtworks 与 [[Birgitta Böckeler|Böckeler]] 是直接观察；OpenAI 只说 agent 会复制坏模式、
   清理靠外部机制，属间接证据。独立性有限：前两者都是 Thoughtworks 作者、都发在 martinfowler.com（只有重构经济学
   一文属于 "Exploring Gen AI" 系列）；第三个来自另一家机构。2026-11-05 增第四个、也是第一个学术来源：SlopCodeBench
   的 15 个 agent 在自己的代码上迭代，77% 的轨迹结构侵蚀上升；即使提示里写明质量要求，平均退化速度也不变。
   限定（2026-11-07）：Tangled refactoring（arXiv 2605.22526）显示 agent 修 issue 时**确实会**做没人要求的顺手重构
   （21.43% 的补丁），只是频率与强度都低于人类（36.72%；每补丁 0.66 vs 1.75 次），且这类重构降低可编译性。
   综合：所以第 1 层的准确说法是"不会自发发起有针对性、有收益的结构债偿还"，不是"从不自发改结构"。
2. **被明确分派后*选题*的质量**：证据分化。Thoughtworks 的 Claude 挑不出合适的重构，需要人主动引导；但 Böckeler
   用推理型模块化评审 skill 得到了大量有价值的重构线索，OpenAI 的后台任务也会自己扫描偏差、发定向重构 PR。
3. **被驱动后*执行*的质量**：综合，证据分化。OpenAI 自述其定向清理 PR 多数一分钟内审完并自动合并（这是评审耗时
   口径，不是质量度量）；Thoughtworks 的多步大重构执行粗糙，价值最大的一步首轮被漏掉、靠人工重新引导才补做。
   2026-11-05 补一个反方向的失败：**被驱动后不会自己停**。对已干净的代码持续要求重构，5 个模型无一停下，最多重写到 31 倍
   （Over-Compliant）。另一种失控发生在**未被要求时**：修 issue 时的顺手重构降低可编译性，论文 Figure 1 引用的真实 PR 里，
   删 3 行死代码的任务改了 16,881 行（tangled refactoring，见第 1 层限定）。综合：不发起有针对性的偿还、被要求后停不下、
   未被要求时改出范围，指向同一个缺口——agent 自己没有"这次改动值不值"的判断，所以发起与停止都得靠外部判断给出。

> 综合：所以这个论点的推论不是"agent 不能重构"，而是**重构的发起必须是 harness 的显式职能**，选题最好交给
> 专门的推理型评审或人。它要有触发条件、选题机制、**停止条件与范围约束**和验证网，不能指望 agent 的"好习惯"。怎么搭见 [[Harness Engineering]]，这样做在经济上
> 值不值见 [[Agentic SE 时代的系统重构]]。

**什么证据会让本页改口**：出现 agent 在**无显式重构指令**时，自行识别并完成有度量收益的结构性重构
（例如降低后续变更的 token 或改动文件数），且在多仓库上可复现。

## 为什么会这样（机制）

综合：三份源各自给了一部分解释，拼起来是一条完整链。

- **模仿是默认策略**。Agent 从上下文里的现有代码学"这个仓库怎么写"。坏模式一旦进入仓库就会被当成范例复制
  （OpenAI），重复越多、被复制的概率越高，形成正反馈。
- **agent 不承担未来的成本**。人重构，是因为预期自己还要再改这段代码；每次会话从零开始的 agent 没有这个预期。
  Thoughtworks 的实验设计正是利用了这一点："agent 不会学习"，所以同一变更可以反复重放测成本。
  Böckeler 列出的人的**隐性 harness**里有一项"对复杂度的痛感"，agent 没有（[[Harness Engineering]]）。
- **局部任务目标压倒全局结构**。一次会话的成功标准是"这个需求做完"，重构是跨任务的投资，不在单次任务的
  目标函数里。当阈值可以绕开、信号又不带修正指引时，agent 会选择绕开（Böckeler 的圈复杂度观察）。
- **选题需要跨文件的语义判断**。该抽哪个类、该贯彻哪个参数对象，要把多个文件放在一起理解。这恰是计算型
  sensor 的盲区；推理型评审能补，但非确定，需要多跑（Böckeler）。

## 对实践的含义

- **把偿还做成定期任务**，不要指望它伴随功能开发发生：OpenAI 的后台 GC 任务，Böckeler 的周期性模块化评审。
- **重构选题由人把关，或由推理型评审多轮产出候选**：综合：Thoughtworks 的计划阶段，同一家族的两个界面
  （Claude.ai 与 Claude Code）给出了不同层次的方案（作者称是轶事）；只看 Claude Code 的第一个提议，会停在
  Extract Function 这一层。
- **sensor 信号要带修正指引，阈值上调要可见**：可以允许上调，但不要永久豁免，这样恶化时规则仍会触发
  （Böckeler 的做法）。
- **给重构任务写停止条件与范围**：只许改哪些文件、改到什么程度算完成、超出范围即废弃。Over-Compliant Refactoring 与
  tangled refactoring 显示，没有这些约束时 agent 会一直改下去或改出范围；Uber AutoClean 的窄权限加并行审查是一种落地形态。
- **规则写进提示不够**：SlopCodeBench 的质量提示只压初值、不改斜率，而且更贵。综合：发起与约束都要落到机制（sensor、定时任务、权限），
  不是落到 CLAUDE.md 里的一句"保持整洁"。
- **先铺验证网再放 agent 执行**：Thoughtworks 的每一步都可单独测试、也都单独测过。综合：这很可能是它能 8 小时
  基本无人值守的条件之一（原文没有把两者直接联系起来）。
- 它回答了 [[AI编码技术债的三层治理]] 的一个隐含问题：技术债那一层"测试、重构、静态分析"的偿还方式，
  在 agent 吞吐下**不会自然发生**，必须被编排。

## 待追踪 / 悬而未决

- 是否存在"agent 自发偿还结构债"的反例？更强的模型、带长期记忆的 agent，是否会改变第 1 层？
  截至 2026-11-07 仍无"自发偿还"的反例。SlopCodeBench 的代际证据混合（综合，本 wiki 从 Table 1 读出）：Opus 4.5→4.6→4.7 侵蚀未降
  （0.70→0.75→0.76），GPT 5.2 Codex→5.3 Codex→5.4→5.5 侵蚀水平下降约三分之一（0.73→0.64→0.51→0.49）；但水平值既不等于退化斜率，也不等于自发偿还。
- 执行质量的分化（OpenAI 的小 PR 顺利、Thoughtworks 的大重构粗糙）是否可以用**重构粒度**解释？
  需要同一仓库内的对照。
- 定期 GC 任务本身的成本与误报率：OpenAI 未公布。已有部分数据：Anthropic routines 合并率约 46%（未合并原因未披露；合并率不等于误报率），
  gh-aw 单次约 19,398 token、近 5 次运行成功 2 次（[[Harness Engineering]]）。误删率与误报率仍无任何一家公布，与 [[全AI代码库的治理决策]]「待追踪」同一缺口。
- 累积的到底是不是本页定义的"结构债"？CodeThread（arXiv 2606.21804，2026-06-19，检索于 2026-10-08）显示前沿 agent 在
  agent 写的代码上继续开发，解决率比在人写的代码上最多低 13.1%，但传统可维护性指标解释不了这个差距，更明显的信号是
  输入校验、错误处理等行为层缺口。若属实，只盯文件长度、重复率的计算型 sensor 会漏掉最伤后续 agent 的那部分债
  （[[上下文经济性]]）。
- 结构债累积速度能否度量？候选指标：同一代表性变更的输入 token（Thoughtworks 的做法）、
  小改动涉及的文件数（Böckeler 眼中可维护性开裂的第一信号）。
