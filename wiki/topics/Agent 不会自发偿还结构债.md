# Agent 不会自发偿还结构债

## 论点

Coding agent **放大**代码库里已有的结构，包括坏结构：它会照着仓库里现成的模式写新代码，却几乎不会自己发起
重构，即使重复已经出现第三、四次，即使 harness 里写着"记得重构"。因此在 agent 的吞吐下，**结构债**会以同样
的速度累积，除非有**外部机制**来驱动偿还：人来选择重构，sensor 暴露问题，定期任务发重构 PR。

本页的"结构债"指技术债中可以从代码结构读出来的那部分：重复、超大文件、缺失的抽象、被绕开的既有抽象、
模块边界侵蚀。认知债与意图债见 [[AI编码技术债的三层治理]]。

论点分三层，证据强度不同：

1. **不会自发*发起*重构**：三个来源同向。Thoughtworks 与 Böckeler 是直接观察；OpenAI 只说 agent 会复制坏模式、
   清理靠外部机制，属间接证据。独立性有限：前两者都是 Thoughtworks 作者、都发在 martinfowler.com（只有重构经济学
   一文属于 "Exploring Gen AI" 系列）；第三个来自另一家机构。
2. **被明确分派后*选题*的质量**：证据分化。Thoughtworks 的 Claude 挑不出合适的重构，需要人主动引导；但 Böckeler
   用推理型模块化评审 skill 得到了大量有价值的重构线索，OpenAI 的后台任务也会自己扫描偏差、发定向重构 PR。
3. **被驱动后*执行*的质量**：综合，证据分化。OpenAI 自述其定向清理 PR 多数一分钟内审完并自动合并（这是评审耗时
   口径，不是质量度量）；Thoughtworks 的多步大重构执行粗糙，价值最大的一步首轮被漏掉、靠人工重新引导才补做。

> 综合：所以这个论点的推论不是"agent 不能重构"，而是**重构的发起必须是 harness 的显式职能**，选题最好交给
> 专门的推理型评审或人。它要有触发条件、
> 选题机制和验证网，不能指望 agent 的"好习惯"。怎么搭见 [[Harness Engineering]]，这样做在经济上
> 值不值见 [[Agentic SE 时代的系统重构]]。

**什么证据会让本页改口**：出现 agent 在**无显式重构指令**时，自行识别并完成有度量收益的结构性重构
（例如降低后续变更的 token 或改动文件数），且在多仓库上可复现。

|---|---|---|---|
| 2026-07-30 | Thoughtworks（Giles Edwards-Alexander），martinfowler.com | 约 15 万行、全部由 agent 编写的应用里，数据访问层长成**单个 17,155 行**的 Rust 文件，每个查询重复同样的样板。开发 harness 里原有的显式重构步骤**从未促使 Claude 处理这个文件**。作者的结论是 Claude "不擅长选择"重构，需要人主动引导（重构完全是对提示的响应）；另据作者的轶事观察，做计划时 Claude.ai 看出应抽出整个 client 类，Claude Code 只提出 Extract Function。它也"不擅长执行"：用 Python 调 grep/sed 做机械改写，常被缩进搞乱；价值最大的一步（拆分 store）首轮被跳过，事后补做 | 支持第 1、3 层，第 2 层为负面信号。单实验、单开发者、greenfield；全程约 8 小时基本无人值守，只在 6 小时 40 分时人工重新引导一次，说明执行**能完成**，只是不可靠。→ [[2026-07-30-Thoughtworks-重构的经济收益-源摘要]] |
| 2026-05-27 | Birgitta Böckeler，martinfowler.com（05-19 起连载，05-27 完结） | 为实验用 AI 从零重建的 Next.js 看板中，在没有人工评审、也没有 AI 评审时，agent 确实在累积**无意的技术债**：三个近乎相同的 route 文件；第三个页面没复用已有 hook，另起一套；参数对象早已引入却从未贯彻，一次日期范围改动因此波及 **40 多个文件**。作者经验：**agent 在第三、四次重复时通常不会主动重构**。允许 agent 在"认为重构不必要"时上调阈值后，圈复杂度成了 agent 唯一频繁上调阈值的规则类别，作者事后发现这条规则恰好没配修正指引 | 支持第 1 层；推理型模块化评审找到了这些问题，是第 2 层的正面信号。阈值一条只说明：**在没配修正指引的规则上**，agent 的默认路径是上调阈值绕过（配了指引的规则未见此现象，追问后它也能给出好的重构）。实验刻意不给 guides，只支持"无指引时"的情形；单人单应用、无对照。→ [[2026-05-27-Boeckeler-可维护性传感器-源摘要]] |
| 2026-02-11 | OpenAI（Ryan Lopopolo），openai.com | 五个月零手写代码、约 100 万行的内部产品中，agent **会复制仓库里已有的坏模式**。团队起初每周五人工清理"AI 残渣"，占一周的 20%，不可扩展；后改为把"黄金原则"编码为机械规则，并定期运行后台任务扫描偏差、更新质量等级、发定向重构 PR | 第 1 层的间接证据（偿还靠外部驱动），也是**解法的证据**（驱动可以机械化，后台任务能自己发定向重构 PR）。作者类比：技术债是高息贷款，宜持续小额偿还。公司自述，无外部审计、无对照组。→ [[2026-02-11-OpenAI-Harness-Engineering-源摘要]] |

## 为什么会这样（机制）

综合：三份源各自给了一部分解释，拼起来是一条完整链。

- **模仿是默认策略**。Agent 从上下文里的现有代码学"这个仓库怎么写"。坏模式一旦进入仓库就会被当成范例复制
  （OpenAI），重复越多、被复制的概率越高，形成正反馈。
- **agent 不承担未来的成本**。人重构，是因为预期自己还要再改这段代码；每次会话从零开始的 agent 没有这个预期。
  Thoughtworks 的实验设计正是利用了这一点："agent 不会学习"，所以同一变更可以反复重放测成本。
  Böckeler 列出的人的**隐性 harness**里有一项"对复杂度的痛感"，agent 没有（[[Harness Engineering]]）。
- **局部任务目标压倒全局结构**。一次会话的成功标准是"这个需求做完"，重构是跨任务的投资，不在单次任务的
  目标函数里。当阈值可以绕开、信号又不带修正指引时，agent 会选择绕开（Böckeler 的圈复杂度观察）。
- **选题需要跨文件的语义判断**。该抽哪个类、该贯彻哪个参数对象，要把多个文件放在一起理解。这恰是计算型
  sensor 的盲区；推理型评审能补，但非确定，需要多跑（Böckeler）。

## 对实践的含义

- **把偿还做成定期任务**，不要指望它伴随功能开发发生：OpenAI 的后台 GC 任务，Böckeler 的周期性模块化评审。
- **重构选题由人把关，或由推理型评审多轮产出候选**：综合：Thoughtworks 的计划阶段，同一家族的两个界面
  （Claude.ai 与 Claude Code）给出了不同层次的方案（作者称是轶事）；只看 Claude Code 的第一个提议，会停在
  Extract Function 这一层。
- **sensor 信号要带修正指引，阈值上调要可见**：可以允许上调，但不要永久豁免，这样恶化时规则仍会触发
  （Böckeler 的做法）。
- **先铺验证网再放 agent 执行**：Thoughtworks 的每一步都可单独测试、也都单独测过。综合：这很可能是它能 8 小时
  基本无人值守的条件之一（原文没有把两者直接联系起来）。
- 它回答了 [[AI编码技术债的三层治理]] 的一个隐含问题：技术债那一层"测试、重构、静态分析"的偿还方式，
  在 agent 吞吐下**不会自然发生**，必须被编排。

## 待追踪 / 悬而未决

- 是否存在"agent 自发重构"的反例？更强的模型、带长期记忆的 agent，是否会改变第 1 层？
- 执行质量的分化（OpenAI 的小 PR 顺利、Thoughtworks 的大重构粗糙）是否可以用**重构粒度**解释？
  需要同一仓库内的对照。
- 定期 GC 任务本身的成本与误报率：OpenAI 未公布。
- 结构债累积速度能否度量？候选指标：同一代表性变更的输入 token（Thoughtworks 的做法）、
  小改动涉及的文件数（Böckeler 眼中可维护性开裂的第一信号）。
