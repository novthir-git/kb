# 变异测试（Mutation Testing）

**一句话**：故意向代码注入小的逻辑改动（变异体），看测试套件会不会因此失败。失败即"杀死"变异体，照样通过即"存活"，
存活说明那处行为没有被任何断言约束。和只记录"哪些行被执行过"的覆盖率不同，它检验的是测试能不能抓住被改坏的行为
（Thoughtworks Technology Radar：https://www.thoughtworks.com/radar/techniques/mutation-testing ，检索于 2026-11-07）。

在本库里它承担两个角色：**覆盖率虚高的对策**，以及**检验测试这一 sensor 本身**的手段。

## 1. 覆盖率虚高的对策

- **一手观察**：[[Birgitta Böckeler|Böckeler]] 的可维护性 sensor 实验中，测试全由 AI 编写、几乎未审。`mappers.ts` 语句覆盖
  100%、分支覆盖 75%，却没有单元测试，Stryker 报出 13 个存活变异体：覆盖来自一个断言稀疏的大验收测试。她的结论是
  把大部分测试交给 AI 时变异测试至关重要（[[2026-05-27-Boeckeler-可维护性传感器-源摘要]]）。
- **行业判断**：Technology Radar 2026-04 版把它放在 Trial，2026-11 版（Vol.35）升为 Adopt。理由是 AI 生成的代码与测试
  量激增，覆盖率"easier to inflate with superficial tests"，变异测试用来确认生成的测试不会"simply pass without catching
  logic changes"（同上 URL；本库首次引用见 [[全AI代码库的治理决策]]）。
- **门禁层的推论**：Sonar way 的"新代码覆盖率至少 80%"可以被满足而不提供保护，所以覆盖率门禁要配变异测试
  （[[AI编码技术债的三层治理]]）。[[全AI代码库的治理决策]] 把覆盖率列为"不能当收益的数"，并在决策树里把
  "测试全由 AI 写且未经变异测试检验"与"没有自动验证"归为同一档。

## 2. 检验 sensor 的 sensor

- 在 [[Harness Engineering]] 的四格里，变异测试是 **computational sensor**（Böckeler 原表）；她在框架文的实践信号里也记了
  "变异测试与结构测试复兴"（[[2026-04-02-Boeckeler-Harness-Engineering-源摘要]]）。Behaviour harness 被她称为
  "房间里的大象"，因为当前普遍过度信任 AI 生成的测试。
- 综合：它的特殊之处在于验证对象是另一个 sensor（测试套件）。Böckeler 的开放问题之一是"sensor 从不触发，是质量高还是
  检测不足"；对测试这一类 sensor，变异测试直接给出答案：注入已知缺陷，看它触不触发。[[Evals]] 检查表里"先用 reference
  solution 证明 grader 与环境没坏"是同一思路在模型 grader 上的版本。本库尚未收录对推理型 sensor 做"注入已知缺陷"检验
  的来源。

## 3. 约束结果，不规定过程

Böckeler 2026-08-10 的小样本评估：5 批，每批 2 个 TDD 方案与 2 个非 TDD 方案，Sonnet 4.6 生成，Opus 4.8 盲评。
TDD 与否没有可辨别差异，"no meaningful difference in mutation scores"。她因此停止要求 coding agent 先写测试，改为
"monitor and improve regression quality with the help of mutation testing"，并试用 Approved Scenarios
（https://martinfowler.com/articles/exploring-gen-ai/tdd-in-the-agent-loop.html ，检索于 2026-11-07）。
综合（[[Specification-Driven Development]]）：对 agent 而言，验证应约束**结果**（测试能否杀死变异体），而不是规定**过程**。

## 怎么用

- **成本**：变异测试资源消耗大，Böckeler 手动触发增量运行；[[AI编码技术债的三层治理]] 建议按变更增量运行。
- **放在哪一步**：[[全AI代码库的治理决策]] 六步路线的第 1 步"验证网先行"要求 AI 写的测试按增量跑变异测试，回归指标里
  记"AI 写的测试的变异得分"；[[Agentic SE 时代的系统重构]] 把它列为"让 sensor 的'绿'可信"的条件，以及 §七重构
  优先级顺序第 1 步"验证网"的组成部分。
- **工具**（类别参考，效果未经本库验证，见 [[全AI代码库的治理决策]]）：Stryker（TS/JS）、mutmut（Python）、
  cargo-mutants（Rust）、PIT（Java）；Go 未列。

## 证据边界

- 本库唯一的一手实测是 Böckeler 单人单应用里的一个文件；TDD 评估也只有 5 批。Radar 是 Thoughtworks 的技术判断，
  不是效果数据。本库没有"引入变异测试后逃逸缺陷减少"的测量。
- 综合：按 [[Harness Engineering]] 记录的古德哈特现象（阈值会被 agent 当作可优化目标），变异得分若设为 agent 的硬阈值，
  同样可能被绕过；本库无此实测。
