# Agent 记忆架构

## CoALA 的准确结构

CoALA（Cognitive Architectures for Language Agents）不是单纯的“四类记忆模型”，而是用三个维度
描述语言 Agent：

1. **信息存储**：工作记忆 + 三类长期记忆；
2. **行动空间**：对内部记忆的检索、推理和学习，以及对外部环境的 grounding 行动；
3. **决策过程**：反复执行“规划 → 选择 → 执行 → 观察”的循环。

因此，记忆提供 Agent 可以利用的状态，但不会单独产生目标、行动或闭环。

## 四类记忆

| 类型 | CoALA 含义 | 工程载体示例 | 常见误区 |
|---|---|---|---|
| Working memory | 当前决策周期可直接使用的观察、目标、中间结果和活跃知识 | 上下文窗口、任务状态、工具结果 | 上下文变长就等于长期记忆 |
| Episodic memory | 过去决策周期或任务的经历序列 | 任务轨迹、成功/失败案例、事件流 | 把全部聊天日志无差别保存 |
| Semantic memory | 关于世界与 Agent 自身的事实和知识 | Wiki、OKF Bundle、文档、知识图谱、领域数据库 | 把派生制品或索引当权威事实源 |
| Procedural memory | 决定如何行动的隐式和显式知识 | 模型权重、Agent 代码、工作流、提示、Skills | 把 Skills 当成全部程序记忆 |

CoALA 还指出，修改程序记忆比写入情景或语义记忆风险更高：它可能引入代码缺陷，
甚至改变设计者原本的意图。因此 Agent 自行修改指令、代码或决策程序不应默认自动生效。

## Skills 在程序记忆中的位置

> 本节的规范细节与三语境收拢已建独立页 [[Agent Skills]]（2026-08-11）。

Agent Skills 规范要求每个 Skill 至少包含 `SKILL.md`，并可附带 `scripts/`、`references/`、
`assets/`。它采用 progressive disclosure：

1. 启动时只加载名称和描述；
2. Skill 命中后加载完整 `SKILL.md`；
3. 脚本、参考和资产仅在需要时读取。

综合：Skills 是**可读、可版本化、按需加载的显式程序记忆**，特别适合沉淀“什么时候做、按什么步骤做、
调用什么工具、如何验证”。但模型权重中的隐式能力、宿主代码和外部 Workflow 同样属于程序性知识。

## 存储不等于记忆

一个存储系统只有进入下列闭环，才成为可用的 Agent 记忆：

```text
观察或经验
→ 判断是否值得写入
→ 结构化并附来源/时间/权限
→ 按当前目标召回
→ 用于推理或行动
→ 根据结果修订、降权或遗忘
```

| 策略 | 必须回答的问题 |
|---|---|
| Write | 什么值得保存？谁能写？是原始经历还是已验证知识？ |
| Retrieve | 按相关性、时间、重要性还是规则召回？怎样避免越权？ |
| Update | 新证据与旧记忆冲突时，覆盖、并存还是标记失效？ |
| Forget | 哪些内容已过时、无用、敏感或超过保留期？ |
| Evaluate | 召回是否改善结果，还是只增加噪声和成本？ |

## 从情景到语义的蒸馏

原始轨迹回答“发生过什么”，属于情景材料；从多次轨迹中验证出的稳定结论回答“世界是怎样的”，
才进入语义记忆。例如：

```text
三次认证故障轨迹
→ 对比共同信号
→ 验证根因均为 middleware token refresh
→ 沉淀故障模式与排查规则
```

因此操作日志本身不是高质量记忆。它首先是审计与取证材料，只有经过筛选、验证和抽象，
才可能转化为情景案例、语义知识或程序规则。

## OKF 在记忆架构中的位置

[[Open Knowledge Format]] 可以把语义知识、Playbook、Skill 和计算契约保存为可读、可版本化的文件，
并用 `sources`、`generated`、`verified`、`stale_after` 表达来源、生产、核验与保鲜信号。

综合：OKF 是长期记忆的**序列化与交换载体**，不是完整记忆系统。它没有规定何时写入、如何按目标召回、
新旧冲突怎样调和或哪些内容应遗忘；这些仍需本页的 Write/Retrieve/Update/Forget/Evaluate 策略。

## Claude Tag 的文件化团队记忆

[[2026-07-21-Simon-Willison-Claude-Code团队访谈-源摘要|Claude Code 团队访谈]]披露，Claude Tag 当前按
Slack 频道共享主记忆，各 agent 实例保有自己的会话，会话内容可以贡献回主记忆；底层实现是**每频道一个
Markdown 文件**。这说明文件化、可读的记忆足以支撑早期多人协作，不必先上复杂数据库。

但访谈没有回答谁能把什么写回主记忆、多人冲突怎样合并、跨频道如何授权、错误偏好如何撤销，以及何时过期
或遗忘。因此它证明的是一种存储与共享实现，不是完整记忆治理。综合：是否改用数据库是后置的规模问题；
Write / Update / Forget 的准入与调和规则才是先决条件。

会话内容进入团队主记忆时需要哪些写回门禁，以及该记忆在研发闭环中的位置，见
[[Claude Tag 驱动的团队研发流程]]。

## 在本 wiki 中的映射

- 当前对话、已读取页面和工具结果：工作记忆；
- `wiki/` 中经验证的事实与综合判断：语义记忆；
- `raw/` 与 `log.md`：来源/过程材料和审计轨迹，不自动等于情景记忆或权威事实；
- 从真实任务复盘出的可复用案例：可作为情景记忆；
- `AGENTS.md`、Skills、脚本与固定流程：显式程序记忆。

总体闭环见 [[从知识图谱到 Agent 编排]]。
