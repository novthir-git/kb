可持续文档—代码一致性方案

把“记得更新文档”改造成可执行的工程闭环：按问题分配权威，用关系契约连接规格、代码、测试和运行证据，再以分级一致性、自动门禁与生命周期退出控制漂移。

推荐：从阶段 0 / 1 开始 适用：长期维护的软件与 Agent 工程 原则：AI 调和，程序约束
快照说明：本页基于 2026-07-16 版分析生成，是该版本的快照，不随源分析自动更新。 源分析在此之后已有两次实质补充，本页均未包含：自产自审的实证边界（LLM 自我偏好、跨模型错误相关、 开放式一致性审查准确率仅 14%——直接约束本页第 03 节调和回路里 AI 环节的用法）、反对观点与未决空白， 以及 Anthropic 生产案例。落地前请以源分析当前版本为准。
TL;DR

目标不是“代码和文档永远相同”，而是做到：没有静默漂移、没有无限期漂移、没有不可追溯的漂移、没有不可恢复的自动删除，也没有永久滞留的临时文档。

01

先定义权威，再谈同步

4 principles

不存在一个回答所有问题的“全局唯一真相源”。每类产物只对一种问题权威，重复展示必须是可生成、可失效的派生视图。

01 · INTENT

规格定义“应该怎样”

Current Spec / PRD / 行为契约保存意图、边界和非目标；实现不能反向静默改写需求。

02 · ACTUAL

代码定义“当前怎样实现”

代码、配置和部署产物是实现事实；API 字段、CLI 参数等高频事实从这里自动生成。

03 · EVIDENCE

测试提供符合证据

测试、Evals、CI 和生产指标用于暴露偏差；测试会漂移，因此不是意图的最终裁判。

04 · DECISION

ADR 保存“为什么”

重要取舍、约束与风险接受进入 ADR；临时计划只保留到长期结论完成蒸馏与回写。

可治理漂移 = 问题级权威 + 显式关系契约 + 有界一致性 + 持续调和 + 可恢复生命周期
02

按风险选择一致性等级

4 levels

“所有文档都必须和代码同一提交更新”会制造形式主义。正确问题是：每类内容最迟必须在何时与权威来源恢复一致。

一致性典型产物门禁时点实现机制
强一致Schema / API Reference、配置定义 / 参数表、CLI / Help同一次合并生成后比较 hash；不一致直接阻断 CI
发布一致用户手册、迁移指南、Release Note、对外行为说明行为对目标用户生效前绑定同一交付事务与发布门禁
有界最终一致内部教程、架构概览、培训材料明确 SLA 到期前自动建调和项；逾期退出导航和 Agent 默认上下文
历史不可变ADR、审计记录、重大决策不覆盖旧记录新记录显式 supersedes 旧记录

04

把文档纳入交付门禁

G0—G5

门禁检查的是产物之间的覆盖与证据，不是“是否生成了足够多的文档”。Quick 变更可合并门禁，但不得跳过影响声明和验证证据。

G0

变更分级

明确目标、范围、非目标、负责人和风险；选择 Quick / Standard / Full。

issue / proposalrisk profile
G1

Spec Ready

需求有稳定 ID、可测场景、边界与异常；TBD 必须有负责人和解除日期。

REQ-IDacceptance criteria
G2

Design Ready

接口、数据、安全、观测、兼容、迁移和回滚有覆盖；重要取舍进入 ADR。

designADR
G3

Implementation Ready

REQ → Design → Task 可追溯；任务有依赖、文件边界和完成条件。

TASK-IDdependency
G4

Merge Ready

REQ → Test / Eval → Evidence 完整；派生视图、示例、链接、构建与范围检查通过。

CI evidencedoc impact
G5

Reconcile & Retire

Delta 合并回 current spec；理由蒸馏到 ADR；引用迁移后按保留策略删除或例外归档过程包。

05

用关系契约替代文件猜测

minimal schema

关系与产物在同一变更中声明，类似外键随数据结构演化。先覆盖高风险、高变化率产物，不追求一次建全图。

docs/auth/spec.md · frontmatter
kind: spec
status: active
authority: expected_behavior
implemented_by:
  - src/auth/session.ts
verified_by:
  - tests/auth/session.spec.ts
consistency_level: release
canonical_target: specs/current/auth
retention: living
owner: identity-platform

最小字段集

kind 与 authority 定义角色；depends_on / implemented_by / verified_by 定义关系；status、retention、retire_on 定义生命周期。

删除还必须满足可程序验证的条件：已有显式 supersedes、所有入链已迁移、保留期已届满。AI 判断只能提出候选，不能授予删除权。

关系要证明的问题确定性检查
derived_from派生视图是否来自当前权威重新生成并比较 hash
implemented_by规格是否有实现覆盖REQ-ID、代码映射、验收测试
verified_by关系是否有符合证据测试 / Eval 执行与结果绑定
observed_by声明是否被运行事实验证部署采样、日志、指标与版本
supersedes旧产物是否有明确替代目标存在、入链迁移、宽限期届满
06

生命周期必须自动退出

5 states

“移动到 archive”通常只是把过时声明换了目录。普通工作产物完成后，应先蒸馏长期知识，再从默认导航和 Agent 上下文退出，最终由 Git 历史承担恢复。

draft→active→ superseded→depublished→deleted
例外分支：法规、审计或长期复现义务明确时，depublished → archived；禁止把“可能以后有用”当作永久保留理由。
风险层产物默认自动化权限
T0自动生成内容自动更新、合并、删除
T1临时文档、坏链接、无效索引验证后自动处理
T2已有完整替代的普通文档仅在替代声明、入链迁移、保留期三条件满足时自动处理
T3Spec、PRD、Architecture允许建议或更新；严格限制删除
T4ADR、法务、安全、公开契约禁止自动删除
07

按漂移成本分级落地

3 phases

持续调和平台不是起点。先用低成本门禁消灭高频表达漂移；只有人工调和明确超载时，才升级为事件驱动系统。

阶段 0 · 立即

生成化与交付绑定

  • API / Schema / CLI 文档全部生成
  • PR 必须声明文档影响
  • 示例可执行，生成物在 CI 比对
  • 过程稿完成后蒸馏并删除
退出条件：强一致层无手工副本，CI 可阻断漂移。
阶段 1 · 推荐默认

关系声明与定期 Lint

  • 高风险产物声明关系和 owner
  • 检查断链、孤儿、过期与重名
  • 一致性 SLA 和复核期限可查询
  • AI 做影响分析，人确认高风险项
退出条件：漂移可观测、可追溯，人工异常队列有稳定容量。
阶段 2 · 按需

事件驱动持续调和

  • Adapter 统一框架状态事件
  • AI 自动生成调和候选
  • T0—T2 按确定性条件自动执行
  • T3—T4 进入受控审批或异常队列
进入条件：多仓库 / 高频变更使阶段 1 的人工调和持续超载。
08

自动化基线：先检查能证明的事

CI baseline

确定性程序负责存在性、结构、生成一致性、证据和删除安全；语义模型负责提出影响范围与文本修改。二者不能混成一个“AI 评分通过即合并”的黑箱。

docs-governance.yml · policy sketch
consistency:
  strong: [schema, api_reference, cli_help]
  release: [user_guide, migration, release_note]
  bounded:
    types: [tutorial, architecture_overview]
    sla_days: 14

checks:
  - schema_validate
  - link_resolve
  - generated_diff_empty
  - requirement_coverage
  - example_execute
  - retirement_safety

建议执行顺序

1. 解析变更文件与关系元数据；2. 验证 schema、链接和唯一 ID；3. 重建派生视图并比较；4. 运行与变更相关的测试 / Evals；5. 检查一致性 SLA；6. 对删除候选执行入链、替代与保留期验证。

任何无法证明安全的修改都应退出默认发布路径，进入异常队列；不应阻塞其他已证明安全的低风险项。

09

用“漂移寿命”衡量结果

8 signals

不要用文档数量或 AI 生成字数衡量成功。基线应同时覆盖漂移规模、检测速度、调和时延、覆盖率和人为负担。

指标意图推荐观察方式
超过一致性期限的差异发现无限期滞后按 strong / release / bounded 分层统计
漂移存活时间衡量从产生到调和的速度P50 / P95，按产物风险拆分
断裂关系与孤儿产物暴露关系图和生命周期缺口每次合并增量检查 + 周期性全量 Lint
派生事实生成覆盖率减少独立维护副本可生成事实中由流水线生成的比例
缺证据的状态晋升防止流程“口头完成”transition 与 completion_evidence 联合校验
过期工作产物发现生命周期漂移完成后未回写、未退役的 Spec / Plan / Story
人工异常队列负载决定是否升级阶段 2到达率、处理时长、积压天数
误阻断与恢复次数控制治理系统自身成本门禁 false positive、自动动作回滚率
10

风险与适用边界

4 risks

该方案主要治理表达漂移与生命周期漂移；符合性漂移需要持续取证，运行漂移应对接 IaC / Controller 等成熟调和机制。

关系图自身漂移 HIGH

已声明关系可验证，不等于关系声明完整。用高风险优先、变更内声明、孤儿指标与周期性 Lint 渐进收敛。

AI 错误获得自动权限 HIGH

禁止模型置信度直接授权合并或删除；AI 只提交候选，确定性门禁和风险政策决定是否执行。

治理流程过重 MED

Quick / Standard / Full 分级；低风险团队停留在阶段 0 或 1，避免为低频文档搭建平台级系统。

测试被误当作真相 MED

测试是符合证据，不是产品意图裁判；把 Spec、实现、证据和生产效果分层，显式处理矛盾。
