核心结论

  1. 蓝图已经普及，编排的基本结构不再构成壁垒。
    • 先后顺序：Claude Cowork（2026-01）、Copilot Cowork（03 月）、Gemini Spark（05 月），再到 08–10 月密集上线的 Grok Bot、Muse、Dots、Claude Duet。
    • 主要厂商收敛到同一张蓝图：
      • 每个用户（或每个会话）一套厂商托管的云端运行环境；
      • 连接器优先，没有 API 的系统用 GUI 操作兜底；
      • 长期记忆；
      • 入口放在消息渠道；
      • 事件触发与定时检查；
      • 动作先经模型预审，重要的再交人审批。
    • 这其实是开源 OpenClaw 的形态，换成了托管云版本。DeepSeek 又把编排层开源。推断（置信度：中）：编排的拓扑不再构成壁垒，但 harness 的质量仍在拉开差距。Microsoft 直接采用了 Claude Cowork 的执行框架，SpaceXSI 专门训练 Grok 4.7 来适配 Grok Bot。
  2. 胜负分在三处：分发入口、常驻的单位经济学、信任层（身份与授权）。
  3. 推断（置信度：中）：定位大体是商业模式的投影。
    厂商商业模式对应的定位
    Meta交易抽成Muse 免费、面向大众
    OpenAI订阅拉高 ARPUDots 从 $100 档起步、做人格化
    SpaceX消化自家算力Grok Bot 主打"一队 Bot 外包岗位"
    Anthropic企业席位 + API 用量，同时合并产品、强制上云来提高付费转化和单用户用量治理作为对企业的主要卖点（但个人档默认不逐步审批）
    MicrosoftM365 席位 + Copilot Credits占住跨厂商的 agent 治理层
    DeepSeek给按量付费的 API 引流Super-agent 是开源自托管的参考架构
  4. "常驻"的唤醒频率由算力成本决定。
    • 事件触发已经落地，但只覆盖已接入、能推送的信号：Copilot Cowork 8 月上线；Grok Bot 的 routine 支持 webhook、Slack、git、邮件、Linear 触发。
    • 其余数据源仍靠定时检查和轮询：Duet 每隔几小时一次，DeepSeek 每 60 秒一次。
    • 推断（置信度：中）：固定月费与 7×24 运行的 agent 存在结构性张力。SpaceX 已公开承认服务成本"相对收入高得不可持续"；但 OpenAI 10-29 反而把 Pro 额度翻倍，说明并非每家都已撞墙。
    • 真正收敛的是"订阅或席位 + 用量池"这种计价结构，不是某个价位。没有一家主流厂商落地按结果计价。
  5. 安全分歧不在沙箱，在授权。
    • 授权可以拆成三层：准入（谁能触发）、授权语义（一次同意覆盖多大范围、多长时间）、执行隔离（agent 被攻破后能碰到什么）。
    • 已公开的事故分布在不同的层。已知的注入和越权案例多半借道已经授权的通道，但样本只有个位数。
    • DeepSeek 原型给出一个反例：确定性外壳必须对 agent 自身也不可写、不可绕过。
  6. 推断（置信度：中高）：现阶段的"AI 同事"更接近高级助理。
    • 采用数字反映的是分发能力：Muse 的 1,000 万是"完成设置"的人数，Grok Bot 的 80 万是"付费周用户"，Dots 没有披露。
    • 长程任务的公开最好成绩是 OSWorld 2.0 的 20.6%。注意这是 2026-06 测的上一代模型，当前各家主力模型都还没有公开成绩。
    • 所以它们现在负责的是监控、提醒、起草和轻交易，还不是能独立交付的员工。

四、架构：同一张蓝图，四处分歧

共同蓝图：托管云端运行环境（或自托管机器）+ 连接器优先、GUI 兜底 + 长期记忆 + 住进消息渠道 + 事件和定时唤醒 + 模型预审或人工审批。

分歧维度光谱
隔离粒度一个 agent 一台 VM（Muse、Dots）→ 一个会话一个临时沙箱（Claude）→ 一个账户一台、所有 Bot 共用（Grok Bot）→ 宿主机全权限（DeepSeek）
身份消费产品多为"agent 用你的身份登录"；企业产品转向"agent 有自己的身份"：Claude Tag 的 Agent Identity（beta）、Google Gemini Agents 的独立 Workspace 账号（私测）、OpenAI specialist dots 的组织身份（试点）、Microsoft Entra / Agent 365
审批代码强制（DeepSeek 的准入、Claude 的出站代理）→ 独立 agent 放行（Muse 的 Sentinel）→ 第二个模型预审（Dots 的 Auto-review、Grok Bot 的 Auto Review、Claude 个人档 Auto 模式的自动安全检查）
常驻程度事件触发（Copilot Cowork、Grok Bot routine、Dots 自动化、DeepSeek 飞书事件）→ 每分钟轮询（DeepSeek 的 GitHub 接入）→ 定时加后台会话（Claude、Dots）→ 每隔几小时检查一次（Duet）

能力：长程无人值守的公开成绩在 20% 量级

  • OSWorld 2.0（arXiv 2606.29537，2026-06-28）：108 个长程任务，人类完成一个的中位时间约 1.6 小时。最好的 Claude Opus 4.8 严格完成率 20.6%，部分得分 54.8%；GPT-5.5 约 13%。失败主因不是 GUI 点错，而是丢失约束、漏看中途信息、该问不问、跳过验证。限定：测的是上一代模型，Opus 5.5、GPT-6 Astra、Muse Wonder、Grok 4.7 都还没有公开成绩，实际水平可能更高。
  • Remote Labor Index：最高自动化率 16.1%（Fable 5，The Decoder 2026-07-02）。
  • 成品层面：五家都没有独立的多周可靠性测试。有据可查的问题包括：
    • Dots 发布会现场演示失灵（NBC）；
    • Cursor 状态页 2026-09-18 至 11-05 的 50 条事故中，有 25 条把 Grok Bot 列为受影响组件，其中 15 条标题直接点名；
    • Claude Cowork 有多起误删文件报告（见下方事件表）；
    • Every 的 Claude Duet 测评顺带提到，作者的 Dot 弄丢了报税任务也没提醒。这是单人体验，且 Anthropic 给 Every 提供了提前访问。
  • DeepSeek 实验：p95 从 29.0 分钟降到 15.7 分钟。但基线的长尾主要来自 5 次运行里模型没有委派的那 1 次；用的是合成负载，每组只跑 5 次，官方自称"indicative only"，也没人复现。与提示里鼓励委派的单会话方案相比，p50 只快约 10%。

六、七条核心洞察

1. 编排拓扑已经普及，竞争退到入口和控制层

这张蓝图已被主要厂商普遍采用，DeepSeek、OpenClaw、Comma 又提供了开源实现。各家的护城河在别处：

  • Meta：36 亿日活的家族应用和 WhatsApp；
  • OpenAI：ChatGPT 付费用户和 4,000 多个插件；
  • SpaceX：X 的大众入口和 Cursor 的客户；
  • Microsoft：M365 租户，以及 Agent 365（$15/用户/月）。

推断（置信度：中高）：Microsoft 的打法最值得注意。它不需要做出最好的 agent，只要成为 agent 的登记处。截至 11-03，Agent 365 已接入 Agentforce、Bedrock、Anthropic、Gemini 等，OpenAI 仍在计划中。Copilot Cowork 用的是 Claude 的执行框架，但模型选择器里已经有了 GPT 6.1 Sol 和 Grok 4.7，管理员可以一键关掉 Anthropic 的模型。Anthropic 在 Microsoft 体系里从"技术来源"退成了"可替换的模型供应商之一"。

推断（置信度：中低）：Grok Bot 的叙事是垂直整合、用自研模型消化自家算力，但它的路由仍会把部分任务交给 Anthropic 的 Opus 5.5（占比未披露）。与此同时，SpaceXSI 推出了专为 Grok Bot 训练的 Grok 4.7，并让第三方模型从第一次使用起就按 API 牌价计费，正在把流量拉回自研模型。

2. 常驻的唤醒频率由算力成本决定，谁付成本决定架构往哪边优化

  • 厂商自己付算力（Grok Bot、Muse、Dots、Duet）：压低唤醒频率和模型档位。
    • Duet 每隔几小时才检查一次账户，官方的理由就是节省额度；
    • Dots 在 GPT-6 Astra 之外加入了更便宜的 GPT-6.1 Terra，据 Fortune（11-05），部分任务已因算力成本转给 Terra；
    • Grok Bot 把 Bot 用量并进共享额度池，客服称额度"不固定"（单一来源）；
    • Meta 称 Muse 暂不全球上线，部分因为算力成本、部分为了逐地优化，并押注一年内成本效率提升 10 倍以上。
  • 用户按 API 付费（DeepSeek）：架构可以放心多耗 token，Router 常驻、批处理、大量缓存读都没关系。前提是缓存命中价足够低：deepseek-flash 的命中价是未命中价的 1/50，v4-pro 是 1/30，高峰时段价格翻倍。
  • 事件触发只解决一部分问题：它只覆盖已接入、能推送的信号，其余数据源仍要靠定时检查。Claude 的帮助文档目前只有定时任务，在这一点上落后于 Copilot Cowork 和 Grok Bot。

3. 定价收敛的是结构，不是价位；按结果计价缺席

  • 入门门槛差别很大：Muse 免费，Duet 包含在 $20 的 Pro 里，Grok Bot 从 $30 起，Dots 从 $100 起。
  • 高阶"agent 档"多落在 $100–200/月：Dots、Claude Max/Ultra、X Super/Ultra。
  • 真正收敛的是"订阅或席位 + 用量池"：每周额度、token、Copilot Credits。没有一家主流厂商落地按结果计价。"SaaS 会从按席位转向按结果"这一流行叙事，近期兑现的是"按用量"。

推断（置信度：中）：原因有二。一是结果难以归因和验收，长程任务的公开完成率只有 20% 量级；二是厂商最大的不确定性在自己的算力成本，按用量计价才能把这部分风险转给用户。

固定月费的张力也不是单向的。SpaceX 在收紧额度，OpenAI 却在 10-29 把 Pro 和 Business Premium 的额度翻倍，并撤回了原定的 Pro 200 下调。可见各家的成本承受力和补贴意愿并不相同。

4. 授权分三层，已公开的事故分布在不同的层

准入授权语义执行隔离
DeepSeek最细：按消息是"明确要求"还是"推断"分级准入，工单授权不可变策略带版本号，但 Router 能通过工具改写策略最弱：全权限，本机管理 API 没有 token 鉴权
Grok Bot由模型做 Auto Review有"总是允许"同账户所有 Bot 共用一台电脑
Muse独立的 Sentinel 放行出过事：Marketplace 上的"Allow Always"强（替身 token、出站审查）；但 Mac 端出过一次本地提权漏洞，当天修复
Dots由模型预审四档自定义规则每个 dot 一台 VM；尚无产品级公开事故
Claude频道级身份（Tag）个人档默认 Auto（不逐步询问，靠自动安全检查放行）；有持久化的"always allow"，企业管理员可以禁用；官方承认 computer use 会绕过其他工具的权限检查临时沙箱、凭据不进沙箱；出过事：PromptArmor 借白名单域名外传文件

已知的注入和越权案例，多半借道已经授权的通道：

  • Claude：PromptArmor 借已放行的 Anthropic API 域名外传文件；
  • Muse：Marketplace 上一次"Allow Always"覆盖了此后所有回复；
  • DeepSeek：已结束的工单，只要线程里有人留言就会按原授权恢复，"regardless of who sent it"（理论路径）。

推断（置信度：中）：授权的单位是"通道"而不是"动作"，这可能是行业共同的缺陷。不过公开样本只有个位数。

模型层的注入防御仍不可靠：

  • GPT-6 Astra 的系统卡中，Gray Swan IPI Arena 的 1,810 次攻击、每个场景 15 次尝试内至少成功一次，估计攻击成功率为 8.5%。前代 GPT-5.6 Sol 是 27.0%；同一系统卡的内部评测防御率是 99.79%。
  • 腾讯 A.I.G 对 DeepSeek Harness 的评测，最高攻击成功率为 17.0%（fake-completion，LLM 判官）和 25.5%（hidden Unicode，规则判官）。
  • 推断：如果预审也由同类模型担任，会有同量级的漏检。厂商自己也承认：OpenAI 说 Auto-review 不能当安全保证，且对浏览器、桌面和委派动作的覆盖"remains under review"；Anthropic 承认内置浏览器和 Claude in Chrome 场景的提示注入风险"可降低但无法消除"。

5. 确定性外壳必须对 agent 自身也不可写

DeepSeek Super-agent 最值得学的思想是"代码管规则、模型管判断"：授权、状态和消息长度上限（代码里写死的 IM_WORDS = 100）都由宿主强制。它最大的教训也出在这里：

  • Router 可以通过工具改写策略（允许名单、规则、accept mode）和团队 prompt，"须由人类明确要求"这一条只写在工具描述里；
  • 本机管理 API 只检查 Host、一个公开的固定请求头和 Origin，没有 token 鉴权，文档写明 agent 也可以调用。以全权限运行的 Worker 理论上能借此改写授权（推断，没有公开 PoC）；
  • 自动合并完全由团队 prompt 决定（默认关闭），宿主没有任何合并逻辑。

推论（置信度：高）：如果 agent 能写到、或者能绕过存放规则的地方，宿主强制就退化成了建议。确定性外壳要成立，必须同时满足三点：

  • 规则存在 agent 写不到的地方；
  • 修改规则必须走 agent 碰不到的通道；
  • 执行层被攻破后，也够不到控制面。

6. "一个无处不在的 agent"和"按容器分区的 agent"，是真正的设计分叉

  • 追求连续性的一方：Muse、Dots、Grok Bot 都卖"同一个 agent 跟着你走遍所有渠道"；DeepSeek 的第一个设计特征"连续"（从任何入口进来面对的都是同一个 agent）也是同一个押注。
  • 追求边界的一方：Claude Tag 按频道和身份隔离会话与记忆。DeepSeek 发布后，评论者冯若航提出了最有分量的反论点：Session 藏进底层"天经地义"，但 Context"是工作现场和权限边界……绝不能对用户隐藏"；单一入口让 Router 去猜路由，"迟早要出事故"。
  • Anthropic 两边都押了：Tag 按频道隔离；Cowork 自 08-25 起在 chat 和云端之间打通记忆，Duet 也沿用账户记忆。

推断（置信度：中低）：连续性换来体验，边界换来路由正确和安全。目前已知的两起建档和扇出类隐私问题（Muse 为联系人建档、DeepSeek 订阅扇出不检查发送者）都出在连续性一侧，但样本很少。

7. 采用数字是分发数字，现阶段的"AI 同事"是高级助理

Muse 的增长很大程度靠 Meta 自家广告拉动；Grok Bot 的付费用户来自捆绑订阅；Dots 和 Duet 没有数据。

目前唯一有厂商披露数字支撑的用法，是 Meta 自报的"购物"：超过四分之一的用户在用，平均客单价超过 $200，未经独立核验。推断（置信度：中高）："同事"和"替你干岗位的活"目前还是营销定位，实际形态是监控、提醒、起草和轻交易。用户的真实用法最先证实哪家的定位，比哪家宣称得更大更关键。

七、各家的战略处境

  • Anthropic：
    • 产品布局：把 Cowork 降为 Claude 的执行层（09-16 合并；10-06 起个人付费计划的新任务一律在云端运行）；用 Duet（10-21）补上与 Dots、Muse 同型的独立常驻 agent（The Decoder 定性为对三者的回应）；团队场景交给 Tag。
    • 代价：失去本地运行的隐私卖点；企业的终端安全软件看不到云端会话；管理员强制登出不会终止已经在跑的云端会话。
    • 风险：Microsoft 在对冲，并公开宣称比 Claude Cowork 便宜 30–40%；Claude Code 与 Cowork 的产品负责人 Cat Wu 于 10-30 离职，加入 OpenAI。
  • OpenAI：产品演进路线是 Operator → ChatGPT agent → ChatGPT Work / Codex 云代理 → Dots，从工具型 agent 走到同事型 agent。系统卡里任务中途变更权限的测试通过率为 91.8%。最大的风险在信任背景（见第五节末）。
  • Meta：分发最强，变现路径最新，信任赤字也最大。Amazon 的屏蔽说明，抽成模式会遭到交易平台的反制。
  • SpaceX：付费周用户一个月翻倍（厂商口径，不能与 Muse 的设置数直接比较），成本矛盾也最尖锐。推断：11 月的额度风波是"固定月费 vs 7×24 agent"这个问题最显眼的一次公开暴露；此前 Meta、OpenAI 已以算力为由限制过开放范围。
  • Microsoft：用治理层和按用量计费避开"谁的 agent 最好"这场竞争。
  • DeepSeek：开源编排层。推断（置信度：中）：它的护城河在便宜的缓存 token、Harness 约 27 万 star 的分发，以及默认上传的会话日志。背景是据 Bloomberg（11-01），DeepSeek 最新一轮融资约 1,000 亿元（约 150 亿美元），属于 IPO 前的融资。

八、风险与局限

  • 证据层面：五家都没有独立、多周的可靠性和安全评测；采用数据全部是厂商口径或第三方估算；DeepSeek 的实验无法复现；能力基准测的是上一代模型。
  • 数据可得性：
    • Bloomberg、Fortune 的付费正文未读到；
    • Grok Bot 9 月的用户数和 11 月额度是否被下调，都只有二手来源；
    • 厂商官网存在事后修改：x.ai 8-11 公告的正文被无标注改成了扩容后的开放范围；Anthropic 多篇文章事后补改了套餐名，只有部分带编者注。引用时应以当天的 release notes 为准。
  • 时效性：品类每周都在变。本报告的事实以 2026-11-06 为准，表中的具体参数会很快过时。
  • 监管：
    • Dots 的 Pro 档、Gemini Spark、Muse 暂不在欧盟和英国上线，Claude Duet 目前也只在美国开放；
    • Reuters 和 Al Jazeera 报道 FTC 已就"失控 agent"事件调查 OpenAI、Anthropic 等公司，FTC 未证实；
    • 常驻 agent 读取群聊和第三方消息涉及的知情同意问题已开始有人讨论：TIME 揭露 Muse 为非用户联系人建档；Fortune 援引学者称 agent 读取消息等于读取未同意的第三方数据；EPIC 批评 Muse 诱导用户交出更多数据。但目前还没有监管结论。

九、行动建议

企业试点（任何一家）

  1. 用 agent 自己的身份，不用员工的身份。 可选的方案有 Claude Tag（beta）、Google Gemini Agents（私测）、OpenAI specialist dots（试点）、Microsoft Entra / Agent 365 体系，大多还没正式 GA。
  2. 禁用"总是允许"，或者给授权加作用域和有效期。 授权的单位应该是"这一类动作、在这段时间内"，而不是"这个通道永远放行"。
  3. 把规则放在 agent 写不到的地方。 策略和允许名单的修改，必须走 agent 碰不到的通道。
  4. 执行隔离按"已被攻破"来设计。 不要把同一账户下的多个 Bot 当作隔离（Grok Bot）；自托管方案必须放进专用 VM 或专用 OS 账户（DeepSeek）；注意云端会话可能脱离终端安全软件的视野（Claude）。
  5. 度量人的注意力，而不只是采用量。 至少记录人工介入率、审批次数、返工率和事故率。这正是目前没有任何一家公布的数据。
  6. 按"唤醒频率 × 模型档位"做预算，并为额度变化做准备。 Grok Bot 收紧过，OpenAI 放宽过，额度可能朝两个方向变。

自建或产品设计

  • 借鉴 DeepSeek 的准入设计：按消息强度分级的准入表、不可变的工单授权、带版本号的策略、先 observe 后 auto、在代码里写死注意力预算（消息长度上限）。
  • 避开它的坑：控制面必须对 agent 只读；本机管理接口要有真正的鉴权；恢复已结束的工单要重新过准入；不要把仓库里的 AGENTS.md 这类外部文本直接读进全权限 Worker 的系统 prompt。

投资与商业研究

  • 被威胁的对象：
    • 按席位收费的 SaaS（agent 成为"用户"）；
    • RPA 和流程自动化（被 GUI 操作绕开）；
    • 没有 API 的网站和电商入口（被浏览器 agent 当成 UI 层绕过；Amazon 的屏蔽是反制的开始）。
  • 推断（置信度：中）：受益的是三类位置：
    • 拥有记录系统（system of record）和专有数据的公司；
    • 身份与治理层（Microsoft Entra / Agent 365 一类）；
    • 能把缓存 token 做到极低成本的模型厂商。

十、后续观察信号

  • Grok Bot：额度池的绝对大小，以及单用户收入与成本；企业版是否大规模部署。
  • Muse：月活和留存是否披露；交易抽成率；Confidential VM 是否上线；会不会有更多平台像 Amazon 一样屏蔽；"personal agent protocol"的进展。
  • Dots：首次披露使用数据；企业 11-18 计费后的采用情况；Agent 365 集成何时上线；何时在欧洲上线。
  • Anthropic：事件触发器；Duet 是否 GA、是否走出美国；默认审批口径的矛盾是否消除；S-1/A（11-02）仍未按产品拆分收入，观察后续修订版或上市后财报。
  • Microsoft：自研的 Cowork 1 模型；Agent 365 登记量的一手披露。
  • DeepSeek：是否推出托管版 Super-agent；原型是否恢复维护；有没有第三方量化报告。
  • 品类：当前主力模型（Opus 5.5、GPT-6 Astra 等）在 OSWorld 2.0 这类长程基准上的成绩；第一份独立的多周可靠性评测；第一个按结果计价的主流产品；FTC 或欧盟的执法动向。
