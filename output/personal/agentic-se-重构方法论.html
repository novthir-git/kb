Environment

代码库是 agent 的运行环境

OpenAI 零手写代码实验的第一条结论是瓶颈在环境而非模型：早期进展慢，是因为缺工具、抽象与内部结构；卡住时要问“缺什么能力，怎样让它对 agent 可读且可强制执行”。自述

Böckeler 把代码库可被约束的程度称为 harnessability：强类型、清晰的模块边界、能替 agent 屏蔽细节的框架，决定了能给 agent 套上多完备的 harness。

重构的传统理由（对人）agent 时代新增的理由
降低理解成本降低每次变更的上下文成本（token 与轮次）
降低修改风险提高可被机械约束的程度：类型、依赖规则、结构测试能覆盖多少
让设计意图可读让设计意图对 agent 可执行：规则写进 linter、分层写进结构测试，而不只写进文档

OpenAI 的另一个判断把时间点也改了：人类团队常推迟到数百名工程师规模才引入的严格分层架构，对 agent 是早期前提。

综合原因是 agent 的吞吐让一个小团队在几个月内产出了过去大团队才有的代码量（约 100 万行）。架构约束的收益随代码量增长，引入时点也随之前移。
Token economics

结构债的 token 账

测量 · 单实验 · 单开发者 · greenfield

Thoughtworks（Giles Edwards-Alexander，2026-07-30）利用“agent 不会学习”：每做完一步重构，就让全新 sub-agent 重放完全相同的代表性变更（在 Firestore 层新增一个三方法 trait），记录 token 后丢弃。对象是一个约 15 万行、全部由 agent 写成的应用里的数据访问层——单个 17,155 行的 Rust 文件。重构手法全部取自 Fowler《重构》第 2 版。

收益

读取量降了 83%

最大文件 17,155 → 3,695 行。数据访问层总行数只小幅下降（17,155 → 16,608），最终拆成 19 个文件。

机制

变的是读取路径

节省来自 agent 能找到并只读所需的最小文件子集。作者判断随机把文件切小不会有同等效果。

成本

上界 500 万 token

重构本身未精确计量；上界含两次制定计划与实验设计。全程约 8 小时，基本无人值守。

矛盾：原文结论与原文数据作者称实验显示了重构“in time and money”的价值，但结果表中同一变更的耗时由 342 秒变为 454 秒，并未下降；时间上的价值在表中找不到支撑。

回本与选题 综合

≈38次

5,000,000 ÷ 132,204。分子是作者账户在时间窗内的总消耗（含非重构工作），分母是按文件字符估算的读取量，两者口径不同，输出 token 又更贵——只能说量级是“几十次”同类变更。

综合 · 选题判据优先重构被 agent 频繁改动、且单次变更要读进大量无关代码的热点：改动频率决定复利次数，无关代码的体量决定单次收益。

它把重构接进了已有的成本框架：Uber 用上下文图谱砍“找信息”的轮次，重构砍“读信息”的体量；工具上下文膨胀的固定开销来自工具 schema，这里来自代码文件本身。

guides × sensors

Böckeler 的框架是两根正交的轴：前馈的 guides 与反馈的 sensors；确定性的 computational 与推理型的 inferential。只有反馈，agent 会反复犯同一类错；只有前馈，agent 不知道规则是否奏效。

信号要带修正指引

否则 agent 绕过而不是修正

Böckeler 的实验里，圈复杂度是 agent 唯一频繁直接上调阈值的规则类别，而这条规则恰好没配修正指引。OpenAI 的 lint 错误信息直接内嵌修复指令。

综合 阈值变成了可被优化的目标——古德哈特定律在 agent 身上的形态。

分工

计算型管局部，推理型管跨文件

计算型 sensor 在文件与函数层面最好；跨文件的模块化与耦合要靠 LLM 的语义解释。原始耦合数据直接丢给模型“乏善可陈”，推理型评审 skill 却找到了一批真问题，再跑一次又找到首轮漏掉的——重要分析值得多跑。

Verification first

sensor 的可信度

让“绿”是真的绿

Böckeler 的实验里，一个语句覆盖 100% 的文件没有任何单元测试，变异测试报出 13 个存活变异体。测试也由 AI 写时，覆盖率门禁要配变异测试。

两条约束，防止“验证优先”走样

约束结果，不规定过程

Böckeler 2026-08-10 的小样本评估里，要求 agent 在自己的循环里做 TDD 没带来可见收益；她改用变异测试直接衡量回归测试的质量。

推理型验证会制造噪音

Claude Code 官方最佳实践：被要求找缺口的 reviewer 总能报出一些，追逐每条发现会导致过度工程，只标记影响正确性或需求的缺口；确定性的 Stop hook 门禁连续拦截 8 次后会被强制放行。Osmani 的对策是把举证责任放回作者：PR 附可运行的证据，而不是加大 review。

Legacy systems

最需要 harness 的地方，最难建 harness

没有测试、边界模糊、弱类型的代码库，恰恰最难给 agent 套上约束（Böckeler）。这是遗留重构的出发点。

Campaign 式批量执行 厂商口径 · Osmani 转述

  • Bun 的 Zig → Rust 移植：约 50 个 workflow、11 天、53.5 万行；每个生成单元配两个对抗性 reviewer，以全部既有测试为合并门禁；任何 agent 开跑前，先花数小时写了 Zig 到 Rust 的惯用法对照指南。
  • Asana：两周清掉多年的 Enzyme 积压，模型与基础设施成本约 1.2 万美元（生成的账单，不是对照过的节省）。
  • Claude Code /batch（v2.1.63 起）把同一模式产品化：拆成 5–30 个独立单元、人批准计划、每单元在独立 worktree 里实现并开 PR。

可迁移的共同点：变更是机械的、既有测试套件完整、人仍审每个变更。

批量改动的三种形态 综合

定位 · LLM改写 · LLM

LLM 拆分 ＋ LLM 改写

/batch、Bun。靠既有测试套件与对抗性 reviewer 兜底。

定位 · 确定性改写 · LLM

确定性定位 ＋ LLM 逐处改写

Google：Kythe 找引用、LLM 改每个文件、逐变更自动校验与人审。也就是 Harrer 说的 guided AI。

产出 · LLM执行 · 确定性

LLM 产出转换 ＋ 工具执行

Harrer 的 code transformation recipe：LLM 写确定性转换，由工具整体执行。

逐处验证整体验证

变更越机械、越可枚举，越该往右靠：确定性工具的输出可以整体验证，LLM 的逐处改写只能逐处验证。

认知债在遗留系统里尤其危险：agent 只掌握外化的知识，快速改码会侵蚀团队对系统的共享理解（概念出自 Margaret-Anne Storey，ACM Queue 2026；Harrer 把它用到了现代化场景）。

Böckeler
挪动		系统性泼冷水按风险校准审查（影响、概率、可检测性），认可 spec-first，低风险高可检测时接受 vibe coding

“生成成本趋零后验证成为稀缺资源”在审慎一端有多条一手支持，口径各异：Karpathy 审 10,000 行 diff 时“I'm still the bottleneck”；Osmani 说瓶颈移到了“证明代码能用”；Sonar 2026 调查中 96% 的受访者不完全信任 AI 代码，坚持每次都检查的却不到一半；Anthropic 内部调查里超过一半的人能完全委派的工作只占 0–20%。

综合激进一端在工程实践上普遍后撤到“人仍在验证环”，但范式层的激进判断仍在。与其说是两派之争，不如说是实践层向“验证是瓶颈”的收敛。真正悬而未决的是：在 agent 吞吐下，由谁、用什么来验证。本 wiki 的答案：确定性 sensor 管局部、推理型评审管跨文件、人管选题与高风险区。

重构的六步顺序

综合 · 整体未独立核验

调研稿的顺序是：验证网 → agent 接口层 → 边界重构 → 批量 campaign。它与 Harrer（characterization tests 先行）、Osmani（“Parallelize last”）方向一致。修订版补了一个起点和一个终点；每两步之间是进入下一步的门槛。

  1. 0

    度量与缩范围

    选几个代表性变更，记录输入 token 与改动文件数；先砍掉不必现代化的部分。

    依据：Thoughtworks 的计价法 · Böckeler 的“小改动要改的文件数” · Harrer 的缩范围

    门槛知道热点在哪、基线是多少

  2. 1

    验证网

    characterization tests、CI 门禁；AI 写测试时配变异测试。

    依据：Harrer · Osmani · Böckeler · SWE-Milestone

    门槛热点区域的行为被锁住

  3. 2

    agent 接口层

    短入口文件做地图（只写推断不出的约定），深层文档按需加载；统一命令入口；依赖与分层规则写成 linter。

    依据：OpenAI · ETH 评测（仓库概览无益、成本 +20%） · Claude Code 修剪判据

    门槛规则能机械执行，而不只是写在文档里

  4. 3

    边界重构

    人画区域图、划 seam；按 agent 的读取路径拆热点大文件、去重。

    依据：Osmani 的区域 · Harrer 的 seam · Thoughtworks 的 −83%

    门槛代表性变更的 token 与文件数下降

  5. 4

    批量 campaign

    小而定向、每单元可独立测试；机械变更优先走确定性转换。

    依据：/batch · Bun · Google · Harrer 的 recipe

    门槛既有测试全绿、人审每个变更

  6. 5

    持续偿还

    定期 GC 任务、周期性推理型评审、阈值上调可见。

    依据：OpenAI · Böckeler

    不结束：与传统“重构项目”的根本区别
综合在 agent 吞吐下结构债持续产生，而 agent 不会自发偿还，所以重构不能是一次性项目，必须是 harness 里一个一直在跑的职能。

争议与开放问题

问题现状
spec 是否是新的源代码旗手是 2025 年的 Tessl（已转型）；GitHub Spec Kit 的方法论文档在理念上接近 spec-as-source，但工具实际形态是 spec-first，持久化文档也不强制任何保留模型；Böckeler 担心 spec-as-source 兼有僵化与非确定性
规则 / 上下文文件写多详尽形态已收敛为“常驻入口极简 ＋ 深层按需加载”；效果证据相互矛盾：ETH 测得成本 +20% 且不提升成功率，Lulla 等测得 Codex 运行时间 −28.64%；McMillan 在 25–500 行内未测到文件大小影响指令遵循，与官方“膨胀导致忽略”的说法相左两处矛盾
人能否退出验证环没有一手来源支持“现在”退出：AaaS 也只在 2028 年以后的愿景阶段让人退到元治理层；Google 每个变更都人审
agent 该不该在循环里做 TDD目前唯一的评估（Böckeler，小样本）显示无收益甚至略差；需要更大样本
重构粒度与执行质量OpenAI 的小 PR 顺利、Thoughtworks 的 15 步大重构粗糙；缺同仓库对照
结构债的回本点只有一个实验、一种变更；换一种变更类型、换一个模型，−83% 能保持多少，未知

什么证据会让“agent 不会自发偿还结构债”改口：agent 在无显式重构指令时，自行识别并完成有度量收益的结构性重构（如降低后续变更的 token 或改动文件数），且在多仓库上可复现。

Evidence boundary

证据边界

  • 一手实验都是单点：Thoughtworks（单实验、单开发者、greenfield、每步只测一次）、Böckeler（单人单应用、无对照）、OpenAI（公司自述、无对照，且被指缺少功能与行为验证）。
  • 唯一的大样本基准是 SWE-Milestone（98 个里程碑、12 个模型），它测的是功能演化，不是专门的重构。
  • 唯一的工业级迁移数据是 Google（3 名开发者、同一类迁移、时间节省是自估）。
  • 遗留系统的方法框架主要出自 Harrer 一人，Osmani 是较独立的佐证；campaign 案例的数字来自厂商或转述。
  • 回本估算、“三种批量形态”、“实践层向验证收敛”、六步顺序与首页机制图的三回路合图都是本 wiki 的综合推断；判断“环境”里的“agent 对上下文经济性远比人敏感”沿用自调研稿，只有机制层面的一手支撑。
