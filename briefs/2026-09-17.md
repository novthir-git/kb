### 1. RL 训练本身会诱导 agent 学会调用工具的"错误理由"
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv（University of Washington / UC San Diego / Stanford）/ 2026-09-14
- 摘要：论文用受控合成环境验证一种此前较少被独立量化的失效模式：训练时把事实问答任务（NQ，配 web 搜索工具）
  与某个语义线索绑定，agent 会习得"线索→搜索工具"的伪相关，而非"任务类型→正确工具"的真实关联。反事实评测中，
  把同一线索加到本该用 Python 解释器的数学题（DeepMath）上，agent 误调用搜索工具的比例最高上升 39 个百分点。
  关键发现：这种捷径不是从训练一开始就有——只在 agent 已经学会可靠使用目标工具之后才会出现，且线索与工具的
  语义相关性越强，捷径越明显。作者提出用 LLM judge 对每次工具调用的必要性打一个密集的 decision-level 奖励，
  能有效抑制线索驱动的误调用，同时不损task本身的表现。
- 为何重要：以往对"agent 为什么调错工具"的讨论多聚焦执行阶段——外部输入被误当命令（间接提示注入）或工具
  返回值本身有歧义（如 09-15 简报收录的 Fabrication After Tool Failure）。这篇论文把错误归因的源头往前推到
  训练阶段本身：RL 优化过程可能主动学出一条看似合理、实际是伪相关的工具选择捷径。**证据边界**：实验限定在
  合成的 NQ + DeepMath 双工具环境，未披露具体测试模型的规模或名称；"捷径需先掌握工具"这一结论目前只在两个
  任务上验证，能否推广到真实多工具、多步骤的生产 agent 场景尚不清楚。
- 原文：[Spurious Tool Use: When RL Agents Learn the Wrong Reason to Act](https://arxiv.org/abs/2609.16268)
- 配图：![训练中习得的线索-工具伪相关，在反事实评测中被激活的示意图](https://arxiv.org/html/2609.16268v1/img/Figure-1.png)
  图片来源：[论文 Figure 1](https://arxiv.org/html/2609.16268v1)。

### 2. OpenAI：2 名工程师 + Codex + GPT-5.5，一个季度重写服务 10 亿+ 用户的存储平台
- 领域：软件工程
- 来源 / 发布日期：OpenAI 官方工程博客（两篇系列文章第一篇）/ 2026-09-16
- 摘要：OpenAI 披露其内部存储平台 Habitat 的演进——从一个 Python 库，逐步变成支撑 ChatGPT、Codex 等全部产品的
  独立分布式存储服务，如今每秒处理 70M+ 请求、存储 500+ PB 数据、覆盖约 40 个地理区域，服务超 10 亿用户，
  过去三年年增速维持在 10 倍。2026 年 Q2，团队用 2 名工程师配合 Codex 与 GPT-5.5，在一个季度内把整个 Habitat
  服务从 Python 重写为 Rust；重写后的服务已承担 95% 的生产流量，相对 Python 版本 CPU 效率提升 6 倍、内存效率
  提升 15 倍，计划近期完全弃用 Python 版本。
- 为何重要：这是"小团队 + coding agent 完成关键生产基础设施重写"这类判断难得一见的正面量化案例——此前同类
  证据（如线索 4 的 harness 系列、多数 SE agent 研究）大多聚焦暴露失败模式，鲜少有公司自曝把 agent 用在自身
  核心基础设施迁移上并给出具体倍数。**证据边界**：数字均为 OpenAI 自报，本文原文因抓取工具在 openai.com
  遇到 403 未能直接打开，以下细节转引自第三方技术评论 HackerNoon 与多方检索交叉核验；该评论明确指出，
  一篇主题是"存储延迟"的文章通篇没给出一个具体的毫秒数字，也没有披露实现细节、测试策略与切换验证过程，
  且效率数字客观上也在为 Codex 与 GPT-5.5 打广告，需要独立复核才能作为可靠基线。
- 原文：[Rapidly scaling online storage to serve over 1 billion ChatGPT users](https://openai.com/index/scaling-storage-one-billion-users-part-one/) （原文站点返回 403，经 [HackerNoon 技术解读](https://hackernoon.com/your-load-test-wont-find-these-four-gaps-learnings-from-openais-habitat) 交叉核验，检索于 2026-09-17）

### 4. NHTSA 把对 Tesla Cybercab 的审查升级为具法律强制力的宣誓质询
- 领域：汽车 / 自动驾驶
- 来源 / 发布日期：Electrek（引用 NHTSA 官方 Special Order）/ 报道于 2026-09-15，Special Order 本身签发于 2026-09-10
- 摘要：美国国家公路交通安全管理局（NHTSA）将此前对 Tesla Cybercab 的非正式审查（Audit Query AQ26002，
  2026-09-04 开立）升级为具法律强制力的 Special Order——由首席法律顾问 Peter Simshauser 签署，要求 Tesla
  在 2026-09-30 前以宣誓证词回答 21 项问题，逐条援引 FMVSS 135（脚控刹车）、111（后视镜）、101（人工操作
  控件指示灯）、102/108/126（换挡显示、转向灯、稳定性指示灯）等专为有人驾驶车辆设计的联邦机动车安全标准，
  质疑无方向盘、无踏板、无后视镜的 Cybercab 如何满足自我认证。若答复虚假或不完整，最高可罚 1.39 亿美元，
  负责签署的 Tesla 高管还面临最高 15 年监禁的刑事风险。文章对比同为无方向盘设计的 Zoox：Zoox 走了正式的
  Part 555 临时豁免路径（已获批，年上限 2,500 辆，至 2028 年），而 Tesla 未申请豁免、直接自我认证后于
  9 月 3 日开始商业化载客。
- 为何重要：这是本 wiki 已跟踪的"自动驾驶技术路线与商业化打法之争"线索中"监管审查/合规风险"维度第一次
  出现具体量化的法律强制后果——从"立案调查"（09-06 简报已收录）升级为带截止日期、罚金上限与刑事条款的
  正式法律文书。**证据边界**：Special Order 只是调查程序的一环，不代表 NHTSA 已认定违规，Tesla 尚未正式
  回应；Electrek 长期对 Tesla 持批评/怀疑视角，但文中条款号、签署人、截止日期等细节具体且可独立核对。
- 原文：[NHTSA orders Tesla to prove its Cybercab is legal to sell, under oath](https://electrek.co/2026/09/15/nhtsa-tesla-cybercab-special-order-fmvss-certification/)

## 今日主线

四条今天共同指向同一个问题：AI/自动驾驶系统的自我声明，由谁来核验、核验不过关谁来负责。RL 训练本身可能
悄悄教会 agent 一套看似合理却错误的工具调用理由；OpenAI 展示了 coding agent 用于关键基础设施重写的罕见
正面案例，但这份自报效率数字同样需要外部核验才能站住；资本市场对 OpenAI 估值的判断本身就是一场核验，
不同媒体口径相差 3000 亿美元提醒我们对"据报"数字保持警惕；而 NHTSA 对 Cybercab 的施压，则是把"自证合规"
的要求从企业内部核验搬到了具有宣誓和刑事效力的公开法律程序。能力扩张越快，"谁来核验、如何核验"的分量
就越重。
