### 1. Growing Harness：让 Agent 从失败反馈中"长出"可执行的控制代码，而非反复调用 LLM 做决策
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / 2026-09-22（中国科学院深圳先进技术研究院、澳门大学）
- 摘要：论文提出 Growing Harness——从一个"无策略脚手架"（仅暴露固定的模型与工具接口，不编码任何任务求解控制逻辑）出发，用失败引导的训练范式，把执行轨迹中反复出现的控制决策沉淀成可复用的可执行代码，只把 LLM 调用留给真正需要语义推理的部分；训练过程包含"定位失败→局部修复代码段→回滚保底"的闭环，以保留已有能力。在 BrowseComp-Plus 与 WebArena-Verified 等 6 个基准-模型组合中的 5 个取得最高平均成功率；相对 Tool-Calling 基线，LLM 调用次数减少 76.0%–91.8%，部署后推理成本降低 74.4%–98.6%；在 4B–120B 跨模型规模测试中，WebArena-Verified 成功率稳定在 44.7%–45.3%，而 Tool-Calling 基线在 4B 模型上骤降到 6.7%。
- 为何重要：这把"harness 是独立于模型能力的架构变量"这一判断进一步具体化为一条训练方法论——harness 本身不必靠人工编写，可以从执行反馈中学习生长，且收益在小模型上更显著（说明其部分替代的是模型能力而非仅仅省钱）。证据边界：论文自建的失败引导训练流程未在生产级多租户环境验证；6 个基准-模型组合规模有限，尚无第三方复现；"回滚保底"机制对训练稳定性的长期影响未做消融。
- 原文：[Grow the Harness, Not the Context 论文](https://arxiv.org/abs/2609.26760)

### 2. SWE-Serve：给 Agent 的"生产推理服务"能力单独建了一把尺子，本地测试通过率与生产正确率相差 23.4 个百分点
- 领域：软件工程
- 来源 / 发布日期：arXiv / 2026-09-22（NVIDIA、UC Berkeley）
- 摘要：现有 SWE 基准很少专门覆盖"生产级推理服务引擎"这类任务——既要懂模型支持、又要懂运行时执行与对外 API。SWE-Serve 从 SGLang 真实合并的生产改动中提炼出 53 个仓库级任务，覆盖模型/后端接入、投机解码、内核/量化性能、缓存与运行时状态、分布式调度、服务 API 正确性六大类，每个任务在 CPU 或单张 H100 上跑隐藏的功能测试与回归测试，其中 19 个任务另配端到端服务测试。11 个模型、31 种配置的实验中，最优配置（Claude Opus 5、GPT-5.6 Sol 并列）拿到 75% pass@1，但若把端到端服务测试从评估中拿掉、agent 补丁不变，通过率会从 45.9% 跳到 69.4%——相差 23.4 个百分点；涉及持久状态与并发协调的任务，通过率分别再低 20.8 与 29.0 个百分点。
- 为何重要：这把"补丁通过局部测试 ≠ 审查/生产可接受"这一已在通用代码修复、漏洞补丁、工业系统等场景反复验证的判断，第一次量化搬进"生产推理服务引擎"这个新的独立任务域——说明该差距不是某类任务的特例，而是 agent 处理有状态、高并发生产系统时的系统性弱点。证据边界：任务全部来自单一开源项目 SGLang 的历史 PR，能否推广到闭源/其他推理框架未知；53 个任务规模中等，11 个模型的具体版本与是否存在训练数据污染未在摘要说明；"局部正确 vs 生产正确"差距的根因（测试设计还是模型能力）尚未拆解。
- 原文：[SWE-Serve 论文](https://arxiv.org/abs/2609.26777)

### 5. CliffCompaction：只删不改写的上下文压缩，让长时编码 Agent 的测试时扩展更便宜（今日细读）
- 领域：AI / 智能体（Agent，今日加选）
- 来源 / 发布日期：arXiv / 2026-09-22（Carnegie Mellon University、Bosch Center for AI）
- 摘要：长时编码 Agent 处理复杂问题常需千万级 token 上下文，必须跨会话压缩。CliffCompaction 的核心原则是"忠实优先于回忆"——压缩时只做逐字保留的截断/丢弃（优先舍弃冗长工具输出与文件读取内容），从不改写或重新摘要，且每次压缩只处理当前会话内容、丢弃全部历史压缩记录（不做"压缩的压缩"），以保持 KV-cache 有效性。在 Terminal-Bench 2.0 上，3 次 CliffCompaction 增强的 Kimi K2.6 并行 rollout 即可追平 Opus 4.7（69.7% vs 69.4%），成本 58.01 美元，低于单次 GPT-5.3 Codex 运行；在 KernelBench Level 3 上连续优化 400 步后达到 3.58 倍 CUDA 内核加速，超过专用优化 agent；在 SWE-bench Verified 上于 32K–16K token 阈值下仍保持满上下文的成功率。已开源为可兼容 Claude Code、Codex 等多种 harness 的 scaffold-agnostic API 代理实现。
- 为何重要：这是"harness 是独立架构变量"这条线索里首次把"上下文管理"这一具体组件的工程原则讲清楚（09-17 已有研究指出该组件仅在 token 预算紧张时重要，本文给出了具体可落地的压缩规则），且与今日头条 Growing Harness 形成互补——一个学习"何时不必调用 LLM"，一个决定"哪些历史文本必须原样留下"。证据边界：三个基准均由作者选定，尚无第三方复现；"忠实优先于回忆"的设计假设（重写会导致语义漂移）本身未被单独消融验证；开源实现的多 harness 兼容性未见独立第三方测试报告。
- 原文：[CliffCompaction 论文](https://arxiv.org/abs/2609.26779)

## 今日主线

今天的 5 条共同指向"agent 系统的能力提升正在从模型本身下沉到工程细节"：harness 可以自己从失败中学习生长（Growing Harness），上下文压缩本身就是一门值得单独研究的工程学问（CliffCompaction），而生产级推理服务这类高状态、高并发场景则暴露出局部测试通过与真正可用之间 23 个百分点的鸿沟（SWE-Serve）。与此同时，商业层面的价格战说明"降速"更多停留在言辞，竞争节奏并未真正放缓；汽车领域的一起工伤事件则提醒，Robotaxi 竞赛的安全风险不止在算法层面，测试车辆本身的工程改装也可能是隐患来源。
