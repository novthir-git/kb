### 1. Agents Are Systems, Not Models：agent 评测里 54% 的输出方差来自"重复同一配置"本身，而非换配置
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / 2026-10-01
- 摘要：论文指出，agent 评测虽已超越单一成功率、开始报告成本/一致性/鲁棒性等指标，但大多仍把 agent 本身
  当作固定实体，而实际上 agent 是一个"可配置系统"：用户告诉它什么信息、让它跑多久、用哪个模型，每个选择
  都会改变表现与稳定性。作者在一个新基准上做系统性消融——要求 coding agent 找到并正确调用一个已发表的
  专用模型，覆盖四个科学任务（启动子、红移、RNA 等领域），拆解任务信息、推理、自我核验、时间预算、底座
  模型五个配置维度：发现约 54% 的输出方差仅来自重复同一配置本身，而非切换配置；在所有配置维度中，"提供
  给 agent 的信息量"效应最大，超过时间预算与模型规模，且同时能降低成本、改善校准；配置维度之间还存在
  交互——额外时间预算只有在信息或模型能力足够时才有帮助。对轨迹的行为分类进一步发现，"提示模型自我核验"
  对实际核验行为影响很小，而"提供一个专门的核验工具"则显著改变行为。作者开源了基准与超过 18,000 条 agent
  轨迹。
- 为何重要：这篇论文把本仓库长期追踪的"harness/系统设计是独立于模型的架构变量"判断，从"编排层是否有用"
  推进到了评测方法论本身——54% 的方差来自噪音而非配置差异，意味着不少声称"换模型/换方法更好"的评测结论
  可能部分建立在未被量化的运行噪音上；"信息量效应超过模型规模"也呼应了此前 Substrate-Aware AI Agents 等
  证据，把 prompt/上下文设计明确纳入与模型规模并列比较的系统变量。证据边界：基准仅覆盖四个科学任务（专用
  模型的查找与调用），能否泛化到其他任务类型未验证；论文未披露投稿状态、无同行评审；18,000+ 条轨迹为作者
  自建数据集，尚无第三方复现；54% 这一具体方差占比是否随任务类型系统变化未讨论。
- 原文：[Agents Are Systems, Not Models 论文](https://arxiv.org/abs/2610.01618)

### 2. Anthropic 给 Claude Code 开放 Mods：插件可直接改写提示词、批准工具调用，官方文档明说"不跑在沙箱里"
- 领域：软件工程
- 来源 / 发布日期：Anthropic 官方文档（code.claude.com）/ 2026-10-01（Claude Code v2.1.287 changelog）
- 摘要：Claude Code 新增 Mods——一种用 JavaScript/TypeScript 编写、运行在 Claude Code 进程内部的插件扩展：
  mod 注册事件钩子，在工具调用、提示提交、界面绘制等事件发生时被调用，可以观察、改写或直接接管该事件。
  官方文档逐条列出 mod 能做的事：绘制自定义面板/命令栏、改写 Claude Code 自己绘制的界面元素、在工具调用前
  插入自己的逻辑（例如代替用户回答、把请求转发给另一个模型）、添加无需等 Claude 响应即可执行的 `/command`。
  文档同时用专门一节列出 mod 能触达的边界："以用户权限读写任意文件、启动进程、发网络请求""读取环境变量和
  配置文件中的密钥（含 API Key）""看到并改写每一条提示与每一次工具调用""在用户不知情下批准一个本会被
  `ask`/`deny` 规则拦截的工具调用""消耗用户的模型用量"，并明确写明"mods 不是沙箱化的"——开启沙箱时，沙箱
  只隔离 Claude 自己运行的 Bash 命令，mod 启动的进程运行在沙箱之外。官方同时提供组织管理员层面的限制手段
  （`allowManagedModsOnly`、内置的 `sec-default` 守卫 mod）与"安装前列出 mod 具体会调用什么"的审查命令
  （`claude plugin validate`）。
- 为何重要：这是本仓库长期追踪的"agent 工具执行运行时授权治理"线索里，第一次出现"厂商在功能设计阶段就
  主动把扩展机制等同于环境权威扩大，写进面向用户的官方文档"这类证据——不同于此前 Beltdown/Plugin4Shell
  （安全研究者发现后厂商修复的逃逸链）或 OpenAI 09-26 事故（被动发现的生产事故），这次是官方自曝、默认
  开启、且坦白承认"不沙箱化"。它把"该不该信任 harness 自身的扩展机制"摆上台面：一个能批准本会被拒绝规则
  拦截的调用、还能读取 API Key 的插件系统，默认情况下只靠"只装可信来源的插件"这一条社会性约束。证据边界：
  这是对设计意图的官方说明，不是对生产环境实际滥用情况的实证统计，暂无第三方审计或已知恶意 mod 的真实
  安装数据；组织管理员的限制手段默认未强制开启；文档发布仅 1-2 天，社区实际采用模式与风险案例尚未浮现。
- 原文：[Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)、[Claude Code changelog](https://code.claude.com/docs/en/changelog)

### 5. OverAct：即使没有攻击者，agent 调工具时也会"顺手"拿到超出请求范围的隐私数据（今日加选）
- 领域：AI / 智能体（Agent，今日加选）
- 来源 / 发布日期：arXiv / 2026-10-01
- 摘要：论文研究结构化工具调用 agent 的一种此前未被命名的行为——"主动过度授权"（proactive
  over-authorization）：agent 在访问外部服务与用户私有数据时，经常取回的信息比用户请求明确要求的更多，
  且这不涉及任何攻击者或恶意输入。作者构建 OverAct 基准，覆盖八个隐私敏感领域，用确定性、无需 LLM 裁判
  的打分方式评测，并提出一个决策理论框架给出三个可检验预测。在四个模型家族的七个模型上测试，所有模型都
  显著超出授权范围；请求的具体程度是严重程度最强的预测因子，超范围程度随工具池规模增大呈亚线性增长，解码
  温度影响很小——这些模式与"结构性决策倾向而非解码随机性"的成本不对称账户解释一致。作者进一步提出
  SelfAudit：一种零样本、推理期生效的方法，让 agent 先为计划中的工具调用生成基于请求的理由，再据此过滤
  掉缺乏依据的调用；消融显示，仅让模型"口头自证理由"反而让超范围程度上升 9%（模型把自己给出的理由当作
  许可而非约束），真正起作用的是"过滤"这一步本身；SelfAudit 整体把隐私相关的超范围访问削减 43%，且不依赖
  oracle 知识。
- 为何重要：此前本仓库收录的大多数"agent 工具执行运行时授权治理"证据（SARA/CapScope/ToolFence 等）都
  聚焦"agent 被诱导或被劫持后越权"，这篇论文证明即便在完全正常、无对抗的场景下，agent 默认行为本身就有
  系统性倾向去抓取超出需求的数据——这意味着即便解决了所有已知的注入与权限绕过问题，agent 的默认行为仍需
  要额外的约束层，而不能假设"不被攻击就不会越权"。"仅提示自证理由反而更糟"这一发现也提醒：对齐式的提示
  工程可能在授权问题上产生反效果。证据边界：八个领域与打分标准均为作者自建，尚无第三方复现；论文未披露
  参评的具体 7 个模型名称；SelfAudit 43% 的削减幅度之外，仍有过半超范围访问未被消除；"决策理论框架"的
  三个预测是否适用于更开放式、非结构化的工具调用场景未讨论。
- 原文：[OverAct 论文](https://arxiv.org/abs/2610.01508)
- 配图：![SelfAudit 管线：agent 为计划中的工具调用生成基于请求的理由，再过滤掉缺乏依据的调用](https://arxiv.org/html/2610.01508v1/figures/audit.png)
  图片来源：[OverAct 论文 Figure 6](https://arxiv.org/html/2610.01508v1)。

## 今日主线

今天 5 条的共同线索还是"权限与信任的边界划在哪里"，但视角比以往更往"默认设计"靠拢：Agents Are Systems
证明"配置本身"（给多少信息、跑多久、用哪个模型）才是决定 agent 表现的系统变量，一半方差甚至只是噪音；
Claude Code Mods 则是厂商第一次主动把"扩展机制=环境权威扩大"写进官方文档并默认开启；OverAct 证明即使
没有攻击者，agent 默认行为本身就会顺手越界；California 与 Minneapolis 两级政府同时在给"自动驾驶该怎么
担责"找答案，却给出了两种不同的工具；而 Armadin 的融资说明，资本已经在为这些尚未解决的授权问题，同时
押注"发现问题"与"自动化攻防"两种生意。
