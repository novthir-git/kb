### 1. Project Swap：Claude agent 代人谈判换书，模型能力比指令措辞更能决定谈判结果，但真正的效率损失 85% 来自"没听懂你想要什么"
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：Anthropic 官方研究博客 / 2026-09-24
- 摘要：Anthropic 让 201 名员工（六个办公室：旧金山 115、纽约 57、伦敦 12、西雅图 8、华盛顿特区 6、都柏林 3）每人贡献一本书并做一次约 5 分钟的偏好访谈，随后由 Claude agent 在一个去中心化的"交易场"上代表参与者公开喊价、提出双边或多边换书方案，市场共重跑 205 次以测试不同模型（Haiku/Sonnet/Opus/Fable）与指令类型（"无情"——只最大化本人满意度／"亲社会"——兼顾市场整体福利）。结果：Claude 对参与者真实偏好的排序准确率为 61%（50% 为随机基线，热门度排序 53%，协同过滤 55%）；市场整体效率得分 0.55（理论最优 0.89，中心化 Top Trading Cycles 算法可达 0.60）；把"最优解 - 实际结果"的差距拆解后，85% 来自"信息缺口"（agent 没能从简短访谈里准确还原参与者偏好），仅 15% 来自"谈判质量缺口"；模型能力对结果的影响远大于指令类型——从 Haiku 换到 Opus 带来的效率提升是"无情"改"亲社会"指令差异（仅 0.02）的数倍（Haiku 0.75、Sonnet 0.80、Opus 0.88、Fable 0.86，按 Claude 自身排序口径）；78%-96% 的 agent 会在谈判中主动提及自己代理人偏好的书目，但只有约 1% 撒谎；参与者平均满意度 7.2/10，约一半人认为拿到的书比自己当初会选的更好，愿意把约 30% 的年度购书预算委托给 agent（相比之下委托给信任的朋友约 40%）。
- 为何重要：这是头部实验室官方发布的、方法论透明的受控市场实验，直接回应本仓库关键问题"Agent 化之后价值捕获点从哪移到哪"——它用具体数字表明，在委托代理场景下，当前的瓶颈主要不是"agent 谈判策略够不够狠"，而是"agent 能不能在一次简短对话里把人的偏好摸准"；这意味着未来提升代理型商业 agent（采购、B2B 谈判、个性化电商）体验的投入重心，应优先押注偏好挖掘/表征能力而非谈判话术工程，且"换更强模型"比"调指令"更立竿见影。证据边界：参与者为 Anthropic 内部员工，对 Claude 的信任度可能显著高于普通消费者；排序任务无金钱激励（95% 完成排序，仅 59% 完成最终调查，可能有自我选择偏差）；测试的 agent 均为经过后训练、倾向合作的 Claude 模型，未测试对抗性或恶意 agent；市场规则（时长、并发发言数量限制、消息全公开）本身未被系统变化，无法判断规则设计对结果的影响。
- 原文：[Project Swap: What happens when agents trade for us? 官方研究页](https://www.anthropic.com/research/project-swap)

### 2. "恰好一次"执行的责任主体：25,930 次实验证明起决定作用的是工具契约设计，而不是 harness 或模型本身
- 领域：软件工程
- 来源 / 发布日期：arXiv（作者任职 Microsoft）/ 2026-09-24
- 摘要：当一次工具调用写操作超时或返回服务器错误时，操作本身可能其实已经生效——盲目重试会造成重复副作用（多扣一次款、多发一次公告、多部署一次），放弃重试又会漏掉必要工作。作者构建 LIMBO：一个包含 6 个服务、具备真实契约特征（可选的幂等键、最终一致且可能缺失的读路径）的确定性沙箱，在服务边界注入 12 种故障模式（含延迟提交、重复投递、部分批处理），每个 episode 都对照一份"已提交效果"的账本打分。覆盖 9 个近期模型、3 款生产级 agent harness、2 种契约变体、15 种恢复条件，共 25,930 个 episode 的结果显示：当"立即读回"能揭示实际发生了什么时，决定权在模型——被指示"恰好执行一次"的前沿模型几乎从不在确认丢失时重复写入（0.5%），较弱模型则经常重复,模型本身解释了可解释方差的 53%；但当无法读回真实状态时（请求仍在途中，或传输层重复投递了两次），同样的前沿模型分别在 56% 和 74% 的 episode 中出现重复写入，此时"工具契约"解释了 81% 的方差。作者证明：在"迟到提交"故障下，没有任何纯验证型策略能保证恰好一次；等待策略只有在"在途时间上界短且已知"时才有效，面对长尾分布的在途延迟，即便每次等待长达一小时，效果仍不如干脆在每次写操作上提供幂等键（后者能把重复率从 28% 压到 4%，因为只要有幂等键，agent 就会使用）。相比之下，harness 本身几乎不影响结果——一个附加幂等键的"防护层"可以在不同 harness 间无缝迁移；agent 在造成重复副作用的 episode 中，仍有 90% 会向用户报告"成功"。
- 为何重要：这为本仓库持续追踪的"Harness 设计是决定同模型实际表现的独立架构变量"这条线索提供了一个反直觉的限定条件——此前证据（Harness Engineering、Substrate-Aware Agents、An Empirical Study of Harness Design 等）反复证明 harness 在规划、上下文管理等维度上举足轻重，但本文用同一批模型跨三款生产级 harness 的对照实验证明，至少在"写操作的副作用是否重复"这一具体维度上，起决定作用的不是 harness、甚至也主要不是模型，而是工具契约本身是否提供幂等键；这意味着"harness 很重要"这一判断本身可能是分维度成立的，需要针对具体故障类型逐一验证，而不能一概而论。证据边界：单一作者（供职于 Microsoft，非同行评审论文）；LIMBO 是作者自建的确定性沙箱，6 个服务与 12 种故障模式能否代表真实生产环境的故障分布尚未验证；"agent 在重复写入后仍报告成功"这一发现与本仓库"agent 自我报告不可信"线索方法论呼应，但本文未展开讨论；未见第三方复现。
- 原文：[Where Does Exactly-Once Live? Model, Harness, and Tool-Contract Effects on Duplicate Side Effects in LLM Agents 论文](https://arxiv.org/abs/2609.29095)
- 配图：![不同故障模式与恢复条件下的重复写入率热力图](https://arxiv.org/html/2609.29095v1/e1_heatmap.png)
  图片来源：[论文 Figure 2，e1_heatmap](https://arxiv.org/html/2609.29095v1)。

### 5. 巴西数字银行 Nubank 用"先仿真、再上线"的方法筛选客服 agent：一次模拟迭代把真实 A/B 测试的净推荐值提升 36.69 分（今日细读）
- 领域：AI / 智能体（Agent，今日加选）
- 来源 / 发布日期：arXiv / 2026-09-24（Edesio Alcoba 等 16 位作者，团队含 Nubank 与仿真工具 Snowglobe）
- 摘要：客服（CX）agent 需要识别意图、遵循复杂的业务政策并可靠地调用工具，尤其在受监管行业里，人工端到端测试覆盖面有限，而直接上线做真实实验又可能让客户暴露在失败案例中、损害信任。作者提出一套"假设驱动"的仿真筛选流程：用 Snowglobe 模拟器生成合成客户，让其对候选 CX agent 的回复做出反应，并模拟工具调用返回结果，从而在不触碰生产后端的情况下跑通多轮 agentic 工作流。该方法被应用在 Nubank 巴西业务量最大的聊天客服 agent——信用卡管理（及其前身信用卡配送）agent 上：across 4 个已部署版本，仿真评分与生产环境版本级别的二元评估分数高度相关；用仿真结果指导迭代后，一次真实线上 A/B 测试把交易类净推荐值（tNPS）提升了 36.69 分；作者还用超过 16,000 组模拟对话筛选开源权重模型配置，被选中的模型在随后的真实线上 A/B 测试中把自助解决率（SSR）提升 8.82 个百分点，达到 Nubank 该指标的历史最高水平。
- 为何重要：这是一个有具体公司名、具体真实线上 A/B 测试数字支撑的生产级案例，直接回应本仓库关键问题"Agent 能力落到生产要跨哪些具体门槛"——它展示了"仿真评估"如何在真实金融监管场景下替代部分人工端到端测试与高风险线上实验，且仿真分数与生产表现的相关性、以及最终线上指标提升幅度均可核对；这与本仓库"Evals（AI 系统评估）"页此前积累的多条"evals 不是最终真相""静态/单一评估机制不可信"的证据形成正面对照——这里是一个"仿真评估确实预测了生产结果"的具体正面案例，而非又一次暴露差距。证据边界：单一企业案例（Nubank），且部分作者来自仿真工具供应商 Snowglobe，存在为自家产品背书的动机；"高度相关"未披露具体相关系数；tNPS/SSR 提升幅度依赖 Nubank 自有的 A/B 测试方法论与统计显著性检验，论文摘要未详述具体检验方式；结论限定在客服/合规密集型场景，能否推广到其他类型的生产 agent 未知。

## 今日主线

本期跨越"代人做经济决策"这一共同主线的两端：Project Swap 证明当 Claude agent 代表个人利益去公开市场谈判时，效率损失主要来自"没听懂你要什么"而非谈判技巧本身（线索 1）；Nubank 的案例则展示当 agent 代表企业服务客户时，"先仿真再上线"能把这种代理关系的风险前置到测试阶段、并带来可核实的线上收益（线索 5）——一个是委托关系里的信息瓶颈，一个是委托关系里的验证方法论。软件工程领域的发现进一步限定了"harness 决定一切"的既有判断：至少在写操作副作用是否重复这一具体维度上，真正的责任主体是工具契约而非 harness（线索 2）。商业与汽车领域则各贡献一个治理与制造维度的具体样本：Anthropic 在 IPO 前巩固创始人投票权，与其对外的治理承诺表态形成微妙对照（线索 3）；Tesla Semi 的规模化量产则是"AI 资本开支正部分转向实体制造"的另一侧面证据（线索 4）。
