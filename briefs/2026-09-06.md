### 1. Clean Engineering, Unstable Measurement：LLM 评委在共享推理端点上无法作为"冻结的测量仪器"
- 领域：AI / 智能体（Agent，评估方法论）
- 来源 / 发布日期：arXiv / 2026-09-03（Thu, 3 Sep 2026 17:59:43 UTC）
- 摘要：作者对"黑盒 LLM 评委"的可靠性做了两轮预注册审计，累计近 5.3 万次请求。同一模型在同一时间窗口内对完全相同的候选答案重复打分，排名一致性仅达 Spearman 0.400（预注册门槛要求 0.90）；跨天重放字节级相同的输入，一致性也只有 0.78（门槛要求 0.99）。作者定位到三种失效机制：标签含义的系统性偏差、信号强度远低于测量噪声、以及"字节级相同输入返回不同排名"。他们尝试了换指标、调整采样、等待、换供应商、自托管等多种补救手段，均未显著改善。结论是："在共享端点上，模型名称不是一台冻结的测量仪器"，并给出一套评估前先校验"测量仪器"本身的报告规范。
- 为何重要：这直接冲击"把 LLM-as-judge 当作稳定裁判、一次性设定阈值就能长期复用"的常见做法，为本 wiki 已跟踪的"outcome/评估不是最终真相"判断补上一个关于测量本身不稳定性的具体量化案例。证据边界：两个审计活动、约 5.3 万次请求，聚焦特定任务类型（算术任务)+特定观测协议，未公开作者机构信息；补救手段的"基本无效"是在其测试的供应商/模型范围内成立，不能排除某些专用评估基础设施已解决此问题；核心指标（Spearman 相关系数）本身是否是衡量"评委可靠性"的最佳代理，论文未与其他可靠性框架交叉验证。
- 原文：[Clean Engineering, Unstable Measurement（arXiv 2609.04198）](https://arxiv.org/abs/2609.04198)

### 2. Refusing the Impossible：给"代码幻觉"建分类法和基准，12 个开源模型平均六成场景一本正经编造
- 领域：软件工程
- 来源 / 发布日期：arXiv / 2026-09-03（Thu, 3 Sep 2026 01:50:06 UTC）
- 摘要：论文把"代码幻觉"定义为一种独立于普通编程错误的"无根据生成"——模型生成的代码看起来可执行、可信，但导入不存在的包，或声称实现了与数学定理矛盾的算法。作者提出三维分类框架（真实性维度：普适真理违背 vs 生态系统特定捏造；表现层级：语法/语义/事实；行为模式：从自信捏造到降级输出），并构建了对抗性测试集——270 个覆盖 6 种语言、24 个子类别的"不可能任务"提示词，配 91 个可解的匹配对照组，用双层评估协议标注（与人工判断的一致率 82%，Cohen's κ=0.73）。在 12 个开源权重模型上测试发现：面对"不可能"场景时，模型平均约 60% 的情况会生成无根据代码，仅 27% 的时候会正确拒绝；而面对本身可解的对照任务，错误拒绝率为 0%。
- 为何重要：这把"模型编造代码"从模糊的"幻觉"标签，拆解成可复现测量的分类体系和基准数字，且证明"能正确拒绝不可能任务"与"不会误判可解任务为不可能"是两种彼此独立、当前模型都做得不好的能力——与本 wiki 已跟踪的"SE agent 补丁通过测试≠真正可靠"这条判断（[[Evals（AI 系统评估）]] 相关线索，见 09-05 简报 SWE-Gate 一条）互补，从"幻觉/拒绝"维度补上又一个具体的能力缺口。证据边界：仅测试 12 个开源权重模型，未包含主流闭源前沿模型；对抗性提示词由作者构造，270 个提示 + 91 个对照的规模用于建立分类基准而非穷尽真实场景分布；82% 一致率、κ=0.73 属"高但非完美"的标注可靠性,部分边界案例的分类可能存在争议。
- 原文：[Refusing the Impossible: A Taxonomy and Benchmark for Code Hallucination in LLMs（arXiv 2609.03267）](https://arxiv.org/abs/2609.03267)

### 5. TAHI：让 Agent 在测试时通过人机交互吸收"个人专业判断"，30 人 600 项任务上成功率提升最高 20.9%
- 领域：AI / 智能体（Agent，今日加选）
- 来源 / 发布日期：arXiv / 2026-09-03（Thu, 3 Sep 2026 17:33:18 UTC）
- 摘要：论文指出，Agent 在群体规模数据上训练获得的是"平均能力"，但专业人士的价值恰恰在于偏离平均、达到个人愿意为之背书的水准；这类个性化标准往往说不清楚，却在多轮人机交互中反复体现。作者提出 TAHI（Test-time Adaptation through Human-agent Interaction）框架，把跨会话交互信号整合进 Agent 的上下文与权重，并通过一个"演化中的评分细则（rubric）模块"将其固化为可复用的评价标准。在写作和数据可视化两个领域、30 个真实用户、共 600 项任务上测试：Agent 独立完成任务的成功率在仅数十项任务内提升 4.5%–20.9%；演化评分细则模块比单独用 LLM 或人工制定的评分细则多捕捉 16.0%–22.3% 的失败案例；个性化后的 Agent 还表现出最高 8.8% 的跨用户泛化提升。
- 为何重要：这提供了一个具体、量化的"Agent 个性化/测试时适应"案例，且核心贡献之一——"演化评分细则能捕捉更多失败"——直接呼应本 wiki 已跟踪的"评估本身需要持续调和、不能一次性冻结"这条判断，与本期第 1 条（LLM 评委测量不稳定）形成同一主题的两面：一个说明"冻结的评委"会失效，另一个说明"演化的评分标准"能带来实际收益。证据边界：仅 30 个个体、两个任务域（写作、数据可视化），样本规模有限；"4.5%–20.9%""16.0%–22.3%""8.8%"均为作者自报的区间而非单一确定数字，具体分布未在摘要中说明；结果依赖论文自建的交互界面与评分细则设计，能否泛化到其他任务域或生产环境尚未验证。
- 原文：[Efficient Test-Time Adaptation through Human-AI Interaction（arXiv 2609.04141）](https://arxiv.org/abs/2609.04141)
- 配图：![人类与 Agent 通过带演化评分细则模块的交互界面协作示意图](https://arxiv.org/html/2609.04141v1/human-agent-interaction.png)
  图片来源：[论文 Figure 1](https://arxiv.org/html/2609.04141v1)。

## 今日主线

今天五条共同指向"评估基础设施本身是否可信"这个比"模型能力"更底层的问题。AI/Agent 一侧：《Clean Engineering, Unstable Measurement》用近 5.3 万次请求证明,把 LLM 评委当作可以设定固定阈值的"冻结仪器"是错误假设；《TAHI》则从正面提供了一个对照——让评分标准随交互持续演化，而不是一次性固定，反而能捕捉更多失败案例并带来可测量的个性化收益。软件工程一侧：《Refusing the Impossible》把"模型编造代码"这个模糊问题拆成可复现的分类与基准,发现"正确识别不可能任务"与"不误判可解任务"是当前模型都做不好的独立能力,呼应了 09-05 简报 SWE-Gate 的"测试通过≠真正可靠"判断——评估的隐性维度还有很多没被现有基准覆盖。物理世界一侧：Crusoe 融资显示资本仍在为 AI 基础设施的合同规模买单，而 NHTSA 对 Cybercab 的正式立案调查，把这周持续三天的自动驾驶技术路线之争（Cybercab 发布 → Wayve/Uber 伦敦发布 → 联邦监管介入）推进到了监管验证阶段——同样落在"验证滞后于部署"这张更大的图景里。
