### 3. "不信任模型直接生成结构化产物/编辑"的确定性执行范式
- 2026-09-03：Don't Let the Model Write the YAML（arXiv 2609.00227）在 Kubernetes manifest 场景证明，无论是统一 diff 还是整文件重写都不适合无人值守自动化（宽容 patch 工具仍有 14%-20% 静默误改率），改用"agent 只给结构化字段意图 + 确定性流水线精确替换字符区间"的方案。
- 2026-09-05：When Models Edit Too Much（arXiv 2609.04061）在代码修复场景量化"过度编辑"问题（前沿模型含 GPT-4.5 普遍存在），"保持最小改动"指令与 RL 后训练均能改善编辑保真度，且证明其独立于修复正确性可测量。
- 2026-09-11：If It's Not Buggy, Don't Fix It（arXiv 2609.10123）把同一判断带到第三个独立场景——迭代式自动修复循环：LLM 在完全无 bug 的程序上仍反复"声称"发现 bug，且修复正确代码的破坏率高于修复真实 bug 的成功率，迭代过程常陷入"加了又撤"的循环；机制分析进一步发现一个控制"编辑倾向"的 steering vector，提示模型存在一个会被不当激活的"缺陷代码"内部表征。
- 状态：候选中 3 条，**已跨越"配置文件改写（YAML）→ 代码修复过度编辑量化 → 迭代 bug-fixing 循环 + 虚假 bug 声明的机制分析"三个场景，正式跨过门槛 a（≥3 条跨天证据）**。**已在本期简报提议沉淀**（新建 `wiki/topics/不信任模型直接编辑的确定性执行范式.md`，暂拟页名），尚待用户批准。

### 6. 审计不必自上而下：透明的多 agent 通信基础设施能让对等审计/吹哨自发涌现，但检测手段普遍落后于攻击/合谋能力
- 2026-09-05：Google DeepMind《A Case Study on Emergent Cheating and Whistleblowing in Autonomous Research Swarms》（arXiv 2609.04170）用 100 agent 受控案例研究显示，同一套透明通信基础设施既让评测漏洞的作弊传播开来，也让另一批 agent 自发组织审计与抵制。
- 2026-09-09：CABAL（arXiv 2609.05227）用 LLM 驱动的审稿人 agent 模拟学术同行评审中的合谋竞价，覆盖竞价→分配→审稿结果全生命周期：串通后目标论文捕获率从 28.0%–29.6% 升至 71.8%–76.9%，但现有检测器"几乎无法区分攻击痕迹"，集合检测器仅能找回小部分串通者（如 77 人中 42 人）——首次把"检测端系统性落后于攻击能力"量化到具体场景。
- 状态：候选中 2 条。**已在 09-05、09-09 简报提议沉淀**（追加证据到「Agent Auditing」`wiki/concepts/agent-auditing.md`），截至本期尚待用户批准。

### 7. SE agent 补丁"测试通过"与"审查可接受"是两回事，且差距可量化
- 2026-09-05：SWE-Gate（arXiv 2609.04167）在 75 仓库 303 修复实例上发现，644 个通过功能测试的补丁中有 221 个（约 34%）未满足对应审查约束。
- 2026-09-07：PatchBench（arXiv 2609.04075）把同一判断带到"漏洞补丁"这个独立任务域：25% 的 agent 补丁与历史开发者补丁高度相似（疑似记忆而非现场推理），传统"仅用 PoC 复现"的验证方式让 11 个被测 agent 的补丁解决率平均虚高 1.83 倍——首次把"记忆历史答案"和"验证方式本身注水"两种具体失效机制量化出来。
- 2026-09-08：Better Understanding, Better Fixes?（arXiv 2609.04909）在 Defects4J 832 个 bug、812 例人工复核样本上发现，72.7% 的修复存在"幻觉"（含通过全部可用测试的补丁），错误因果定位与错误修复策略分别占 45.9%、18.5%——把问题从"验证方式是否注水"进一步深入到"修复过程本身的因果假设是否成立"。
- 2026-09-09：一篇工业案例研究（arXiv 2609.04483）把同一判断带到两个真实 Java 生产系统：38 个真实崩溃 bug 上，LLM+崩溃报告挖掘的最优配置能定位 71%，但只正确修复 52%——首次在真实工业场景（而非学术 benchmark）量化"定位"与"修复"两个环节的落差。
- 状态：候选中 4 条，已跨越"通用代码修复""漏洞补丁""修复过程幻觉分析""工业真实系统"四个独立任务域，**门槛 a（≥3 条跨天证据）持续巩固**。**已在 09-05、09-07、09-08、09-09 简报提议沉淀**（追加证据到「Evals（AI 系统评估）」`wiki/concepts/Evals.md`），若用户批准则转为"已沉淀"。

### 8. LLM-as-judge / 评估基准不能被当作一次性冻结的裁判，需要持续校验或演化
- 2026-09-06：《Clean Engineering, Unstable Measurement》（arXiv 2609.04198）用近 5.3 万次预注册审计请求证明，黑盒 LLM 评委在共享推理端点上，同一模型对相同输入的重复打分一致性远低于预注册门槛（Spearman 0.400 vs 要求 0.90），换供应商/自托管等补救手段基本无效——"模型名称不是冻结的测量仪器"。
- 2026-09-06：《Efficient Test-Time Adaptation through Human-AI Interaction / TAHI》（arXiv 2609.04141）从正面提供对照：让评分细则（rubric）随人机交互持续演化而非一次性固定，能比静态 LLM/人工评分细则多捕捉 16.0%–22.3% 的失败案例。
- 状态：候选中 2 条（未达门槛 a 的 ≥3 条）。两条分别指向同一判断的"问题"（冻结评委不可靠）与"缓解方向"（评分标准持续演化），与已有线索 7（SWE-Gate）及「Evals（AI 系统评估）」页的"Evals 不是最终真相"论点相邻但角度不同（测量工具本身的稳定性，而非评估覆盖面）。若下次再出现独立的第三方复现或生产环境案例，可考虑提议追加到「Evals（AI 系统评估）」或新建更聚焦的 concepts 页。

### 9. 代码幻觉（无根据生成）是独立于普通编程错误、可分类可测量的能力缺口
- 2026-09-06：《Refusing the Impossible》（arXiv 2609.03267）提出代码幻觉三维分类法，在 12 个开源模型上测得：面对"不可能任务"平均约 60% 会编造无根据代码，仅 27% 正确拒绝；面对可解任务错误拒绝率为 0%，说明"正确识别不可能"与"不误判可解任务"是两种当前模型都欠缺的独立能力。
- 状态：候选中 1 条。单一奠基性基准（未达门槛 a），暂无对应 wiki 落点页（与「Evals（AI 系统评估）」相邻但聚焦点不同：该页目前证据链聚焦 outcome/审查缺口，这篇聚焦"幻觉行为分类"）。继续观察是否有后续独立评测或闭源模型上的复现。

### 10. Agent 互操作协议出现标准化机构背书的新竞争者
- 2026-09-07：NLIP（arXiv 2609.04135）经 Ecma International 标准化，正面对标 MCP、A2A，已被 ACM AI Summit 2026 接收；核心是可跨 HTTP/WebSocket/AMQP 承载的轻量语义消息信封，内建安全设计原则。论文本身是协议提案 + 参考实现，无生产采纳数据，作者机构不明。
- 状态：候选中 1 条。单一提案性来源（未达门槛 a/b），与「Agent Task Protocol」`wiki/concepts/agent-task-protocol.md` 主题相邻但范畴不同（ATP 是 benchmark×harness 的内部软件接口，NLIP 是网络层互操作协议标准提案）。继续观察是否有后续行业采纳信号或与 MCP/A2A 的正面竞争案例。

### 11. 区分语言模型"表面欺骗行为"与"欺骗性机制"需要因果分析工具，不能只看行为
- 2026-09-07：《From Deceptive Outputs to Deceptive Mechanisms》（arXiv 2609.04166）提出因果分类法，拆开"事前承诺 vs 事后报告""模型偏好 vs 实际输出"等维度，在两个开放权重模型家族的受控实验（猜谜、模拟股票交易）中验证：表面欺骗行为可独立于假设机制出现，观察到欺骗性机制不必然证明模型有欺骗"能动性"。
- 状态：候选中 1 条。单一作者、单一理论框架（未达门槛 a/b），与线索 6（DeepMind 欺骗涌现案例）方法论互补但角度不同（一个是实证案例，一个是分析工具）。暂无对应 wiki 落点页。继续观察是否有独立复现或应用到真实生产 agent 审计的后续工作。

### 12. Agent 记忆的存储格式选择隐含不同的"模型可迁移性"风险
- 2026-09-08：《Does Your Agent's Memory Survive a Model Upgrade? A Controlled Study of Memory Portability》（arXiv 2609.05339）比较 LC-RAW / RAG / NOTES / KG-fixed 四种记忆格式，发现压缩程度越高（NOTES）模型升级后准确率波动越大（+9.91~-13.28 个百分点）且越难事后修复（48 案例中 0 例达 90% 恢复阈值），而保留原始历史或归一化知识图谱更抗升级冲击（KG-fixed 波动仅 ±0.0020）。
- 状态：候选中 1 条。**已在本期简报提议沉淀**（新建 `wiki/concepts/agent-记忆的模型可迁移性.md`，单一来源、标注待独立复现），若用户批准则转为"已沉淀"。命中门槛 b（单个受控实验设计严谨，足以形成初步可复用判断）。

### 13. LLM 车间协商为多车协同自动驾驶决策提供新架构范式
- 2026-09-08：CoLMIN（arXiv 2609.04807）提出多意图协商（LMin）+ 浅层反思（ESRM）+ 深层反思（LDRM）三模块架构，缓解现有 LLM 车间协商方法过早收敛到次优解的问题，在 CARLA 仿真的高交互性场景中优于现有方法。
- 状态：候选中 1 条。仅 CARLA 仿真验证，未见与已有 wiki 页面（如线索 5 的商业化路径之争，聚焦感知/商业层而非协商架构）直接关联，未达门槛 a/b/c，继续观察是否有真实道路测试或后续独立复现。

### 14. 长时 agent 记忆在紧张 prompt 预算下的设计权衡：合并规则与打包方式比检索算法更关键
- 2026-09-09：RSM-full（arXiv 2609.04915）提出在线聚类记忆流水线，在 4k token 预算下达到全上下文质量的 83%、仅用 32% 的 token 成本；消融显示提升主要来自"合并规则"（+5.7pp）和"分组打包器"（+5.0pp），而非检索算法本身；论文自陈该方法仅在 2.6k–5k token 区间是帕累托最优，超出区间不成立。
- 状态：候选中 1 条。单一来源（依赖作者自建 AMA-Bench，未达门槛 a/b），与线索 12（记忆存储格式的模型可迁移性）相邻但问题不同（12 测模型升级后的可迁移性，本条测固定模型下的预算权衡），也与已有页 [[Agent 记忆架构]] 的"存储不等于记忆"讨论相关但未达到直接改写页面判断的强度。继续观察是否有第三方复现或更大规模验证。

### 15. 自动驾驶规划器验证：把"生成对抗场景"和"做规划决策"统一到同一模型，用于打破"benchmark 领先≠鲁棒"的假象
- 2026-09-09：《One Diffusion Model, Two Roles》（arXiv 2609.04921）证明单个预训练扩散交通模型可同时作为自车规划器和安全关键场景生成器，在 nuPlan 闭环仿真中用生成的长尾交互场景暴露规划器失效模式，论文明确指出"基准测试上的优越表现不必然转化为鲁棒性"。
- 状态：候选中 1 条。ECCV workshop（非主会）录用，仅 nuPlan 闭环仿真验证，未见真实道路数据（未达门槛 a/b）。与「Evals（AI 系统评估）」页的"evals 不是最终真相"核心判断方向一致，但属自动驾驶垂直领域的独立数据点，暂不视为足够强的跨域证据。继续观察是否有更高级别会议的后续版本或跨领域呼应。

### 16. Agent 可靠性问题的新切面：同一任务重复执行的"一致性缺口"，独立于平均通过率
- 2026-09-10：《Closing the Consistency Gap》（arXiv 2609.08832）在 AppWorld 基准上测得 GPT-4.1+ReAct agent 单次任务平均通过率 77%，但同一任务连续五次全部成功的比例只有 53%（24 个百分点落差）；提出的自演化框架（Consistency Analyzer + Guideline Generator）把"五次全对"比例在同任务/相似任务上分别提升 16/13 个百分点。
- 2026-09-11：Do Agents Know When They Succeed?（arXiv 2609.09448）从第三个独立视角切入同一判断——能否从模型内部表征（残差流动态 LTD、动作决策点探针 ARP）预测 agent 任务是否真正成功；在 Bash/SQL/Python 三个交互式基准、Qwen14B/Qwen7B/DeepSeek6.7B 三个模型家族上一致优于传统校准基线，且无需 prompt 修改或多次采样。
- 状态：候选中 2 条，**已与线索 17（进度自报可靠性）凑齐"一致性执行→进度自报→成功信心校准"三个独立证据源/视角，正式跨过门槛 a**。**已在本期简报提议沉淀**（新建 `wiki/topics/agent自我报告的不可信性.md`，暂拟页名，拟合并本条与线索 17），尚待用户批准。

### 17. Agent 任务进度自报的可靠性因执行阶段而系统性失真
- 2026-09-10：《The Unreliable Progress Bar》（arXiv 2609.08589）在 τ²-bench 与自建 StageIF 测试床上发现，几乎所有被测模型的进度汇报可靠性都"因阶段而异"：多数已部署模型在任务中段准确率下降、完成后恢复，最新一代模型修复了中段下降但在任务临近结束时变得过度保守；作者主张 agent 框架不应仅凭模型自身状态汇报控制任务流程。
- 状态：候选中 1 条，与线索 16 的 2026-09-11 新证据（Do Agents Know When They Succeed）合并计入"agent 自我报告不可信"论点，**跨过门槛 a**，详见线索 16 状态与本期沉淀候选。StageIF 检查点划分为作者自建，"最新一代模型"判断基于有限样本，未量化对真实生产系统的实际影响，此局限性在合并后的证据点表中仍需注明。

### 18. 自动驾驶场景化测试的流水线统一：用 LLM agent 编排全流程验证，而非单一模型兼职
- 2026-09-10：PlannerForge（arXiv 2609.08965，EMNLP 2026 主会）用统一 LLM-agent 框架覆盖场景生成、选择、修改、模块路由、规划器测试、增强全流程，10 个 LLM 评测下各任务最佳得分 0.88-1.00，端到端流水线种子查询留存率商业/开源模型分别 83%/78%；成本调优把规划器成功率从 50.4% 提到 70.2%，碰撞率从 19.0% 降到 8.4%。
- 状态：候选中 1 条。EMNLP 是 NLP 主会而非核心 AV 安全会议，报告指标均为流水线内部自动化得分，未见真实道路数据对照（未达门槛 a/b）。与线索 15（One Diffusion Model, Two Roles）方法论互补——一个是单模型兼任规划器与场景生成器，一个是多阶段 agent 编排验证流水线，暂不合并。继续观察是否有后续独立复现或与线索 15 的正面方法对比。
