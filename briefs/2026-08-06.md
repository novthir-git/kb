### 1. ContinualSkillBench：Agent 的“技能进化”大部分可能只是上下文适应
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / 2026-08-04（过去 72 小时扩展）
- 摘要：北京大学与北京通用人工智能研究院团队提出 ContinualSkillBench，在医疗、法律、数学、金融和办公五个领域各设置 100 个相互关联的连续任务。顺序执行在 15 个“模型×领域”组合中的 14 个带来提升，整体相对增益为 16.9%；但纯上下文学习与显式维护技能库的平均归一化奖励几乎相同（0.605 对 0.602）。
- 为何重要：结果削弱了“Agent 写下更多 skill 就等于能力持续进化”的直觉：很多收益可能来自保留历史与反馈，而非形成了可迁移的程序性知识。真正值得优化的指标应从技能数量转向复用率、压缩度和跨任务迁移效果。
- 原文：[ContinualSkillBench 论文](https://arxiv.org/abs/2608.03874)

### 2. Active-SWE：没有 Issue 报告时，最强 Coding Agent 的主动修复率仍只有 20%
- 领域：软件工程
- 来源 / 发布日期：arXiv / 2026-08-05
- 摘要：Active-SWE 将评测从“根据详细 Issue 修一个已知 Bug”推进到“在没有 Issue 指引时主动发现并修复一个或多个 Bug”，共构建 1,663 个任务，覆盖六类缺陷和八种编程语言。论文的 400 题精选集上，参评模型对已记录 Bug 的最高完整修复率仅 20.0%，多 Bug 场景尤其薄弱。
- 为何重要：它更接近生产中的真实维护工作：Agent 必须先决定哪里值得查、问题是什么，再生成补丁和测试证据。结果说明自主软件维护的主要瓶颈仍是仓库理解与 Bug 定位，而不只是补丁生成能力。
- 原文：[Active-SWE 论文](https://arxiv.org/abs/2608.04682)

### 3. Robinhood 把 YC 早期公司打包成上市基金，零售投资者获得“类风投”入口
- 领域：创业 / 商业
- 来源 / 发布日期：TechCrunch / 2026-08-05；Robinhood 官方公告 / 2026-08-03
- 摘要：Robinhood Ventures Fund II（RVII）计划于 8 月 13 日以每股 25 美元在纽交所上市，初始组合约含 80 家私营公司，重点面向现任或往届 Y Combinator 创业者。它是可公开交易的 BDC，而非让投资者直接持有创业公司股份；管理费为净资产的 2%，另收已实现资本利得的 20% 激励费，并存在额外费用、估值不确定与折溢价风险。
- 为何重要：如果这类产品扩大规模，私募市场的分销会从机构 LP 模式部分转向交易所零售渠道，但流动性只存在于基金份额层，不等于底层资产变得透明或可退出。Robinhood 同时扮演发行平台、投资顾问和收费方，利益冲突与费用结构值得比“人人可投 YC”这一叙事更受关注。

### 4. PCTP 用多级“枢纽点”降低自动驾驶长时轨迹预测的误差累积
- 领域：汽车 / 自动驾驶
- 来源 / 发布日期：arXiv / 2026-08-04（过去 72 小时扩展）
- 摘要：PCTP 将长时轨迹预测拆为多尺度枢纽点预测和局部轨迹细化，试图同时解决单一终点引导不足与迭代细化误差累积。它可插入 LaFormer、HPNet、DenseTNT 和 QCNet 等现有模型；验证集上的 b-minFDE 分别下降 3.5%、1.2%、1.9% 和 3.9%，与 QCNet 结合后在提交时位列 Argoverse II 无集成方法首位。
- 为何重要：自动驾驶对周边参与者的长时预测不能只给一个终点，也不能无限迭代整条轨迹；分层中间目标提供了更可控的结构。更关键的是，该方法以较小模型增量改善多种 backbone，具有比替换整套感知预测栈更低的工程迁移成本。
- 原文：[PCTP 论文](https://arxiv.org/abs/2608.03521)

### 5. 首个面向“Agent + 业务数据 + 工具编排”的系统级形式化验证框架
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / 2026-08-04（过去 72 小时扩展）
- 摘要：研究将单个 LLM、工具编排器和关系型业务数据组合形式化为 Stateful Tool-Enabled Agentic Deployments（STEADs），并用一阶计算树逻辑描述业务约束。作者证明一般验证问题不可判定，但在有限域与标识符重命名等变条件下可精确验证且为 PSPACE-complete，并提出可为任意基础 Agent 强制满足该条件的规范化 wrapper。
- 为何重要：这把 Agent 安全从“接口层阻止某次危险调用”推进到“系统层验证工作流和数据状态始终满足业务规则”。它尚是理论框架而非即插即用工具，但明确了生产 Agent 可验证性的边界、代价与一个可落地的封装方向。
- 原文：[Formal Verification of Agentic Systems over Operational Data](https://arxiv.org/abs/2608.03609)

## 今日主线

今天的共同信号是：Agent 的竞争正从单次任务能力转向长期经验是否真正可复用、能否主动发现目标，以及运行过程能否被系统级验证。与此同时，自动驾驶研究也在用分层中间状态约束长时决策；商业侧则把原本封闭的早期资产包装成可交易产品，但“更易获得”并不自动等于“更透明、更低风险”。
