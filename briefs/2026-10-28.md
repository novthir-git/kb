### 1. 把 harness 从代码搬进机械臂：EBench 让"直接控制"和"调用策略"正面对决

- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / v1 于 2026-10-26 17:51:02 UTC 上传，作者 Yifei Yao、Yude Zou、Guanbo Jiao 等
  15 人；综合：论文配套项目页出现 Shanghai AI Lab 与 InternRobotics 的机构 logo，暗示作者机构归属，但
  论文页面本身未列出机构名，故不作为确证事实陈述
- 摘要：EBench 是基于 GenManip 与 Isaac Sim 搭建的诊断型仿真基准，用 ARX Lift 2 双臂移动机器人，覆盖
  家居/零售/工业 9 类场景共 26 个任务（按移动性分 19 移动/7 桌面，按操作精度分 14 低/8 中/4 高，按时间
  跨度分 11 短程/15 长程），另设 Background/Object/Instruction/Mix 四个泛化维度，共 510 个测试回合。
  论文用 OpenAI 的 GPT-6-Astra 作为智能体核心，对比两种配置：**直接控制**（agent 直接从 RGB 图像与本体
  感知状态输出末端执行器与底盘路点指令）与**调用策略的 harness**（agent 可额外调用后训练好的
  VLA/WAM 专用策略——π0.5、InternW0-Δ 等——来执行动作）。结果：直接控制整体成功率 46.7%（分数
  0.654），短程任务上反而排名第一（73.2%），但长程任务（27.3%）、桌面任务（20.0%）、高精度任务
  （11.3%）明显偏弱；"harness + InternW0-Δ"把整体成功率拉到 56.0%（分数 0.744），超过被调用策略单独
  使用时的表现（InternW0-Δ 单独为 49.2%），且逐回合对比显示净增益（96 回合由败转胜 vs 49 回合由胜转
  败）；token 成本上，不成功回合平均耗费约 545 万 token/55.9 次调用，成功回合仅约 184 万 token/27.4 次
  调用，论文称 harness 配置下"每次成功的 token 成本降幅超过一半"（具体数字在正文未展开的附录中）。
- 为何重要：这是本仓库持续追踪的"Harness 不是轻量 Wrapper"这条线索（对应已有页
  `wiki/concepts/harness-vs-model.md`，此前已累计 21 条候选证据，均因用户尚未批准而未合并）第一次把
  战场从编码/计算机使用类 agent 搬到具身机器人操作——此前所有证据（组件消融、排名随模型/基准漂移、
  行业 CEO 表态等）都在"软件执行环境"内打转，这篇论文证明同一个"模型能力 vs 执行环境设计"的权衡在
  机械臂操作上同样成立，且给出了具体的互补模式：直接控制在短程任务上已经够用、甚至优于专用策略，
  长程/高精度任务则需要把执行权移交给后训练过的专用策略，调用时机与方式本身就是需要设计的 harness
  决策。证据边界：每个任务仅一条标注示范（single-shot ICL），作者自陈"无法完全体现测试时的分布偏移"；
  大多数任务 20 回合、两个任务仅 15 回合，四个高精度任务样本量很小；无深度图、无标定、无真值位姿，
  且 agent 不知道步数预算；token 用量、工具调用次数、推理时间均未设限；harness 配置下 agent 调用策略
  后往往无法维持抓取状态，是观察到的主要失效模式之一；直接控制还观察到脱手、越界、腕部快速运动等
  安全问题，作者明确提示这些需要在真实部署前解决；复合实验（agent 规划+机器人执行）仅做了 10 次试跑
  的小规模试点；论文作者自陈这是"刻画能力边界"而非对前沿多模态 agent 的普遍性结论；预印本未披露投稿
  状态，暂无第三方复现。
- 原文：[Profiling a Frontier Agent with EBench: From Direct Control to Harness with Policy](https://arxiv.org/abs/2610.35832)；项目页：[EBench-Astra-Tech-Report](https://internrobotics.github.io/EBench-Astra-Tech-Report/)

### 2. 删掉 agent 的旧记忆能省钱吗？42 种配置测下来，答案是 0/42

- 领域：软件工程
- 来源 / 发布日期：arXiv / v1 于 2026-10-26 14:25:17 UTC 上传，作者 Fernando Vallecillos-Ruiz、
  Islem Bouzenia、Michael Pradel、Leon Moonen（机构未披露）
- 摘要：Coding agent 每一轮都要把完整历史轨迹重新发给 LLM，直觉上删掉旧轮次的部分内容能省 token、省钱。
  论文在 Mini-SWE-agent（仅 shell 工具）与 Trae agent（文件查看器+编辑器+shell）两款 agent 上、统一用
  自托管的 DeepSeek-V4-Flash（温度 0，200 轮上限），在 100 个 SWE-bench Verified 任务上跑了 42 种删除
  配置（按范围：推理文本/工具输出/两者都删；按粒度：整轮删除或逐 token 随机删；按比例：整轮删除
  25/50/75/100%、逐 token 删除 25/50/75%；按时机：延迟两轮删除或立即删除），共 9,400 次运行。
  **有效性**：延迟删除下，42 项里 37 项任务解决数无统计显著下降，但立即删除下 19 项显著下降——时机是
  关键变量；**代偿行为**：被删内容会被重新获取，Trae agent 在"两者都删、整轮删除、100%"配置下重新
  获取比例达基线的 7.5 倍；**成本**（这是论文的核心反转）：在假设"按最长相同前缀计价"的、更贴近真实
  按量计费（caching-aware pricing）场景下，42 种配置里**没有一种比不删除更便宜**，26 种反而显著更贵
  （最差情形约为基线 5 倍）；而如果只看表面 token 计数（flat pricing，不考虑缓存计价），42 种里倒有 26
  种看起来更便宜——这正是论文标题"隐藏成本"的来源：删除会打断被缓存的公共前缀，导致本该按缓存价
  （基线的 1/10）计费的内容被重新按全价计费。
- 为何重要：这是本仓库持续追踪的"Agent 记忆系统的检索/重构环节可能是当前主要瓶颈"这条线索（对应已有页
  `wiki/concepts/Agent 记忆架构.md`，此前已有 VibeMemBench「记忆系统实践效果存疑」、Persistent Memory
  in Multi-Agent LLM Inference「常见消融实验测的是假象」两条独立证据）第三条独立证据，**首次正式跨过
  "≥3 条跨天证据"的沉淀门槛**。它给这条线索补上一个此前两条证据都没有触及的具体机制：即便某种记忆/
  上下文裁剪策略在"任务是否解决"这个指标上看起来无害甚至在 token 计数上更省，一旦放进真实生产计费
  体系（几乎所有大厂 API 定价都对缓存前缀打折），结果可能是系统性更贵而非更省——这意味着"要不要裁剪
  记忆"这个问题，光看效果指标和表面 token 数都不够，必须联立计价模型一起评估，否则很容易得出完全相反
  的结论。证据边界：仅覆盖一个开源权重模型（DeepSeek-V4-Flash）与两款 agent，任务范围是 SWE-bench
  Verified 的 100 题子集；公开仓库与已知修复可能被模型记忆过，存在数据泄漏可能；只测试随机删除，未测试
  基于学习的选择性删除或摘要压缩；每种配置每道题仅跑一次、一次随机抽样，置信区间只反映任务抽样的不
  确定性；caching-aware 计价模型本身省略了缓存写入溢价、最小前缀长度与缓存淘汰，作者称这是成本的
  "下界"而非精确值；重新获取的判定标准（≥80% 行重合）在 50%/90% 阈值下做过敏感性检验，具体比例会变但
  结论方向不变；论文未披露投稿状态，暂无第三方复现。
- 原文：[The Hidden Costs of Forgetting: A Study of Trajectory Deletion in Software Engineering Agents](https://arxiv.org/abs/2610.35496)

### 3. IPO 之后，Anthropic 到底谁说了算？一份监管文件拆出的治理迷宫

- 领域：创业 / 商业

- 摘要：文章以 Anthropic 的 S-1 披露与公开声明为基础，拆解这家公司递交 IPO 后复杂的治理结构。
  Anthropic 是一家"公益公司"（public benefit company），法律上允许董事会在股东价值之外权衡安全使命，
  不必担心单纯因安全决策而被股东起诉。董事会现由 Daniela Amodei（总裁）任主席，成员含 Dario Amodei

### 5. 计算复杂度的一块基石被动摇了？OpenAI 和 Anthropic 同一天都说推翻了指数时间假设（AI / 智能体，今日加选）

- 领域：AI / 智能体（今日加选，今日最值得细读）
- 来源 / 发布日期：TechCrunch（Tim Fernholz）/ 2026-10-27 10:08 PDT；核心技术细节另交叉核验
  thenextweb.com、aiweekly.co 等二级信源的报道，qz.com 对自动化抓取返回 403 未能直接核验、仅引用其
  标题与摘要级别信息；OpenAI 官方博客原文对自动化抓取返回 403，本条未能直接核验其原文全文
- 摘要：OpenAI 宣布其内部模型产出了数学、计算机科学、物理学三项结果，其中计算机科学一项声称推翻了
  "指数时间假设"（Exponential Time Hypothesis，ETH）——这是密码学与算法复杂度理论长期依赖的一条基础
  假设，认为对某类困难的逻辑难题（3-SAT），即便用已知最快的算法，所需时间也会随变量数指数增长。
  据报道，OpenAI 的模型给出的算法把 n 个变量的 3-SAT 求解时间压到约
  exp(n/(log n)^{1/2+o(1)})——这是"亚指数"量级，如果成立，意味着当前对 P 与 NP 之间鸿沟的理解需要
  修正，理论上也可能打开一条让某些问题"表现得像 P=NP"的路径。OpenAI 称已用 Lean（一种可机器核验的
  证明语言）核验了该结果，并把论文与 Lean 证明发布到 GitHub。MIT 计算复杂度学者 Ryan Williams（此前曾
  批评 OpenAI 此前一次证明发布是"对数学家的 DDOS 攻击"）与提出 ETH 的两位学者 Russell Impagliazzo、
  Ramamohan Paturi 一起组建工作组参与审核，三人明确声明"参与审核不代表认证该结果"；工作组要求 OpenAI
  公开原始数据并出资支持一场相关研究会议，OpenAI 已同意。据二级信源报道，Anthropic 数学家 Levent
  Alpöge 曾指出 OpenAI 的解法建立在已有工作之上，数小时后 Anthropic 自己也在 GitHub 发布了一份独立的
  ETH 推翻方案——目前未见进一步交叉信源证实这一后续细节，按未独立核实处理。三项结果中的物理学结果
  （量子色动力学/纯 Yang-Mills 理论的存在性证明）目前仍被监督该领域的物理学家小组要求暂不公开其 AI
  产出的具体内容。Williams 被问及这是否会威胁依赖特定密钥长度的密码系统时，转述 OpenAI 的回应是
  "已经检查过，相当有信心没有密码系统被攻破"；Williams 本人认为应该提高"P=NP 确有可能"这一判断的权重，
  但强调 OpenAI 给出的算法大概率不是最优解，这也大概率不是这个问题的最终答案。

## 今日主线

今天 5 条的共同落点，是"设计一个系统的边界在哪"这件事在不同层面反复出现，而且越来越能被量化。条目 1
（EBench）把"直接控制 vs 调用 harness 策略"这道题从代码世界搬进机械臂，证明同一种权衡在具身智能体上
依然成立——模型能力和执行环境设计仍然是两个独立变量。条目 2（Hidden Costs of Forgetting）则从一个
看似无害的优化（删点旧记忆省 token）里挖出一个只有联立计价模型才能看见的陷阱：42 种配置无一例外在
真实缓存计费下更贵，说明"效果没掉"和"真的省钱"完全是两件事，必须一起测。条目 3（Anthropic 治理结构）
把"边界设计"从技术系统搬到公司治理——信托、特殊股权、日落条款，是目前最具体的一份"把安全使命嵌进
公司结构而不只是嵌进使命宣言"的制度文本。条目 4（Re:Build/Slate Auto）代表的是另一种边界突破：不靠
算法而是靠真金白银，赌能不能把整车制造业重新搬回美国。条目 5 则是一个提醒——有些边界动摇发生在完全
不同的尺度上：一条计算复杂度理论的基石假设，可能在一天之内被两家实验室分别宣布推翻，而审核它需要的
时间会以年计，不会以天计。
