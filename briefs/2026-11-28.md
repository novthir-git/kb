### 1. TASK Memory：检索明明给对了记忆，agent 为什么还会用错——给"文字记忆"焊上激活转向与知识编辑
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / 2026-11-25（v1 于 UTC 17:30:37 上传），Jinkun Zhao 等（第二作者姓名页面未完整显示；机构未披露）
- 摘要：论文关注一种此前较少被单独量化的失效——即使检索环节完全正确、把对的记忆原文放进了 prompt，模型在"使用"这段记忆时仍可能出错。作者在五个开源模型上把这类"用时记忆幻觉"拆成三种具体子型：Memory-ignoring（模型转而依赖权重里过时的事实，最高达 46% 的查询）；Memory-misapplying（把记忆错误地归到不相关实体上，最高 24%，叠加知识编辑后升到 49%）；Version confusion（新旧两版事实同时存在时，53% 的回答仍给出已被取代的旧值）。为此提出 TASK memory：用一段文字记忆承载内容，配一个可随时移除的知识编辑提供"地址"（通过主语键支持多跳组合），再用一对转向向量按每次查询动态决定模型该用记忆还是用自己的答案——这对转向向量本身不携带任何内容。在预先注册、只测一次的协议下，十个"模型×数据集"组合里 Memory-ignoring 幻觉全部降到 1.5% 以内；CounterFact 上邻近实体误用从 39.2% 降到 7.5%；300 条记忆规模下比 BM25 RAG 高 16.4 个百分点，扩到 3000 条记忆优势仍保持；在无需事实 ID 的前提下处理事实修订，并在 MQuAKE 上多跳准确率提升 7.5 个百分点；跨 8B–27B 参数、四个模型家族的 23 组跨模型比较中 21 组统计显著；在 10 个"模型×数据集"组合中的 9 个上优于三种近期的上下文转向方法。
- 为何重要：本仓库线索 31（"Agent 记忆系统的'检索/重构'环节可能是当前主要瓶颈，而非'要不要有记忆'本身"）此前已累积 4 条候选证据（VibeMemBench、Persistent Memory 消融、Hidden Costs of Forgetting、How Much Should an Agent Remember），全部聚焦"该存什么记忆、怎么检索、怎么裁剪"这一层。本文补上第 5 个独立角度：把问题从"存储与检索层"下沉到"模型拿到正确记忆之后到底怎么用"这一此前很少被单独量化的环节，并首次给出一个不靠额外内容、只靠运行时转向机制来决定"信记忆还是信自己"的具体控制手段。对应 `wiki/purpose.md` 关键问题 4（agent 需要什么样的知识—记忆—行动架构）。
- 证据边界：论文页面只完整显示第一作者姓名，第二作者姓名未能确认，机构全程未披露；全部实验基于冻结模型与预先注册的"只测一次"协议，具体五个开源模型的身份、参数规模细节未在摘要给出；CounterFact/MQuAKE 均为学术构造数据集，是否能代表真实生产场景的记忆分布未讨论；知识编辑组件"可移除"特性在多次连续编辑后的长期稳定性未涉及；预印本，无第三方复现。
- 原文：[TASK Memory: Beyond Text-Only Memory with Activation Steering and Knowledge Editing against Memory Hallucination](https://arxiv.org/abs/2611.34762)（检索于 2026-11-27）

### 2. Evaluating More with Less：不用看模型内部，SWE-bench Verified 一次评测费从 225 美元砍到 47 美元还几乎不掉准
- 领域：软件工程
- 来源 / 发布日期：arXiv / 2026-11-25（v1 于 UTC 16:05:46 上传），Ali Asgari、Mitchell Olsthoorn、Arie van Deursen、Annibale Panichella（机构未披露）
- 摘要：论文称这是第一个针对"agentic 软件系统"的黑盒测试用例选择实证研究——每当模型、prompt、工具或环境变化，agent 基准就要重新跑一遍，而商用 agent 往往连内部状态都看不到。作者把每个基准任务当作一条"测试用例"，将回归测试里常见的黑盒选择技术（按任务描述、元数据、代码片段或向量嵌入分组挑选）搬过来，并额外提出两种估计任务难度的方式：启发式特征打分，以及独立的 LLM-as-judge 评估；所有策略都不需要先跑一遍目标 agent 或依赖历史跑分结果。作者在 10 个 AI agent 基准（每个基准覆盖 12 到 101 个 agent）上比较了 14 种策略，分别针对两个不同目标：估计 Success Rate、尽早抓到失败案例——结果没有一种策略能同时在两个目标上都最优。改造自回归测试的黑盒方法在估计 Success Rate 上最准，其中 Category Partition 方法在 20% 任务预算下，于五个基准上取得最低的估计误差中位数；LLM-as-judge 选择法则更擅长尽早发现失败。具体到 SWE-bench Verified 配 GPT 5.2 Codex 的场景：Category Partition 只用 100 条任务（而非全部 500 条）就把执行成本从 225 美元砍到 47 美元，估计误差仅 0.8 个百分点；同等预算下，LLM-as-judge 选中的任务里 53.0% 能暴露失败，接近随机抽样 27.4% 的两倍。
- 为何重要：本仓库已有「Evals（AI 系统评估）」页，此前积累的多条证据都在回答"基准/裁判本身能不能一次性冻结信任"这个问题，角度集中在评分是否失真、裁判有没有偏差。本文补上一个此前缺失的具体操作维度：当 agent 是黑盒（看不到内部状态，常见于商用 API）时，该怎么在可控的成本和误差之间选评测子集，并且明确拆开"估计整体成功率"和"尽快抓到失败"是两个需要不同策略的独立目标——这是一条可以直接追加到该页、而不需要新建页面的具体方法论证据。对应 `wiki/purpose.md` 关键问题 5（如何用 evals 与反馈闭环驱动工程与产品演化）。
- 证据边界：10 个基准、14 种策略的具体基准/agent 名单及入选标准未在摘要展开；"Category Partition 在五个基准上误差最低"具体是哪五个、在其余基准上表现如何未全列；LLM-as-judge 所用的具体裁判模型未披露，裁判自身可能存在的评判偏差（本仓库线索 8 已反复记录"裁判不可全信"）是否会系统性扭曲任务难度估计，本文未讨论；机构未披露；预印本，无第三方复现。

### 4. Recoverability Policy Editing：不重训、不学风险场，只在"回得去的危险区"局部改策略，闭环安全事故砍掉近一半
- 领域：汽车 / 自动驾驶
- 来源 / 发布日期：arXiv / 2026-11-25（v1 于 UTC 14:01:37 上传），Yang Guan、Shengbo Eben Li（机构未披露）
- 摘要：论文针对神经网络端到端自动驾驶策略缺乏安全保证这一问题，提出一种状态级的策略编辑方法：在尽量保留原策略已有驾驶能力的前提下，让车辆在"可恢复的扰动"下保持无碰撞。作者定义"策略可恢复性"（policy recoverability）——车辆能否在有限时间内回到原策略的可行集合内；方法先找出在原策略下长期不安全、但仍属可恢复的状态子集，只在这些状态内编辑策略的输出；车辆一旦进入该区域就被纠正动作，一旦恢复就交还给原策略继续运行。在 nuPlan 城市驾驶场景的闭环仿真中，该方法据作者报告相对原策略把安全事故降低了 48%，同时较大程度保留了原有驾驶表现。
- 为何重要：本仓库线索 22（"端到端自动驾驶安全场设计：从写死规则转向可学习/自适应表示"，候选 2 条）和线索 67（"用近专家失败轨迹做排斥锚点的安全后训练"，候选 2 条）都在回答"怎么让已训练好的驾驶模型更安全"，但走的是两条不同路径——线索 22 改变风险的表示方式本身，线索 67 在训练阶段注入负样本。本文提供第三条独立机制：完全不改变风险表示、也不动训练阶段，而是在部署后找出"长期不安全但仍可恢复"这一可形式化定义的具体状态子集，只在这些状态局部编辑策略输出。这给"训练后安全加固"这一更大问题补上一个新的技术维度（推理期局部策略编辑），但机制与线索 22、67 均不同，暂不强行合并，继续观察是否有第三方复现，或是否出现把三条路径放在同一基准下做消融对比的后续工作。对应 `wiki/purpose.md` 关键问题 1（agent/自动化系统落地生产要跨哪些具体门槛——此处为自动驾驶的安全性门槛）。

### 5. Do We Still Need Reinforcement Learning When We Can Read the World Model？：让 Agent 直接读环境源码当世界模型，用远少的经验打平甚至超过 RL（今日最值得细读）
- 领域：AI / 智能体（第二条，今日最值得细读）
- 来源 / 发布日期：arXiv / 2026-11-25（v1 于 UTC 16:29:37 上传），Mingchao Zhang、Miduo Cui、Kangze He 等 13 位作者（机构未披露）
- 摘要：论文探讨基于模型的强化学习（model-based RL）的一种替代方案——model-based RL 依赖学出来的世界模型做规划或策略优化，但仍需要大量交互经验。作者转而研究让基于 LLM 的 coding agent 直接读取环境的源代码本身——把这段代码当成一份天然可读的世界模型，再把读到的知识转译成可执行的决策规则，并用在线反馈或离线数据对规则做迭代修正，全程不做任务特定的 RL 训练。在多组不同的决策类基准上，作者报告这种"策略综合"方法用远少于传统 RL 所需的经验量，就能达到与之相当或更好的表现；进一步分析展示了可解释的决策规则本身及其随反馈演化的过程；与"不给源码访问权限"的对照组相比，以及在更困难条件下的测试，均被作者用来说明"可读的世界模型"确有实际帮助。作者据此得出结论：直接做策略综合可以减少对试错的依赖，这对"任务特定的 RL 训练是必要的"这一普遍假设构成挑战。
- 为何重要：这是一个相当有冲击力的反直觉主张——不是用更好的 RL 算法或更精确的学出来的世界模型去逼近环境，而是直接把环境源码本身当成 100% 准确、无需学习的世界模型，让 agent"读代码生成策略"取代"在环境里试错学习策略"。如果这个结论能被独立复现，它会为 `wiki/purpose.md` 关键问题 4（agent 需要什么样的知识—记忆—行动架构）给出一个具体且可操作的方向：在环境源码可读的场景下，"读代码直接编译决策规则"可能比"从零试错训练"更划算。这与本仓库此前反复出现的"确定性机制优于单纯信任模型判断"方向（线索 3、45、64）相通，但角度是第一次出现——不是用确定性机制去约束或核验 agent 的行为，而是把环境本身的确定性源码当成 agent 决策的知识来源，用来替代试错式学习。单篇论文、机构未披露，暂不提议沉淀，继续观察是否有独立团队复现或扩展到源码不可读的场景对照。
- 证据边界：13 位作者均未披露所属机构；"match or outperform conventional RL"所涉具体基准列表、对照的 RL 算法选型、是否存在"为 coding agent 量身定制"的基准选择偏差，摘要均未展开；方法的前提是"环境源码可读且可被 agent 访问"，不适用于黑盒环境、无源码的真实生产系统或物理世界场景，这一适用范围限制本身在摘要中未被充分讨论；"随反馈演化的可解释决策规则"在长期迭代中是否存在不稳定或震荡未知；预印本，无第三方复现。
- 原文：[Do We Still Need Reinforcement Learning When We Can Read the World Model?](https://arxiv.org/abs/2611.34656)（检索于 2026-11-27）

这 5 条共同指向同一个转变：当系统复杂到无法整体信任时，"判断"正在从"这个东西整体靠不靠谱"下沉为"哪个具体环节、哪个具体状态可以被单独核查或局部修正"。TASK Memory 不再问"记忆系统整体好不好用"，而是精确定位到"检索对了之后、模型使用记忆这一步"单独出了什么问题，并用不携带内容的转向向量局部控制。Evaluating More with Less 不再要求整套基准全量跑分才算可信，而是用可核算成本与误差的子集选择，把"评测靠不靠谱"拆成"估计准不准"和"抓失败快不快"两个要分别优化的具体目标。Recoverability Policy Editing 不再对整条驾驶策略做安全性断言，而是先形式化定义出"长期不安全但仍可恢复"这一具体状态子集，只在那里局部编辑。Do We Still Need RL 把"agent 怎么学会决策"的信任来源，从反复试错换成一份可直接读取、确定无误的源码。Nvidia 的出口管制执行同样如此——不是靠"谁被列入黑名单"这种整体判断，而是下沉到"这块芯片物理上放在哪、谁能摸到它"这一可核查的具体环节。五条证据分别来自记忆、评测、自动驾驶安全、agent 决策架构与出口管制五个不相关的领域，却在同一个方向上收敛。
