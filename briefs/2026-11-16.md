### 1. Anthropic 官方拆解"常驻 Agent"该怎么架构：五个原语，而非一个更强的模型
- 领域：AI / 智能体
- 来源 / 发布日期：Claude 官方博客（Best practices，作者 William Hu）/ 2026-11-13
- 摘要：文章把"常驻 agent"（在无人直接监督下跨会话管理上下文、自主行动的 agent）与普通 agent 的区别，归结为同一个核心循环之外的一层架构原语，而非模型本身的差异：① **事件收件箱**——webhook、定时任务、用户消息统一进一个持久队列，由单一 worker 顺序处理，避免并发 run 互相竞争或事件丢失；② **计时器**——agent 给自己设置的后续跟进与周期性任务，与事件队列分开存储，由调度器轮询后再把到期事件投回收件箱；③ **记忆**——用户指令、笔记、消息历史与任务进度的持久存储，让 agent 跨多次 run 保持连续性；④ **权限**——凭证代理、auto-mode 分类器与"需用户批准才继续"的延迟工具调用；⑤ **发件箱**——run 的产出交付给用户的通道（因为后台工作不能像交互式会话那样逐步流式呈现），文章建议"先安静、再逐步赢得用户关注"。另建议保持上下文窗口固定开销精简并善用 prompt caching，并用 evals 来调校"该多频繁打扰用户"。
- 为何重要：这把"agent 可靠性"问题从"模型能不能做对任务"进一步下沉到"围绕模型的系统该长什么样"——与本仓库已记录的"harness 设计是决定同模型实际表现的独立架构变量"这条判断同属一个方向，但这次的对象是"持续运行、无人盯着"的场景，提出的是可执行、可复用的具体原语清单，而非又一组实验对比数据。证据边界：这是 Anthropic 官方最佳实践文章而非受控实验，没有给出采用这五个原语前后的量化对比（如事故率、人工介入率变化）；内容基于 Anthropic 自己构建 Claude 相关产品的经验，各原语的必要性未经外部团队独立验证；文章未讨论这套架构在非 Claude 平台上的可迁移性。
- 原文：[Building always-on agents（Claude 官方博客）](https://claude.com/blog/building-always-on-agents)（检索于 2026-11-16）

### 2. "AI slop" PR 现象首次被开源维护者视角量化：多数无人给理由就被关闭
- 领域：软件工程
- 来源 / 发布日期：arXiv（cs.SE）/ 2026-11-13（v1 于 2026-11-11 UTC 上传）
- 摘要：作者首次聚焦"被维护者明确标记为 slop 的 PR"这一子集（此前研究多从理论、平台或泛化开发者视角切入，未落到具体项目层面），对真实开源项目中的低质量、低价值 GenAI 生成 PR 做混合方法研究：追溯来源、测量规模、刻画特征、分析维护者标记或关闭的理由。核心发现：此类 PR 数量从 2025 年中开始上升，2026 年 5 月见顶；多为"只加不改"的增量式修改，很少被合并，通常 3 天内被关闭；仅 14% 的作者主动披露使用了 AI，其中 1% 是被维护者问起后才披露；多数 PR 被关闭或标记为 slop 时，维护者没有给出任何理由；给出理由的案例里，跨度从具体的"build 失败"到主观的"一看就是 AI 写的"都有。作者明确将本研究定性为探索性、捕捉一个早期阶段现象。
- 为何重要：这是本仓库已记录的"AI 编码提高产出、但维护负担与返工同步上升"这条判断（见 [[生产力-体验悖论]]、Xu et al. 的 37,334 名贡献者 DiD 研究）在"开源维护者要花多少精力过滤垂圾 PR"这一具体子维度上的首个量化刻画——此前该线索停留在"返工变多"的宏观统计，这次给出了具体的时间曲线（2026-05 见顶）、关闭速度（3 天内）与披露率（14%）。证据边界：作者机构未在摘要页列出；研究样本是"被维护者标记为 slop"的 PR，天然依赖维护者主观判断、存在标记不一致和漏标的可能；"2026 年 5 月见顶"是否已经回落或仍在上升未说明；探索性研究，未做因果推断。
- 原文：[An Empirical Study of Maintainer-Identified AI Slop Pull Requests in Free and Open Source Software Projects](https://arxiv.org/abs/2611.15159)（检索于 2026-11-16）

### 3. 用海洋温差发电驱动浮动数据中心：一家六个月的初创公司拿到 2000 万美元
- 领域：创业 / 商业
- 来源 / 发布日期：TechCrunch（Tim De Chant）/ 2026-11-13
- 摘要：成立约六个月的华盛顿 D.C. 初创公司 Drogue（创始人 Sam Sipe，前美国海军 E-2D 鹰眼预警机飞行员）向 TechCrunch 独家披露完成 2000 万美元融资，投资方包括 XYZ Venture Capital、Toyota Ventures、Tamarack Global、Dream、FDVC、Garuda Ventures、Flexcap、Boost VC、Slow Ventures 等（轮次与估值均未披露）。技术路线是海洋温差发电（OTEC，1950 年代即有原理）搭载在船体上：数据中心用海洋表层暖水降温，暖水再用于把氨煮沸驱动涡轮发电，约 1000 米深处抽取的约 4°C 冷水把氨重新冷凝为液体，循环往复——本质是反向运行的热泵。首个原型为多兆瓦级、装载在常规远洋船上，计划 2028 年初下海；后续版本会改用类似海上石油平台的浮动结构，单船设计寿命约十年。公司已从美国船级社（ABS）拿到"原则性批准"（预备性认可，非最终认证），并在采购第一艘船。创始人称 OTEC 在 1980 年代测试后被放弃，这次复兴归因于管道与热交换器制造工艺的进步，但文章未给出支撑这一说法的具体证据。

### 5. Singularity-Bench：Claude Opus 5.5 + Claude Code 在"从零搭建 AI 研发全栈"任务上追平甚至超过人类基线
- 领域：AI / 智能体（今日最值得细读）
- 来源 / 发布日期：arXiv（cs.AI）/ 2026-11-13（v1 于 2026-11-12 UTC 上传）
- 摘要：19 位作者（含多家机构，论文摘要页未列出具体隶属）提出 Singularity-Bench，一个面向"自主 AI 研发"的开放式基准：六个端到端任务覆盖预训练、中训练、后训练、推理、agent harness 与集群编排，agent 需要从极简起点独立搭建核心系统，并在相同硬件上与成熟的人工工程基线对比打分。11 个 agent（来自 7 个前沿模型 × 2 种 harness）参与测评：Claude Opus 5.5 搭配 Claude Code 拿到"Singularity-Index"1.25，在全部六项任务上追平或超过人类基线；其余 agent 平均分仅 0.58。作者同时针对 Agentic 应用的 OWASP Top 10 做红队测试（覆盖其中 9 类），在 Harbor 框架中发现 reward-hacking 漏洞，并构建 Harbor 扩展 Breakwater 挡住了测试中的全部攻击。作者据此提出"agent 可能正在接近能够端到端负责构建更强继任者"这一前瞻判断，但明确将其表述为愿景而非已证实的结论。
- 为何重要：这是"agent 自主构建 AI 系统本身"这条能力边界的一次具体量化尝试，而不是又一个任务型 coding benchmark——六项任务直指 AI 研发基础设施本身（训练、推理、harness、集群），且首次把"安全红队测试+防御"作为基准的内生组成部分而非事后补丁。但这是单一基准首次发布，分数差距（1.25 vs 0.58）由作者自定义的 Singularity-Index 计算得出，其构造方式、是否存在对特定模型家族的隐性偏好尚无法独立评估。证据边界：论文作者自建基准、自选评测维度，尚无第三方复现或同行评审确认；"Singularity-Index"的具体计算公式与归一化方式未在摘要页给出，无法判断该指标本身是否稳健；红队测试仅覆盖 OWASP Top 10 中的 9 类，另 1 类未覆盖的原因未说明；"追平人类基线"是在六个预定义任务上，能否推广到任意 AI 研发场景未知。
- 原文：[Singularity-Bench: Can Agents Build Agents?](https://arxiv.org/abs/2611.16591)（检索于 2026-11-16）

## 今日主线

今天的五条拼出同一张图的两面。AI/智能体两条（常驻 agent 架构原语、Singularity-Bench）共同指向一个方向：agent 被设计/评测的目标正在从"完成一次性任务"转向"持续自主运行"甚至"自己搭建下一代 AI 基础设施"。但另外三条——软件工程里维护者被低质量 AI PR 淹没却说不清理由、自动驾驶里中国公司被迫为芯片供应准备 Plan B、创业/商业里一家初创还在用未建成的原型船解决电力瓶颈——都在说同一件事：自主性在往上走，但承接它的人力审核带宽、芯片供应链、物理电力基础设施这些约束条件，没有一个随之同步变强。这也呼应了 Jensen Huang 辞任这一上周已记录的事件如何继续产生下游影响：从创投资金流动，延伸到了具体国家/行业的硬件依赖风险。
