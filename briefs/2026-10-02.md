### 1. Approval Laundering：审批记录里"已批准的动作"和"实际执行的动作"可以被系统性地悄悄替换
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / 2026-10-01（v1 于 2026-09-30 UTC 上传）
- 摘要：论文指出，Claude Code、Codex CLI、Cursor 等主流 coding-agent harness 的安全边界都隐含一个未被检验
  的假设——人类批准的动作 A 与 harness 最终执行的动作 A′ 是同一个。作者提出 Approval Laundering 分类法，
  归纳出 Scope（范围）、Argument（参数）、Temporal（时序）、Tool（工具）、Delegation（委托）、Semantic
  （语义）六类"批准后被悄悄替换"的失效模式，并在 Claude Code 的 PreToolUse 预执行调解点上做受控、无头、
  重复测量研究（每类 N=19-20 次运行，报告 Wilson 置信区间，评审者间一致性 κ=1.0）。作者进一步做了一个
  "Approval Token"原型——由中介方签发、密钥从不返回给 agent 的能力令牌，用 118 次配对前后重放做 McNemar
  精确检验：该令牌完全消除了 Delegation 类与（针对本文构造的会话身份错配场景的）Temporal 类替换，但对
  Scope 类毫无影响、对 Argument 类也没有显著降低（p=1）——作者坦承这是"诚实的负结果"，因为这两类替换不
  改变任何被记录下来的调度字段，发生在字段级验证器根本看不到的进程层级之下。
- 为何重要：这把"审批是否可信"从抽象的权限模型问题精确到"哪些具体字段能被看到、哪些字段级验证器天生看
  不到"这一可操作判据，并罕见地主动报告了方案的失败边界而非只展示成功案例。证据边界：论文单一作者、未
  披露机构归属与投稿/评审状态；受控实验仅覆盖 Claude Code 一款 harness 的 PreToolUse 钩子，每类仅
  19-20 次运行，样本量小；未见第三方复现。**综合**：与 2026-09-25 已沉淀线索中收录的同名概念论文《Agent
  Approval Laundering》（arXiv 2609.28586，中科院信息工程研究所等）研究对象不同——那篇聚焦"审批记录的
  传递性效应覆盖率"（授权前预测效应边界），本文聚焦"已批准动作与实际派发动作的逐字段一致性"（执行后核
  验绑定完整性），二者互补而非重复。
- 原文：[Approval Laundering 论文](https://arxiv.org/abs/2609.38983)

### 2. Aletheia：把"用户真正授权的值"和"规则文件里可能夹带的指令"分开测，专治 AGENTS.md 类规则文件的权限越界
- 领域：软件工程
- 来源 / 发布日期：arXiv / 2026-10-01（v1 于 2026-09-30 UTC 上传，香港理工大学 Jieke Shi、Yuchen Chen、
  Junda He、Yue Liu 与新加坡管理大学 David Lo）
- 摘要：仓库里的指令文件（如 AGENTS.md、CLAUDE.md 类规则文件）用于指导 coding agent，但也可能被提示注入
  利用——恶意规则可以在 agent 产出正确补丁的同时，夹带访问凭证或转移数据的额外指令。Aletheia 把一条规则
  请求的权限翻译成带类型的语言，自动合成可执行的沙箱配置：同一条规则与任务分别在完整权限下、以及逐次去掉
  单个权限的独立受限条件下运行；如果去掉某权限后功能测试依然全部通过，就得到一个"可免除"证据，再结合任务
  上下文判断该权限请求是否可疑。在一个共享重构任务上，Aletheia 对全部 314 个 AIShellJack 攻击输入均成功
  执行并检测出来，对 5 个良性模板零误报；在 80 条人工核验过的良性 GHAgentFiles 规则上，产生 3 个误报
  （3.75%）。
- 为何重要：这是本仓库长期追踪的"agent 工具执行运行时授权治理"线索里，第一次把检验对象从"运行时工具调用"
  下沉到"规则文件本身请求的权限"这一更早的环节——与此前聚焦调用边界的方案（SARA/CapScope/ToolFence 等）
  互补而非重叠，恰好对应越来越多 coding agent 依赖的 AGENTS.md/CLAUDE.md 类仓库规则文件这一新攻击面。
  证据边界：评测语料（314 个攻击输入、80 条良性规则）均为作者自建/收集，尚无第三方复现；3.75% 的误报率
  建立在 80 条规则的小样本上，更大规则库上的表现未知；该方法只验证"去掉某权限后功能测试仍通过"这一个维度，
  对隐蔽触发、延迟生效式的恶意规则是否有效未讨论；论文仅 6 页，未披露投稿状态。
- 原文：[Aletheia 论文](https://arxiv.org/abs/2609.39678)
- 配图：![Aletheia 的权限最小化测试框架](https://arxiv.org/html/2609.39678v1/architecture.svg)
  图片来源：[论文 Figure 1](https://arxiv.org/html/2609.39678v1)。

### 3. General Intuition 以 62 亿美元估值融资 2.2 亿美元：靠游戏录像训练"动作模型"
- 领域：创业 / 商业
- 来源 / 发布日期：SiliconANGLE / 2026-09-29（经 Dealroom 等多家报道交叉核实）
- 摘要：世界模型初创公司 General Intuition 完成 2.2 亿美元融资，估值达 62 亿美元，投资方包括 Valor Equity
  Partners、Atreides、Seven Seven Six、Point72、Khosla Ventures 与 General Catalyst。公司一年前从游戏

  依赖的静态文本/图像在结构上不同。其模型 MIRA 有 56 亿参数，能在单张 B200 显卡上以 20 帧/秒、720×576

### 4. Minneapolis 市议会表决机器人出租车监管条例：强制配备人类安全员，Waymo 称"管太宽"
- 领域：汽车 / 自动驾驶
- 来源 / 发布日期：MPR News（明尼苏达公共广播）/ 2026-10-01
- 摘要：Minneapolis 市议会以 7 比 6 的票数通过一项针对自动驾驶网约车的条例，要求车内配备持有有效驾照、
  收入不低于最低工资的人类安全员；该条例要到 2027 年 10 月才会生效。市长 Jacob Frey 已表态将予以否决，
  称"要求无人驾驶汽车里必须有司机说不通"，并将条例定性为对自动驾驶的"变相禁令"；7 比 6 的票数不足以在
  市长否决后被推翻。Waymo 此前已在双子城（Twin Cities）配人类安全员试运营，尚未对公众开放载客，此前曾
  表态该条例"管得太宽"，会限制其在当地的运营能力，具体上线时间仍不明确。
- 为何重要：这是继此前已收录的 NHTSA 对 Tesla Cybercab 联邦层面立案调查之后，这条"自动驾驶技术路线与
  监管后果"线索第一次出现**市级**议会主动立法强制配备人类安全员的案例，且表决结果本身（7:6，不足以推翻
  市长否决）说明地方层面对"是否该管、管多严"仍存在实质分歧，而非一边倒的监管收紧。证据边界：条例要到
  2027 年 10 月才生效，期间仍可能被否决或修订，不构成已落地的既成事实；Waymo"管太宽"的表态为此前立场
  转述，本次报道未附最新回应；州级层面的相关立法此前已失败，州与市两级监管口径是否统一仍不明朗。
- 原文：[Waymo robotaxi regulation up for Minneapolis City Council vote](https://mprnews.org/story/2026/10/01/waymo-robotaxi-regulation-up-for-minneapolis-city-council-vote)

### 5. 强模型 + 极简 harness，就能打平精心搭建的多 agent 编排——"harness 越精巧越好"再添一个反例（今日加选）
- 领域：AI / 智能体（Agent，今日加选）
- 来源 / 发布日期：arXiv / 2026-10-01（v1 于 2026-09-30 UTC 上传，作者含 EPFL 教授 Emmanuel Abbé）
- 摘要：近期自主机器学习工程（MLE）agent 在公开榜单上进展显著，常见做法是在强模型之上叠加多 agent 编排器、
  专职检索子 agent 等日益精巧的"机器"；本文研究的是相反方向——给 LLM 直接提供读/写/bash 原语的极简 harness
  是否同样有效，此前这一方向关注较少。在相同时间预算、相同前沿 LLM 底座下，作者通过大规模系统性消融实验
  发现：开源的 SOTA harness 相对于单会话、极简 harness 的 coding agent 基线并无优势，说明当前 MLE 基准上
  性能的主要驱动因素是模型底座本身，精心搭建的编排层在 coding agent 场景下很大程度上是冗余的。
- 为何重要：这条线索此前已有 LIMBO（09-24，"harness 影响需按具体维度分别验证，而非一概而论"）与 Beyond
  the Model（09-29，"harness 增益随模型能力增强系统性收缩"）两个限定条件，本文把这一收缩推到了一个更极端
  的具体场景（自主 MLE 任务）——在强模型加持下，复杂编排层的边际收益可能直接归零，而不只是收缩。证据边界：
  论文未披露投稿状态、无同行评审；"开源 SOTA harness"具体涵盖哪些产品名称及版本未在摘要中列出；结论建立在
  特定时间预算设定下，预算改变后结论是否成立未讨论；三位作者机构背景（Abbé 为 EPFL 教授）是否代表机构级
  持续研究方向未知。
- 原文：[How Much of a Harness Does a Strong Agent Need for Autonomous ML Engineering? 论文](https://arxiv.org/abs/2609.40303)
- 配图：![精简 harness 与精巧编排 harness 在相同时间预算下的对比](https://arxiv.org/html/2609.40303v1/headline-baselines.svg)
  图片来源：[论文 Figure 1](https://arxiv.org/html/2609.40303v1)。
