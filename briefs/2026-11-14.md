### 1. Sonar 2027 全球开发者调研：76% 的人写 AI 代码的速度已经超过自己核验的速度
- 领域：软件工程（今日最值得细读）
- 来源 / 发布日期：Sonar 新闻稿（PR Newswire）/ 2026-11-12
- 摘要：Sonar 调研 1,026 名全球开发者与工程管理者（未披露调研窗口与抽样方法），发现 AI 平均生成或大幅
  辅助了开发者提交代码的 65%；76% 的受访者承认"生成 AI 代码的速度已经超过自己核验的速度"；53% 的人
  如今审查代码花的时间超过写代码（采用 AI 工具前这一比例为 18%）。信任侧：94% 不完全信任 AI 生成的
  代码，但只有 39% 完全认同"AI 代码在提交前总会被检查"，仅 23% 的团队有明确的 AI 专属代码规范或自动
  化检查。37% 把"需求不清"列为头号返工来源，26% 把"修正/重写 AI 代码"列为头号返工来源。
- 为何重要：这是对已有判断的第 5 条独立证据——AI 把"写代码"的边际成本打到接近零之后，瓶颈转移到
  "评审/验证带宽"，与此前 GitHub 平台数据（PR 评审停留时长增加 441%）、团队级工业案例（15 天 C++ 整改、
  单人考试判分系统、30-agent 批量重写）共同指向同一方向。证据边界：Sonar 本身出售代码验证/质量产品，
  这份调研天然有利于其商业叙事；样本抽样方法、调研窗口、地区/行业分布均未披露；全部数字为自报，
  无第三方审计；"审查时间占比上升"可能部分反映"代码量本身增加"而非单纯验证成本上升，新闻稿未做区分。
- 原文：[Sonar Survey: AI Makes Code Abundant, but Code Confidence Remains Scarce](https://www.sonarsource.com/company/press-releases/sonar-releases-2027-developer-survey-report/)（检索于 2026-11-14）

### 2. Actor, Judge, or Teacher？长时程 Agent 里，"演得差"和"教得好"可以是同一个模型的两面
- 领域：AI / 智能体
- 来源 / 发布日期：arXiv / 2026-11-12
- 摘要：论文系统比较同一个"决策模型"在三种角色下的表现——作为 actor 直接输出动作、作为 judge 事后给
  轨迹打分、作为 teacher 用打分训练策略模型。在 ALFWorld 上测试三个决策模型与三个通用 LLM：六个模型
  作为 actor 时都会倾向漂向更容易的子目标而不先完成前置子目标；但作为 judge、拿到完整轨迹后，这些模型
  反而能准确识别"哪个动作真正推进了前置子目标"，尤其是被问"这个动作是否帮助了任务"而非"任务最终会不会
  成功"时更准；用其中一个模型（JEV）作 teacher，用 GRPO 训练一个 Qwen2.5-1.5B 策略模型，在 ALFWorld 与
  WebShop 上的成功率均有提升。
- 为何重要：核心判断是"一个模型在事前决策（actor）上的短板，不代表它在事后归因（judge/teacher）上同样
  弱"——事后判断能看到动作的后果，事前决策必须预判后果却常常失败，两者是可分离的能力。这对"用更强模型
  当 judge 来训练/监督 agent"的常见设计有直接含义。证据边界：全部实证限定在 ALFWorld（+ WebShop 用于
  teacher 验证）两个受控文本环境，是否外推到真实工具调用场景未知；仅测试了 6 个模型，覆盖面有限；论文
  未披露作者机构归属；提升幅度未在摘要页给出具体数字。
- 原文：[Actor, Judge, or Teacher? Understanding Decision Models in Long-Horizon Agents](https://arxiv.org/abs/2611.17167)（检索于 2026-11-14）

### 4. SO-Arena：21 个模型里,综合能力最强的那个,可靠性排名只有第七
- 领域：AI / 智能体（今日加选）
- 来源 / 发布日期：arXiv / 2026-11-11
- 摘要：SO-Arena 是一个面向"System One"（偏直觉/快速响应）模型的基准,覆盖 11 个领域、五类能力,除常规
  准确率外专门设计了两类可靠性测量——换一套选项后决策是否还稳定、模型能否识别"题目本身没有有效答案"
  的情况。作者测试 21 个模型后发现,扩大规模或加更多推理步骤带来的收益因领域差异很大;综合准确率排名
  最高的模型,放到可靠性排名里只排第七。
- 为何重要：这是"准确率不等于可靠性"判断在更广泛模型能力谱系（而非单一 agent 执行任务)上的又一次独立
  验证,方向上与此前"同一任务重复执行一致性缺口""outcome-only 指标掩盖过程脆弱性"等线索相邻,但测量对
  象（通用能力基准而非 agent 轨迹)不同,暂不并入已有线索,单独观察。证据边界:11 个领域与五类能力分类
  均为作者自建,评测设计是否代表真实应用分布未知;论文未给出"可靠性第七"具体模型名称与数值;结论依赖
  自建的"选项扰动"与"缺失答案识别"两种可靠性定义,是否是可靠性的完整刻画存疑。
- 原文：[SO-Arena: Benchmarking the Capability Spectrum and Reliability of System One Models](https://arxiv.org/abs/2611.15777)（检索于 2026-11-14）

## 今日主线

四条里有三条都在重复同一个方向的判断:模型/Agent 的"看起来行"和"真的可靠"是两件可以分开测量、分开优化
的事——Sonar 的调研证明企业已经用脚投票承认了这一点（评审时间反超编码时间),Actor/Judge/Teacher 说明
同一个模型在"当场决策"和"事后归因"上的可靠性可以截然不同,SO-Arena 则把这条判断从单个 agent 任务扩展到
通用能力基准全谱系。Mirendil 的巨额 A 轮提供了一个对照:市场在用"信任单一叙事"的速度给这类系统估值,而
上述三条证据恰恰说明这种信任目前缺乏可验证的度量基础。
