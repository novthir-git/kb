### 1. Actions with Receipts：把"引用可信"与"执行可信"这两件事绑在一起核验，99.61% 的替换攻击被识破
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / 2026-09-29（v1 于 2026-09-29 提交，Fri 10-02 批次公示）
- 摘要：中国科学院大学人工智能学院 + 中国科学院信息工程研究所团队（Miaobo Hu 等 8 人）指出，工具调用
  agent 展示引用来源与执行日志时，往往留下一个未被审计的关联：呈现给用户的"论断"是否真的来自已提交
  执行且被引用来源支持的那次调用。论文提出"论断锚定执行合约"——把发出的论断、来源片段、有序执行前缀、
  来源版本与访问状态联合绑定，并把"结构完整性核验"与"语义支持评估"拆成两个独立环节，展开为七条可
  测试属性。在 1,280 个跨对象替换攻击上识破 1,275 个（检出率 99.61%），移除关键属性后检出率暴跌到
  0.0156–0.0625；在独立判定的 384 对评测集上 F1 达 0.8865，假接受率 0.0729（在未见过的失效类型上升
  到 0.0938）。
- 为何重要：本仓库长期追踪的"agent 执行权限的授权/委托治理空白"这条线索（SARA/CapScope/GuardedAct/
  Agent Approval Laundering/EffectMatch/SEAD/ToolFence/Aletheia/PACE 等）此前的证据分别聚焦"调用前
  预测效应边界"（授权前）与"提交前核验实际效应"，本次把核验环节挪到了"回放时"——不问这次调用该不该
  被批准，而是问事后呈现给用户的结论是否真的可追溯到被批准、被执行、被引用来源支持的那条链路，是对
  "审批记录与实际派发是否一致"（09-25/09-30 两篇 Approval Laundering 论文）这一问题在"用户可见输出"
  这一层的延伸。证据边界：1,280 个攻击与 384 对评测集均为作者自建，尚无第三方复现；论文未说明具体
  测试了哪些真实工具调用 agent 产品，更接近受控实验而非生产系统验证；7–9 个百分点的假接受率意味着
  仍有不可忽视的残余漏检；提出方自身没有披露明确的商业或学术竞争动机，但方法复杂度（联合绑定五类
  状态）在真实部署中的工程成本未讨论。
- 原文：[Actions with Receipts: Jointly Binding Claims, Evidence, and Execution for Replayable Tool-Agent Auditing 论文](https://arxiv.org/abs/2610.00327)
- 配图：![论文提出的论断锚定执行合约整体架构图](https://arxiv.org/html/2610.00327v1/figures/algorithm_structure_v3.png)
  图片来源：[论文 HTML 全文](https://arxiv.org/html/2610.00327v1)。

### 2. Code That Works, Environments That Don't：三款 coding agent 对"同一任务该装什么依赖"的共识低至 7%
- 领域：软件工程
- 来源 / 发布日期：arXiv / 2026-09-30（v1 于 2026-09-30 16:04:45 UTC 提交，Fri 10-02 批次公示；拟投
  AAAI Journal《AI Magazine》特刊）
- 摘要：密苏里大学哥伦比亚分校团队（Bhanu Prakash Vangala、Tanu Malik）指出，coding agent 生成的
  代码即便功能正确，也常常无法准确声明其运行所需的依赖——这是功能测试测不出来的质量维度。论文构建
  三层框架区分"声明的依赖""运行时实际安装的依赖""必要且充分的依赖"，用命令行默认设置对比三款前沿
  coding agent（Claude Code / Anthropic，Claude Opus 扩展思考模式；Codex / OpenAI，经 GitHub Copilot
  接入；Gemini Code Assist / Google，最高推理档位），覆盖 Python、Java、JavaScript、C++ 四种语言、
  50 个编程任务。结果：同一任务下三款 agent 给出的依赖集合一致率低至 7%，且"更新的 agent 并未表现出
  有意义的改善"，说明问题不随模型规模或新旧而自动解决；最大的分歧出现在"声明的依赖"与"运行时实际
  安装的依赖"两层之间，论文将其归因于模型从训练分布里继承的"环境先验"是主要驱动因素。
- 为何重要：这是本仓库此前尚未覆盖的一个新质量轴——"环境规范的准确性"独立于功能正确性，且测试通过
  本身检测不出这类问题，与本仓库"SE agent 补丁'测试通过'与'审查可接受'是两回事"（线索 7）在方法论
  立场上相通（测试通过不等于可信），但切入点完全不同：前者关心补丁改动本身是否可接受，这篇关心补丁
  声明的"运行环境"是否可复现——对"把代码原样丢给 CI/生产环境"这类无人值守流程，依赖集合 7% 的一致率
  意味着同一任务换个 agent 跑，拿到的可运行环境可能完全不同。证据边界：仅覆盖 3 款 agent、4 种语言、
  50 个任务，样本规模中等；"必要且充分依赖"这一层的判定依赖作者自定义的协议和人工/工具复核，具体
  标准是否可被第三方独立复现未详述；三款 agent 均以命令行默认设置访问，IDE 集成模式或自定义系统
  提示词下是否同样成立未测试；论文拟投 AAAI Magazine 特刊，尚未经同行评审正式接受。
- 原文：[Code That Works, Environments That Don't: Measuring Environment Reproducibility in AI-Generated Software 论文](https://arxiv.org/abs/2610.00425)
- 配图：![论文的三层依赖评估框架与评测流水线示意图](https://arxiv.org/html/2610.00425v1/figures/evaluation_pipeline.png)
  图片来源：[论文 HTML 全文](https://arxiv.org/html/2610.00425v1)。

### 5. Groundability, Not Scale Alone：审查者模型的大小不重要，重要的是喂给它什么证据结构（今日加选）
- 领域：AI / 智能体（Agent，今日加选）
- 来源 / 发布日期：arXiv / 2026-10-01（v1 于 2026-10-01 04:10:59 UTC 提交，Fri 10-02 批次公示）
- 摘要：UC Berkeley（Javad Lavaei）+ Virginia Tech（Ming Jin）团队等提出的问题是：coding agent 常常
  返回"看起来合理"但遗漏了必要行为的补丁，而冗长的执行轨迹和自信的总结会掩盖到底漏了什么——什么时候
  一个名义上更弱的审查者模型能可靠判断一个补丁是否真正解决了问题？研究基于三款 agent 产出的 411 条
  执行标注轨迹与 101 个受控案例：仅给结构化但未经核验的证据时，GPT-5.4 作为审查者的覆盖率 0.89、
  风险 0.33、缺陷捕获率 0.76、过度拒绝率 0.66；改为提供官方执行证据作为"上限诊断"，并为每个审查者
  选定并冻结一种证据格式后，六个审查者中有五个在 122 条留出轨迹上同时提升了捕获率与拒绝率，两个做到
  完全正确分类；由于生产部署中官方测试通常不可得，论文进一步评估了一种"冻结级联"方案（结合补丁引发
  的静态错误 + 先在未打补丁仓库上失败的生成测试），在 121 条 GPT-5.4 留出轨迹与 59 条 Gemini 轨迹上
  覆盖率分别为 0.89、0.86。核心发现：审查者模型的规模并不是判断质量的稳定预测因子，关键在于给它的
  证据结构。
- 为何重要：这是对本仓库"SE agent 补丁'测试通过'与'审查可接受'是两回事，且差距可量化"这条线索（线索
  7，待批准追加到 `wiki/concepts/Evals.md`）的直接补强，补上了一个此前未测试过的具体变量——"用更弱、
  更便宜的模型做审查是否可行"，答案是可行，前提是证据结构对，呼应 09-30 Merged, Not Measured（合并率
  跟随 agent 历史信任度而非代码质量）对"轻量审查机制是否可信"的关切，把判断从"定性怀疑"推进到"具体
  给出可行的轻量方案配方"。证据边界：数据集规模中等（411 条轨迹、101 个受控案例、122 条留出轨迹），
  来自三款 agent 的自建基准，论文未披露具体是哪三款产品；"选定并冻结一种格式"的选择过程是否在看到
  留出集结果之前完成未详述，存在事后调参的可能性；结果仅在 GPT-5.4、Gemini 两个模型族上验证，能否

## 今日主线

今天 5 条的共同线索是本仓库一直在追的"信任从叙述/自报转向可验证结构"，但今天第一次从单纯的技术论文
扩展到了政府监管与当事人自白两个新维度。Actions with Receipts 把核验环节挪到"回放时"，核验用户看到
的结论是否真能追溯到被执行、被引用的那条链路；Code That Works, Environments That Don't 指出即便代码
本身正确，agent 对"该装什么依赖"的共识也低到 7%，是一个测试通过检测不出来的新质量轴；Groundability
证明"用小模型做审查"本身不是问题，证据结构才是——呼应了前几周"补丁测试通过≠审查可接受"的判断，给出
了具体可行的轻量方案。另外两条则是"自我治理承诺"这件事从技术/论文层面第一次撞上真实世界的强制力：

激光雷达能解决、纯视觉解决不了的问题——两条合在一起说明：当"我们会对此负责"的说法从公司公关稿变成
具体场景下的真实短板时，无论是行业自我监管还是技术路线选择，都正在被迫从"自我陈述"转向"可验证的
外部检验"。
