### 1. Idempotency Is Not Recovery：故障注入研究拆开"不重复"与"能恢复"两件事
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / 2026-11-18（v1 于 2026-11-17 UTC 上传，单一作者 Song Xu，机构未披露）
- 摘要：论文研究 LLM agent 的工具调用在外部系统已被实际改动后中断的场景——直接重试有重复副作用的风险，直接认定成功又可能掩盖一次从未真正发生的动作。作者在受控 agent 运行时中组合鉴权、操作台账、目标端幂等、调和、证据封存五个机制，注入 10 类单主机故障，用独立于运行时台账的目标端 oracle 对比 4 种配置与 3 组消融。Windows/Linux 各 7,513 次试验、96 个真实模型响应：完整配置在 200 组已知"崩溃-重放"对中做到 0/200 重复效果，各简化基线均为 117/200；移除操作台账会产生 170/170 孤儿效果（完整配置为 0/170），恢复成功率从 300/300 掉到 200/300；关闭调和后，100 组已知故障后效果全部无法判定；完整运行时吞吐量约为"失败开放"基线的七分之一。
- 为何重要：它把 9 月 Microsoft LIMBO 论文已经指出的"幂等键决定写操作副作用是否重复"这一判断往前推了一层——证明"不产生重复"和"故障后能被正确恢复"是两个要分别设计、分别测量的独立属性，光有幂等键不保证能恢复，光能恢复也不保证不重复。证据边界：全部实验在作者自建的受控故障注入环境中进行，10 类故障能否代表真实生产故障分布未验证；完整配置吞吐量降到约七分之一的具体性能代价未结合真实工作负载讨论；证据封存环节本身出故障时仍有 75/100 试验无法判定，说明方案是把"不可判定"压缩到更小范围，而非完全消除；单一作者、未见第三方复现，也没有会议/期刊录用信息。
- 原文：[Idempotency Is Not Recovery 论文](https://arxiv.org/abs/2611.23353)

### 2. SWE-Growth：用教师模型的验证结果，给自我对弈训练挖出"全错任务"里的学习信号
- 领域：软件工程
- 来源 / 发布日期：arXiv / 2026-11-19（v1 于 2026-11-18 UTC 上传，8 位作者，机构未披露）
- 摘要：自我对弈能规模化生成仓库级修复任务来训练软件工程 agent，但二元修复奖励加上有限 rollout 预算下，学生模型全部失败的任务组无法提供基于组内相对优势的强化学习信号。SWE-Growth 用一个教师模型的已验证修复结果去识别这类任务里哪些仍有学习价值：学生全错但教师能稳定解出的任务转成监督微调（SFT）样本；SFT 之后学生再做 rollout，找出"教师比学生强出一截"的混合结果任务专门做强化学习；任务是否"有学习价值"这一判定还反过来指导任务生成器（Injector）该怎么继续造任务。从 101 个种子 issue 起步，Qwen3-Coder-30B-A3B-Instruct 在 SWE-bench Pro 上从 27.7% 提升到 31.7%、留出集 TerminalBench 2.1 上从 11.0% 提升到 17.2%（第二轮），分别比"只做学生自对弈"高出 2.6 / 4.1 个百分点，比"教师增强自对弈"（预算大致匹配）高出 1.8 / 2.5 个百分点。
- 为何重要：它给"用 agent 自我对弈规模化训练 agent"这条已经很拥挤的路线补上一个此前被忽略的具体障碍——不是所有失败任务都值得学，有些任务对当前学生来说纯粹是噪声，教师的验证结果可以把"值得学"和"学不出来"分开。证据边界：仅在单一开源模型上验证；论文只报告两轮迭代的结果，更多轮次是否会出现收益递减或过拟合未披露；101 个种子 issue 规模较小；教师模型自身的能力上限决定了可转化监督信号的上限，论文未讨论教师能力不足时整条流水线会如何失效；暂无会议/期刊录用信息，未见第三方复现。
- 原文：[SWE-Growth 论文](https://arxiv.org/abs/2611.23876)

### 4. Attention Is Not Relevance：自动驾驶规划器的注意力权重，测出来是相关性不是因果性
- 领域：汽车 / 自动驾驶
- 来源 / 发布日期：arXiv / 2026-11-19（v1 于 2026-11-18 UTC 上传，Luca Lusvarghi、Javier Gozalvez，机构未披露）
- 摘要：论文把 NLP 领域"注意力是否真的反映模型输出的因果来源"这一既有质疑带入自动驾驶场景。基于 PlanT 2.0（Transformer 架构的物体级规划器），作者在超过 8 万个合成驾驶场景中，把基于注意力的相关性估计方法与反事实分析得到的因果参考做对比。结果显示注意力提供的是相关性而非因果性指示：会漏掉部分真正对驾驶决策有影响的物体，也会把对决策几乎没有影响的物体误判为"相关"；在单车道直行这类简单场景下表现尚可，多车道道路与交叉口等复杂场景下准确率明显下降。
- 为何重要：注意力权重是自动驾驶模型可解释性/事后归因的常用工具（用来回答"车为什么这么判断"），这项工作提示这类解释本身可能不可靠，尤其在真正需要解释的复杂路口场景下最不可靠。证据边界：摘要未给出具体的准确率、精确率或召回率数值，结论停留在定性层面；仅测试单一规划器架构与合成场景，未在真实道路数据上验证；作为"地面真相"的反事实因果参考本身依赖同一类模型机制而非独立的真实世界因果实验，能否完全代表因果地面真相本身仍可讨论；两位作者机构未披露，暂无会议/期刊录用信息，未见第三方复现。
- 原文：[Attention Is Not Relevance 论文](https://arxiv.org/abs/2611.24051)

### 5. Safe Personal RSI：个人智能体"只改提示词"的自我修改，需要专门的更新前评估—修复闭环
- 领域：AI / 智能体（Agent，今日加选）
- 来源 / 发布日期：arXiv / 2026-11-18（v1 于 2026-11-18 UTC 上传，机构未披露）
- 摘要：论文针对个人智能体"递归自我改进"（限定为仅修改可复用提示词指令，模型权重与运行时代码不变）提出一个更新评估组件，案例是作者自建的个人健康助手"Kicker"。流程对候选指令与当前指令同时测试、重复失败用例、临时撤销改动辅助定位根因，并在采纳前核验安全性与任务表现是否双双达标，任一版本未通过则维持当前指令。作者自建的可执行基准含 29 个邮件/日历/健康/市场任务用例，并为"授权复用""记忆""工具输出注入"设独立探针。三个模型×两种蓄意设计的高风险改动下，该流程拒绝 20/21 次更新尝试；在修复确认环节，一次被采纳的 GPT-5.6 Luna 修复把攻击违规率从 10.7% 降到 0%、安全任务完成率从 89.7% 升到 100%（一条手写权限规则也能达到同等效果）；在更强攻击下，一条从 Qwen2.5-7B-Instruct 迁移到 Qwen3-14B 的修复把违规率从 69.0% 降到 17.9%、安全任务完成率从 19.5% 升到 64.4%。另有独立运行时探针发现被评测快照中缺失本地 OAuth 授权范围检查。
- 为何重要：常驻/个人 agent 的"自我改进"目前多讨论模型权重或基础设施层面（如本仓库已收录的 Anthropic《Building always-on agents》架构原语），这篇论文把讨论下沉到更常见、更低门槛的"改提示词"这一层，说明即便限定在提示词范围内，自我修改仍需要专门的评估—修复闭环而非一次性人工审批。证据边界：机构未披露，全部评测基于作者自建的单一个人助手应用与 29 个用例，样本规模小；"蓄意设计的高风险改动"由作者主动构造，与真实使用中自发出现的有害提示词改动分布可能不同；跨模型迁移修复仅测试一条从 7B 到 14B 的迁移路径，泛化性未知；暂无会议/期刊录用信息，未见第三方复现或独立部署验证。
- 原文：[Safe Personal RSI 论文](https://arxiv.org/abs/2611.23651)
- 配图：![Safe Personal RSI 流程示意](https://arxiv.org/html/2611.23651v1/safe_rsi_intro_fig.png)

## 今日主线

今天的研究类条目有一条共同的收缩方向：各自领域里原本被当作"够用"的中间层机制——agent 工具调用的幂等重试、自我对弈训练的奖励信号、自动驾驶可解释性的注意力权重、个人 agent 的提示词自我修改——分别被证明只解决了问题的一部分，真正可靠还需要更专门的机制（恢复 vs 重复抑制分离、教师验证筛选任务、因果而非相关性的归因方法、更新前评估—修复闭环）。创业/商业条目则把 Anthropic IPO 从"定价多少"的事件新闻，推进到"这笔钱里有多少是在同一群参与者之间循环"这一结构性问题，两位独立分析师的分歧也说明这个问题目前没有共识答案。
