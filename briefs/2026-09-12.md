### 1. OpenAI 将 Codex 底层 Harness 包装为公测版 Agents API，正面对标 Claude Managed Agents
- 领域：AI / 智能体（Agent 基础设施，产品发布）
- 来源 / 发布日期：OpenAI 官方博客 / 2026-09-10（经 InfoWorld、The Decoder 交叉核验于 2026-09-11；检索于 2026-09-12）
- 摘要：OpenAI 面向所有开发者公测开放 Agents API，把此前驱动 Codex 与 ChatGPT 的 agent 运行时基础设施（编排、上下文管理、执行环境）打包成单次 API 调用即可配置的托管服务。核心概念分四层：Agent（模型、指令、工具及可用 MCP servers）、Environment（可选沙箱，供 agent 访问文件、加载 skills、执行命令）、Session（持久化的 agent 实例）、Events/items（输入输出事件流）。技术特性包括自动上下文压缩（临近上下文上限时自动精简，无需开发者自写压缩逻辑）、Tool Search（按需加载工具定义以降低 token 开销、保留模型缓存）、并行工具调用与子 agent 任务委派。执行环境可选 OpenAI 托管沙箱，或 Cloudflare、Vercel、Oracle、E2B、Modal、DigitalOcean 等第三方沙箱提供商。计价仅按 token 用量，无额外费用；但即使企业自带沙箱部署，该 API 也**不支持 Zero Data Retention**，分析师指出这对医疗、金融等受监管行业构成顾虑，且模型、上下文管理、工具、编排一体绑定 OpenAI 会加大迁移成本。
- 为何重要：这是"Harness 设计是决定同模型实际表现的独立架构变量"这条本 wiki 持续跟踪的线索（`briefs/memory.md` 跨天论点线索 4）迄今最重的商业化数据点——OpenAI 直接把经过生产验证的 harness（而非仅模型）作为可计费产品对外出售，与本期第 5 条 Ecdysis（如何更高效地训练/演化 harness 本身）形成呼应，说明"harness 即产品"正从研究判断变成市场事实。证据边界：本条细节未直接读取 OpenAI 官方原文（WebFetch 对 openai.com 返回 403），改用两家独立科技媒体交叉核验，功能描述一致但可能遗漏官方原文的限定条件或数字；"不支持 Zero Data Retention"等限制来自媒体分析而非官方逐字确认；市场竞争格局（对标 Claude Managed Agents、AWS Bedrock AgentCore 等）为媒体归纳，非 OpenAI 自陈。
- 原文：[Introducing the Agents API（OpenAI 官方博客，直接访问被拦截）](https://openai.com/index/introducing-the-agents-api/)；交叉核验来源：[OpenAI's new Agents API gives developers the infrastructure behind Codex and ChatGPT（The Decoder）](https://the-decoder.com/openais-new-agents-api-gives-developers-the-infrastructure-behind-codex-and-chatgpt/)、[OpenAI launches managed Agents API to simplify enterprise AI agent development（InfoWorld）](https://www.infoworld.com/article/4221163/openai-launches-managed-agents-api-to-simplify-enterprise-ai-agent-development.html)

### 2. GuardedAct：给 LLM 生成的生产环境修复动作加一道"数字孪生沙箱+爆炸半径"验证闸门
- 领域：软件工程（AIOps / 生产事故自动修复的安全执行）
- 来源 / 发布日期：arXiv（cs.DC / cs.SE），v1 于 2026-09-10 上传（检索于 2026-09-12）
- 摘要：论文指出，LLM 生成微服务故障修复动作虽有效，但在生产环境直接执行存在级联附带损害风险。GuardedAct 在 LLM 动作生成器与生产环境之间插入一道"爆炸半径感知"验证层，分四阶段运作：①摄入诊断报告、系统拓扑与近期遥测数据；②让 LLM 产出排序后的候选修复动作列表；③在轻量级数字孪生沙箱中模拟每个动作、估算爆炸半径并打风险标签；④"回滚置信度闸门"只自动执行低风险动作，高风险动作升级人工审核。在 DeathStarBench 社交网络应用上注入 5 种故障场景测试：整体恢复率 87.4%，相对直接 LLM 执行，附带损害率从 25.6% 降到 5.2%（下降 79.7%），代价是沙箱模拟带来约 8 秒的平均恢复时间增加；消融实验确认各组件都对"安全-速度"权衡有实质贡献。
- 为何重要：这为本 wiki 持续跟踪的"agent 执行权限的授权/委托治理空白"线索（`briefs/memory.md` 跨天论点线索 2：SARA→Delegation Without Trust→CapScope→Anthropic 真实事故披露）补上一个新场景——不是"拦截恶意/越权指令"，而是"即便指令善意，也要在执行前验证爆炸半径"，把同一治理判断从安全对齐问题延伸到可靠性工程问题。证据边界：仅在单一开源基准 DeathStarBench 的 5 个人工注入故障场景上验证，未见真实生产环境或第三方复现；"爆炸半径"估算依赖数字孪生沙箱与生产环境的保真度，论文未讨论沙箱与真实拓扑漂移时估算失准的后果；5 篇作者均来自同一团队，无跨机构验证。
- 原文：[GuardedAct 论文（arXiv 2609.11264）](https://arxiv.org/abs/2609.11264)

### 4. 欧盟把"在用监测与报告"（ISMR）写入自动驾驶量产法规，仿照核能与轨交的运行数据强制回收机制

- 来源 / 发布日期：arXiv（cs.RO），v1 于 2026-09-10 上传；将在 EsREDA 第 62 届会议（荷兰特文特）报告（检索于 2026-09-12）
- 摘要：论文介绍欧盟近期批准的自动驾驶系统（ADS）量产上路法规中的数据收集条款，其设计借鉴 UNECE 层面的"在用监测与报告"（In-Service Monitoring and Reporting, ISMR）最佳实践，并参照核能与交通运输行业既有的运行数据强制回收监管模式。核心机制：real-world 运行数据供安全监管机构核实型式认证（homologation）安全目标是否在实际道路上成立；ADS 实际运行中发现的安全相关场景可存入"场景目录"，供比较不同 ADS 厂商如何应对同一交通冲突；数据教训可在整车厂（OEM）与安全监管机构间共享。论文主张，仅靠传统型式认证验证流程无法覆盖所有未知风险，ISMR 是补上这一缺口的必要工具。
- 为何重要：这与本 wiki 已跟踪的"自动驾驶技术路线与商业化打法之争"线索（`briefs/memory.md` 跨天论点线索 5）中"监管审查/合规风险"这一维度直接呼应——继 NHTSA 对 Tesla Cybercab 无方向盘设计立案审计（2026-09-06 已收录）之后，这篇论文说明欧盟选择的监管路径不是"事后立案审计"，而是"事前写入法规的持续运行数据强制回收"，为比较美欧两种监管哲学提供了具体制度设计样本。证据边界：这是一篇政策/框架研究论文而非实证评估，未提供该 ISMR 机制已实际运行的效果数据；论文未列出作者所属机构，其"欧盟近期批准"的法规细节本条未逐条核实原始法规文本；会议 EsREDA（欧洲风险与可靠性分析论坛）非顶级 AV 安全会议，截至检索时论文本身状态为会议投稿/预印本。

### 5. 今日细读：Ecdysis——用"批量跨任务失败聚类"取代逐条试错，把 Agent Harness 的自我演化训练提速 1.84 倍
- 领域：AI / 智能体（Harness 自我演化训练方法，今日加选）
- 来源 / 发布日期：arXiv（cs.SE / cs.AI），v1 于 2026-09-10 上传（检索于 2026-09-12）
- 摘要：论文指出现有 harness 演化方法依赖"迭代搜索"——针对单个任务实例的执行反馈反复评估、修改候选 harness，导致训练耗时高，且容易过拟合到已观察任务的具体失败模式，损害对未见任务的泛化。作者认为根本瓶颈在于缺乏"有原则的失败诊断"：一次观察到的失败可能反映模型自身的局限，也可能反映 harness 本身的系统性缺陷，直接针对单个失败优化容易导致不必要的"迁就模型"式修补。Ecdysis 因此采用批量级跨实例失败聚合范式，联合分析多个任务实例的失败证据，并引入"失败驱动的协同精炼"（Failure-Driven Collaborative Refinement）机制诊断失败原因、迭代精炼 harness 修改规范，区分"模型特定迁就"与"harness 级修复"。实验显示，相较现有 harness 演化方法，Ecdysis 训练速度提升最高 1.84 倍，最终 harness 的推理准确率提升 18.56%。
- 为何重要：这与本期第 1 条（OpenAI 把 harness 商品化为 Agents API）共同把"harness 不是模型的轻量包装，而是独立、可系统性优化的架构变量"这一本 wiki 已有判断（`briefs/memory.md` 跨天论点线索 4）向前推进了一步——一边是把 harness 训练本身的效率问题方法论化（如何更快演化出更好的 harness），一边是把训练好的 harness 直接产品化对外出售，两条路径互补但都指向"harness 工程"正成为独立于模型能力的竞争维度。证据边界：论文未披露具体测试用的 benchmark 名称、任务数量及基线方法的完整列表（本条基于摘要与可读部分，未逐节核对实验设置表格）；"18.56% 推理准确率提升"与"1.84 倍加速"均为作者自报的单一研究结果，未见第三方复现；论文未讨论该方法在生产级、长时运行 agent 系统上的适用性。
- 原文：[Ecdysis: Efficient and Effective Training of Runtime Harnesses for LLM Agents（arXiv 2609.11677）](https://arxiv.org/abs/2609.11677)

## 今日主线
