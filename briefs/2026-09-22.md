### 1. CodeMidas：不靠 issue/commit，直接把开源代码库"炼"成强化学习训练环境

- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv（小米 MiMo 团队）/ v1 于 2026-09-18 17:55 UTC 上传
- 摘要：训练 coding agent 用强化学习，需要大量"任务 + 可靠验证器"的训练环境，此前方法普遍依赖
  issue、commit 等开发过程产物作为任务来源，能覆盖的任务范围有限。CodeMidas 反其道而行——只用
  代码库本身的源码作为输入，让 agent 自己完成环境构建的每一步：先探索代码库已实现的功能、反推出
  行为规范，再基于对原始代码的实际执行构造测试，最后通过执行检查和多次解答 rollout 过滤验证候选
  任务。最终产出 5,545 个训练任务，来自 3,185 个开源代码库，覆盖 23 种编程语言、15 个技术领域。
  用这批任务以 GRPO 训练 MiMo-V2.5，在五个不同基准上全部提升：issue 修复类 DeepSWE +11.7%、
  整程序构建类 ProgramBench +17%、终端操作类 Terminal-Bench v2.1 +8.5%；消融显示高质量任务数量
  越多、效果越好；轨迹分析显示训练后的 agent 表现出更多代码库探索行为和更多样的自我验证行为。
- 为何重要：这条证据把"如何规模化生产 RL 训练环境"这个问题的解法从"依赖人类留下的开发痕迹"
  推进到"直接从代码本身反推任务"，呼应了 09-12 简报收录的 Ecdysis（同样关注 harness/环境的规模化
  训练方法）这条尚待用户批准沉淀的线索——两者共同指向"训练环境本身的构造方式"正在成为独立于模型
  架构之外的一个工程变量。证据边界：19 位作者均来自小米内部团队，无外部机构复现；五个基准的提升
  幅度均基于同一批内部构造的任务集训练后测得，未见第三方在独立任务集上的复现；论文未披露训练
  任务集本身是否存在数据污染（即基准测试集是否与训练代码库来源重叠）的检查方法。
- 原文：[CodeMidas: Scaling Agentic Coding RL Environments from Code Itself](https://arxiv.org/abs/2609.22068)

### 2. 527 名科研人员自述："跑一遍看看能不能用"是验证 AI 生成代码的主流方法

- 领域：软件工程
- 来源 / 发布日期：arXiv（Sandia National Laboratories / 密歇根大学 / 田纳西大学诺克斯维尔分校）/
  v1 于 2026-09-18 17:41 UTC 上传
- 摘要：研究者分析 2025 年一项调查中 527 份自由文本回答（多数来自美国高校的科研编程人员），每份
  回答讲述受访者自己工作中的一次具体任务、如何用 AI 工具完成、以及如何判断结果对不对。用途高度
  集中在五类任务：数据处理（23.9%）、可视化（19.8%）、调试（17.4%）、数学/科学计算
  （11.7%）、统计分析（10.9%），合计约占全部用例的 76%。验证方式非正式且高度依赖个人判断：
  52.8% 的account描述"跑一遍代码看结果"，22.5% 检查输出、19.4% 读代码、16.2% 检查可视化结果，
  而写自动化测试仅占 2.8%、请同事复核仅占 2.0%。编程经验与"用 AI 做什么""怎么验证"关系不大，
  但与"信心"密切相关：经验约 3.7 年是分水岭——经验更少的程序员对 AI 工具的信任高于对自己的信任
  （用 AI 去做自己本来做不了的事），经验更丰富的程序员则相反（用 AI 节省本来自己也能做的事所花
  的时间）；而"验证信心"本身与"实际采用了哪种验证策略"没有显著关联，最强的相关因素是"对工具的
  信任度"和"对自己能力的信任度"。
- 为何重要：这是首次把"科研人员如何验证 AI 生成代码"量化到具体任务类型和验证策略分布的调查，和
  已有页「Evals（AI 系统评估）」中"SE agent 补丁测试通过≠审查可接受"的判断（SWE-Gate、PatchBench
  等）形成有意思的对照——那条线索测的是 agent 自动化流水线里"验证是否严谨"，这篇测的是人类科研者
  日常工作里"验证有多不严谨"（自动化测试、同行复核合计不到 5%），说明验证缺口不只存在于自动化
  agent 系统内部，人类使用者自己手动使用 AI 编程工具时同样普遍缺乏正式验证手段。证据边界：作者
  自陈样本 97.6% 来自美国、93.7% 来自高等教育机构，可能"过度代表了对编程调查本身感兴趣的科研
  人员"；受访者只描述"单次回忆的episode"，可能低报实际验证行为；大多数回答由单一作者编码，
  未做多编码者一致性检验；调查限英语作答，结论未必能推广到其他科研环境。
- 原文：[How Researchers Use and Verify AI Coding Assistants: Tasks and Validation Practices in Scientific Programming](https://arxiv.org/abs/2609.22049)

### 4. CounterPlay：自动驾驶策略训练进入收益递减期后，"回溯改风格重试"比"继续堆算力"更划算（今日细读）

- 领域：AI / 智能体（Agent，今日加选，兼汽车/自动驾驶技术候选）
- 来源 / 发布日期：arXiv（弗莱堡大学 Abhinav Valada 团队）/ v1 于 2026-09-18 11:00 UTC 上传
- 摘要：大规模自演对弈（self-play）能训练出闭环表现不错的自动驾驶策略，但每单位仿真算力带来的
  提升会随训练规模递减——常见场景很快学会，剩下的训练量反复撞上同一批"解不开"的失败场景。此前
  的改进方法大多在"已访问过的状态"上评估备选动作或续玩，但论文认为很多失败真正需要的是"更早
  一步就换个开车风格"。CounterPlay 提出三个组件：失败驱动的回溯（用策略自身的价值估计选一个更早
  的存档状态重试）、奖励条件化（同一个策略可以在重试时选择从谨慎到激进的不同风格）、以及验证
  过滤（只有在新的随机性下重试、且没有让其他车辆出现新的或更早的碰撞/驶出道路，才会被蒸馏回
  策略里）。在 BehaviorBench 的 Interactive 和 Random 两个测试集、全部 8 种交通场景下均取得
  最优成绩，且只用了锚点模型 1,000 亿次自演训练量的 1%（10 亿次）做后训练；三种驾驶风格下改进
  均成立，能解决锚点模型相当一部分的超时失败案例，且在任务完成率与安全性之间取得了"继续自演"或
  "干脆改激进风格"都做不到的平衡。
- 为何重要：本期汽车/自动驾驶领域排查多轮（Waymo 官方博客、Tesla/NHTSA 监管动态、Zoox/Wayve/
  Nuro/Pony.ai 近期新闻）均未找到过去一周内满足质量门槛的一手候选，这篇论文是唯一命中窗口、
  论证扎实的技术候选，故破例收录为本期"今日细读"、计入 AI/智能体领域而非单列汽车条目。它的价值
  在于给"扩大自演对弈规模收益递减"这一直觉提供了具体的训练效率数字（1% 训练量达到甚至超过
  锚点表现），方法论上也与线索 4（harness/训练方法本身是独立工程变量）呼应。证据边界：**全部
  验证均在 BehaviorBench 仿真环境中完成，未见任何真实道路数据或车队部署**；"跨 8 种交通场景取得
  最优"依赖 BehaviorBench 这一基准本身的场景设计是否有代表性，论文未讨论其局限；"锚点模型"的
  具体来源（是否为某已知商业自动驾驶系统的复现）未在摘要中说明。
- 原文：[CounterPlay: Counterfactual Post-Training for Self-Play Driving Policies](https://arxiv.org/abs/2609.21617)

## 今日主线

本期四条独立证据从不同角度指向同一件事："AI 系统的产出能不能被信任"这个问题，正在从"要不要相信
agent"细分成"用什么方法生产可信的训练数据/环境"（CodeMidas）、"人类自己验证 AI 产出的手段有多
薄弱"（527 名科研人员的自述）、"公司自身的重大决策时间表与外部安全叙事是否同步"（Anthropic IPO
澄清与安全辩论无关）、"仿真训练的收益递减能否靠更聪明的重试策略而非砸更多算力来解决"
（CounterPlay）。汽车/自动驾驶领域本期未见独立候选，用 CounterPlay 顶替，且已在条目内明确标注
仅有仿真验证。
