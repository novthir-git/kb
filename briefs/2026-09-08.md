### 1. Agent 换了底层模型，记忆会不会跟着"失忆"？一项受控研究给出量化答案
- 领域：AI / 智能体（Agent，记忆架构）
- 来源 / 发布日期：arXiv / 2026-09-07（公告日），v1 于 2026-09-04 16:44:17 UTC 上传
- 摘要：论文比较四种 agent 记忆存储方式在**模型升级后**的表现：原始历史逐字保留供长上下文阅读（LC-RAW）、切块做检索增强（RAG）、由模型压缩成自然语言笔记（NOTES）、归一化进固定 schema 知识图谱（KG-fixed）。结果差异悬殊：KG-fixed 在模型升级前后准确率几乎不变（±0.0020）；NOTES 因构造阶段信息损失，升级后波动达 +9.91 到 -13.28 个百分点；RAG 若只做部分重嵌入，提升幅度（4.96 点）远不如全量重嵌入（11.90 点）。更关键的是"能否事后补救"：48 个案例中，仅保留笔记的 NOTES 存储无一例能通过 90% 的恢复阈值修复，而保留原始历史的方案中有 34/48 案例可修复——原始证据保留与否，直接决定记忆损失能否事后挽回。
- 为何重要：目前生产 agent 普遍用摘要/笔记类记忆以节省上下文和成本，这篇研究说明这个选择隐含一个未被充分讨论的代价——一旦更换底层模型，压缩过的记忆可能不可逆地"错译"历史，而原始日志或结构化知识图谱更抗升级冲击。证据边界：仅在受控合成任务上测试，未覆盖真实生产 agent 的长期记忆库；论文未标注作者机构，同行评审状态未知；"KG-fixed 最稳"的结论可能依赖其归一化 schema 与测试任务的匹配度，未验证 schema 设计不佳时是否仍成立。
- 原文：[Does Your Agent's Memory Survive a Model Upgrade? A Controlled Study of Memory Portability（arXiv 2609.05339）](https://arxiv.org/abs/2609.05339)
- 配图：![四种 agent 记忆格式对比：各自保留的信息与升级风险不同](https://arxiv.org/html/2609.05339v1/figures/memory_formats.png)
  图片来源：[论文 Figure，Section 2.2](https://arxiv.org/html/2609.05339v1)。

### 2. Better Understanding, Better Fixes：LLM 修 bug 时，"过程"里的幻觉比"结果"更常见也更隐蔽
- 领域：软件工程
- 来源 / 发布日期：arXiv / 2026-09-07（公告日），v1 于 2026-09-04 09:11:27 UTC 上传
- 摘要：论文把"自动程序修复中的幻觉"从只看最终补丁，拆成最终补丁 + 三类中间产物（定位触发用例、预测行覆盖、生成额外测试用例）的多层分析，定义幻觉为"未被现有修复证据支撑的产出"。在 Defects4J 的 832 个 bug 上评测 GPT-5、DeepSeek-R1、Claude Sonnet 4.5 三个模型：自动评测下仅 21.0%–55.9% 的生成补丁能通过开发者写的测试；对 812 例人工复核样本的分析发现，72.7% 的修复存在幻觉（**含通过了全部可用测试的补丁**），其中错误的因果定位占 45.9%、错误的修复策略占 18.5%。更准确的中间产物通常伴随修复成功，但这一关系并不总成立。
- 为何重要：这是本 wiki 已跟踪判断"SE agent 补丁'测试通过'≠'审查/现实可接受'"（09-05 简报 SWE-Gate：34% 通过功能测试的补丁未达审查标准；09-07 简报 PatchBench：25% 补丁疑似记忆历史答案、PoC-only 验证让解决率虚高 1.83 倍）的第三个独立证据源，且首次把"通过测试的补丁里仍有幻觉"这一更反直觉的现象量化到 72.7%——说明问题不只在验证方式偷懒，修复过程本身的因果定位就经常是错的。证据边界：仅覆盖 Java 的 Defects4J 基准，未验证能否推广到其他语言或真实生产代码库；人工复核的判定标准细节与评审者间一致性未在摘要中说明；三个被测模型均为通用模型，未测试专门为 APR 微调过的模型。
- 原文：[Better Understanding, Better Fixes? A Study of Hallucination in LLM-based Automated Program Repair（arXiv 2609.04909）](https://arxiv.org/abs/2609.04909)
- 配图：![LLM 自动程序修复中幻觉研究的概念框架图](https://arxiv.org/html/2609.04909v1/hallucination_overview.png)

### 3. CoLMIN：让多辆车用 LLM"谈判"走哪条路，靠反思机制防止过早收敛到次优方案
- 领域：汽车 / 自动驾驶
- 来源 / 发布日期：arXiv / 2026-09-07（公告日），v1 于 2026-09-04 07:03:29 UTC 上传
- 摘要：论文指出，多车协同自动驾驶中的路径决策天然是"多解"问题，现有基于 LLM 的车间协商方法常过早收敛到次优方案，难以达成稳定共识。CoLMIN 提出三个模块的组合：Negotiator-Evaluator 范式的多意图协商模块（LMin）为同一场景生成多条候选驾驶意图供联合评估；浅层反思模块（ESRM）分析每轮协商结果并反馈以加速收敛；深层反思模块（LDRM）对协商历史做长期复盘，缓解"认知固化"、避免系统反复收敛到同一个次优解。在 CARLA 仿真环境的高交互性驾驶场景中，CoLMIN 显著优于现有方法。
- 为何重要：这为自动驾驶领域"车辆间如何协商共享道路"提供了一条不同于感知/控制层竞争（本 wiki 线索 5 跟踪的 Waymo/Tesla/Wayve/Atoms 商业化路径之争）的技术路线——把协同决策问题转成显式的多轮 LLM 协商 + 反思架构，而非依赖预设博弈规则或单次意图预测。证据边界：仅在 CARLA 仿真环境验证，未见真实道路或硬件在环测试；对比基线、具体性能提升幅度的数字未在摘要中给出；LLM 协商的实时性（延迟是否满足行车决策时限）未被讨论，这对车载部署是关键但未验证的前提。
- 原文：[CoLMIN: LLM-based Multi-Decision Path Negotiation for Cooperative Autonomous Driving（arXiv 2609.04807）](https://arxiv.org/abs/2609.04807)
- 配图：![CoLMIN 整体架构：感知模块与三个协商相关模块（LMin、ESRM、LDRM）](https://arxiv.org/html/2609.04807v1/img/Structure.png)
  图片来源：[论文架构图](https://arxiv.org/html/2609.04807v1)。

### 4. 今日细读：给 Agent 的任务说明书里加一句"内存 128MB、限时 10 秒"，生成的代码质量立刻不同
- 领域：AI / 智能体（Agent，执行上下文，今日加选）
- 来源 / 发布日期：arXiv / 2026-09-07（公告日），v1 于 2026-09-04 14:57:17 UTC 上传
- 摘要：论文提出"substrate blindness"概念——agent 的规划状态里缺失内存、执行时间、运行时与算力等执行约束信息，导致规划出的方案在实际执行环境里"看似合理、实则不可行"。作者用高维两两欧氏距离计算任务做受控实验：让 Claude Opus 5、GPT-5.6-Sol、Gemini 3.7 Flash 三个前沿模型，分别在"只给任务描述"和"额外给出 128MB 内存 + 10 秒 wall-time 的执行契约"两种条件下生成代码。披露执行契约后，14 组对照中 13 组的峰值内存下降，三个模型的平均耗时全部下降，最快提速 3.1 倍；在更严格的 96MB 契约下，三个模型"正确且不超预算"的成功率从 0/5、1/5、0/5（仅给任务）分别提升到 4/5、5/5、3/5（给执行契约），平均峰值内存与耗时分别降低 49%–74%、35%–64%。
- 为何重要：这为本 wiki 线索"harness 设计是决定同模型实际表现的独立架构变量"（[[Harness 不是轻量 Wrapper]]，此前证据为 09-04 简报的 Harness Engineering 源码级横向剖析）补上一个更细粒度的机制解释——不只是 harness 的工具封装和执行循环影响表现，连"是否把执行环境的资源约束显式写进 prompt"这一件小事，都能让同一个前沿模型的输出质量出现数倍级差异。证据边界：任务被限定在一个高维距离计算的合成基准，未验证能否推广到更复杂的真实软件任务；论文为单作者署名，未标注机构，同行评审状态未知；三个模型的样本量均为 5 次运行，方差与统计显著性未报告。
- 原文：[Substrate-Aware AI Agents: Execution Context as a First-Class Input（arXiv 2609.05232）](https://arxiv.org/abs/2609.05232)

## 今日主线

今天四条共享一个底层追问：**agent 系统里哪些"上下文"是显式给出的，哪些是隐式假设、一旦缺失或变化就会出问题？** 记忆可移植性研究说明，压缩记忆格式隐式假设了"未来读它的还是同一套理解方式"，模型一换就可能露馅；程序修复幻觉研究说明，补丁"过程"里隐藏着大量未被验证的因果假设，测试通过掩盖不了这些假设是错的；Substrate-Aware Agents 说明，连"这段代码会跑在什么资源约束下"这种基本执行上下文，不显式给出模型就会视而不见；CoLMIN 则从正面提供一个"把隐式假设显式协商出来"的架构范式——用多轮候选生成加反思机制,让多车协同决策收敛到更稳的共识而非一次性猜测。四条放在一起，呼应本 wiki 长期跟踪的判断：**agent 的瓶颈正从"模型能力"转向"给模型的上下文和验证机制是否完整"**。
