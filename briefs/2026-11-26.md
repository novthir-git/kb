### 1. Delegent：让前沿模型继续掌舵、把琐碎子任务甩给笔记本电脑就能跑的 2B 小模型，编码成本砍掉三分之二且不丢性能
- 领域：AI / 智能体
- 来源 / 发布日期：arXiv / 2026-11-25（announced；v1 于 2026-11-24 UTC 18:34 上传），Lingwei Gu、Jimmy Lin（机构未披露），代码已在 GitHub（castorini/delegent）公开
- 摘要：论文指出，前沿模型 agent 成本高的一个原因是模型会反复重读完整上下文，并且亲自处理每一个子任务——不管难易。Delegent 是一个基于 Claude Code 构建的多 agent harness：前沿模型始终掌握任务主导权，只把代码调研、跑测试、语料检索这类聚焦型子任务委派给小语言模型（SLM）子 agent 执行；与"级联"或"路由器"式方案不同（那类方案为整个任务挑选一个模型），Delegent 让前沿模型全程在场，且不训练任何路由器，因此前沿模型与子 agent 模型都可随意替换。作者发现一条简短的指令承担了大部分成本节省效果，并且能让一个仅 2B 参数的 SLM 不至于把任务搞丢。量化结果：用 27B（FP8）SLM 做子 agent，长时编码任务的前沿模型成本降 67%、agentic 检索任务降 59%，均无性能损失；换成可在笔记本电脑本地跑的 2B SLM，编码成本仍降 66%。
- 为何重要：本仓库线索 4（"Harness 设计是决定同模型实际表现的独立架构变量"）此前已累积 34 条候选证据，但证据大多集中在"同一模型换一套 harness 后的成功率/效率变化"，很少专门针对"把前沿模型的部分认知负荷结构性转移给小模型子 agent、同时不牺牲性能"这一具体子设计。Delegent 把这条判断推进到一个可复现的工程配方：代码已公开，且明确报告"小模型损失一次就终止委派"的失败模式与"一句短指令承担大部分收益"这一反直觉发现，是该线索里少见的、同时给出正向效果与边界条件的案例。
- 证据边界：仅两位作者（Lingwei Gu、Jimmy Lin），机构未披露；"长时编码/agentic 检索"两类任务的具体基准、样本量与任务难度分布，论文页面未给出；"无性能损失"是作者自建评测下的结论，未见第三方复现；委派粒度、子 agent 失败后的恢复机制细节未在摘要中说明；预印本，无同行评审信息。
- 原文：[Delegent: A Multi-Agent Harness That Reduces Cost without Sacrificing Performance](https://arxiv.org/abs/2611.33098)（检索于 2026-11-25）

### 2. SpecEngineeringBench：给 coding agent 出一道"自己找缺陷、自己定位"的真考题——测试写得越全、覆盖率越高，也不代表真的抓到了缺陷
- 领域：软件工程
- 来源 / 发布日期：arXiv / 2026-11-25（announced；v1 于 2026-11-24 UTC 17:07 上传），13 位作者（Xingjian Wang、Shijian Wang、Minghao Liu 等，机构未披露）
- 摘要：论文指出，"自主规范工程"（autonomous specification engineering）要求 coding agent 自己把功能需求转成可执行测试，并用执行结果去发现和确认缺陷；但现有基准往往直接把 issue 描述、测试入口点或该检查哪些文件喂给 agent，没有真正测试 agent 能否自己判断"该测什么、该去哪找"。SpecEngineeringBench 收录 78 个开源 Python 仓库、16 个应用类别下的 100 个实例，每个实例配有多条已记录的真实缺陷；设置两个任务——生成测试套件、通过执行分析发现缺陷——并同时打分测试有效性、缺陷检出率、覆盖率，以及定位的精确率与召回率。在 7 款前沿 coding agent 上的结果：测试有效性（Head Pass Rate 91.47%）与改动相关覆盖率（80.48%）都很高，但与之明显脱钩的是缺陷暴露率（Fail-to-Pass Rate 仅 26.36%）；定位召回率随粒度变细而下降（文件级 78.11% → 函数级 51.29%）；让 agent 自主生成测试，比只依赖仓库已有测试，能把定位召回率再提升 2.7-5.0 个百分点。
- 为何重要：本仓库关键问题 3（知识与规格如何在人和 agent 之间保持不漂移）里，"可执行规格"一直被当作对抗漂移的候选手段（见线索 34、线索 45）；这篇论文从另一侧补上一个警示性数据点——即便 agent 能把规格转成"看起来很规范"的测试（高有效性、高覆盖率），这些表层指标本身并不保证真的抓住了缺陷，二者在经验上是脱钩的。这与线索 61（IR 式 Bug 定位基准的 ground truth 标注本身大面积错误）方向相邻但机制不同：线索 61 指向"评测标注本身错了"，本文指向"即便标注没错，测试的表层质量指标也可能系统性误导对真实缺陷检出能力的判断"——两者合起来提示，"规格/测试"这条看似确定性的调和路径，自身的测量方式也需要被审视。
- 证据边界：论文暂无 html 版本可供核验配图或完整正文，数值取自 abs 页摘要；13 位作者所属机构均未披露；100 个实例、78 个仓库的样本规模中等，16 个应用类别的覆盖面是否有偏未讨论；7 款 coding agent 的具体名称、版本及其与 Delegent 等商业 harness 的关系未在摘要中说明；预印本，无同行评审信息。
- 原文：[SpecEngineeringBench: Evaluating Coding Agents as Autonomous Specification Engineers](https://arxiv.org/abs/2611.32973)（检索于 2026-11-25）

### 4. CodeWAM：驾驶世界模型里加一段"可执行代码"，让自车状态演化不再只靠模型隐式猜测
- 领域：汽车 / 自动驾驶
- 来源 / 发布日期：arXiv / 2026-11-25（announced；v1 于 2026-11-24 UTC 12:11 上传），Zhisheng Chen、Jinpeng Wang、Beicheng Lou 等 8 位作者（机构未披露）
- 摘要：CodeWAM 是一个在世界表示中显式包含可执行代码的驾驶世界模型：代码负责建模自车状态在给定候选规划下如何演化，一个学习出的视觉模型则负责捕捉场景相关的结果；执行这段代码会得到一条运动序列，再与此前的规划和已记录的运动历史打分比对。规划器据此把"代码执行后果"和"场景结果预测"两者结合起来评估每个候选方案的未来走向，被选中的方案又成为下一次决策的上下文输入。量化结果：NAVSIM v1 navtest 上 PDMS 93.6；NAVSIM v2 navtest 上 EPDMS 92.1；NAVHARD 上 EPDMS 50.6；在 Hydra-MDP、DrivoR 等现有规划器上无需额外训练即有提升（具体增益幅度论文正文未在摘要层给出）。
- 为何重要：这是本仓库线索 4（Harness 设计是决定同模型实际表现的独立架构变量）第三个自动驾驶领域证据（此前为 11-20 Generalist Action Critic、11-23 ROSE-Drive），且带来一个新的具体设计变体：不是靠编排层调度冻结模型（ROSE-Drive）或用独立模型做事后复核（Generalist Action Critic），而是把"自车状态演化"这一部分直接交给确定性可执行代码计算、只让学习模型负责场景级的不确定性。这与本仓库线索 3（"不信任模型直接生成结构化产物/编辑的确定性执行范式"，此前证据均来自代码/配置编辑场景，已跨过门槛 a 待用户批准沉淀）在设计哲学上高度呼应——"不完全依赖模型的隐式预测，用确定性计算验证/承担可以被确定性建模的那部分"，首次以自动驾驶世界模型的形式出现，但任务性质与线索 3 现有证据差异较大，本期只作为跨领域设计哲学的参考记录，不直接合并进线索 3。
- 证据边界：全部数字来自作者自建的 NAVSIM v1/v2 navtest 与 NAVHARD 基准，未见独立第三方复现；8 位作者所属机构未披露；"无需额外训练即有提升"的具体幅度摘要未给出，需读正文图表确认；真实道路场景下的安全性与可执行代码部分的覆盖范围（能处理多复杂的动力学/交通规则）未讨论；预印本，无同行评审信息。
- 原文：[CodeWAM: A Code World Action Model for End-to-End Autonomous Driving](https://arxiv.org/abs/2611.32483)（检索于 2026-11-25）

### 5. Auditing the Judge：LLM 裁判也有自己的"偏见"，而且偏见强度因模型而异、可以被量化纠偏（今日最值得细读）
- 领域：AI / 智能体（第二条，今日最值得细读）
- 来源 / 发布日期：arXiv / 2026-11-25（announced；v1 于 2026-11-24 UTC 18:05 上传），Hamin Koo、Chanjoo Jung、Fangzhao Wu、Jaehyung Kim（机构未披露；NeurIPS 2026 投稿）
- 摘要：论文指出，用 LLM 做自动评委已越来越普遍，但其判断常带有与人类偏好相冲突的系统性偏差；已有工作依赖预先列好的偏差清单，忽视偏差强度，且纠偏手段成本高昂。作者提出 HUB-J 框架：利用人类与 LLM 评委意见不一致的案例，发现可解释的偏差因子；再利用双方意见一致的案例，通过受控的输入编辑及其引发的模型判断变化，量化每个偏差因子的强度；最后用一种轻量、无需训练、基于回归的纠偏方法，估计每个偏差因子对判断的影响并将其移除。论文报告 HUB-J 能发现已知与此前未被识别的新偏差因子，揭示不同模型对偏差的易感程度存在差异，并"在跨模型泛化的同时持续降低由偏差驱动的判断翻转"（摘要未给出具体数值，论文另在 20 个额外评委模型与 JudgeBench 数据集上报告偏差效应与翻转率数据，但页面未提取出具体数字）。
- 为何重要：本仓库线索 8（"LLM-as-judge / 评估基准不能被当作一次性冻结的裁判，需要持续校验或演化"）已累积 9 条候选证据、早已跨过门槛 a，此前角度分别覆盖测量不稳定性、评分标准演化、排行榜统计显著性、工具调用信任前提、长时评估可观测性、离身审计不可能性定理、把基准当软件维护、基准有效性审计与评分权限隔离防御——本文补上第十个独立角度：不是诊断"裁判不可信"这一现象，而是给出一套可操作的偏差发现+量化+无训练纠偏方法论，且专门处理"偏差强度因模型而异"这一此前角度未覆盖的维度，是该线索里少见的、同时具备方法论新颖性（NeurIPS 投稿）与直接可用纠偏手段的证据。
- 证据边界：论文页面未给出任何数值结果，"持续降低偏差驱动的判断翻转""揭示新偏差因子"等结论均为摘要层定性表述，具体翻转率降幅、新发现偏差因子的清单与数量需读正文确认；4 位作者机构均未披露；回归式纠偏方法是否会引入新的系统性偏差（例如过度拟合已知偏差模式）论文摘要未讨论；目前仅为 NeurIPS 投稿状态，尚未经同行评审录用确认。
- 原文：[Auditing the Judge: Human-Derived Bias Discovery, Quantification, and Mitigation in LLM Judges](https://arxiv.org/abs/2611.33065)（检索于 2026-11-25）

## 今日主线

这 5 条表面分散，实则共同指向同一个问题：**我们用来衡量/验证 AI 产出的那把尺子，本身有多可信？** SpecEngineeringBench 发现"测试有效性高、覆盖率高"这类表层指标与"真的抓到缺陷"脱钩；Auditing the Judge 证明连 LLM 裁判本身都带系统性偏差，且偏差强度因模型而异；Anthropic 股价跌破发行价，是公开市场用真金白银对"AI 公司基本面是否配得上估值"给出的第一次负面判分；CodeWAM 选择把自车状态演化这部分从"模型隐式猜测"换成"确定性代码计算"，本质上是不信任学习模型单独承担这个判断；Delegent 则反过来证明，把部分判断下放给小得多的模型也不一定会牺牲质量。五条证据合起来提示：无论是测试、裁判模型、股价，还是模型自身的决策权，行业正在各个层面重新审视"谁来判断、怎么判断才可信"这件事，而答案越来越指向"需要独立于被评估对象之外的确定性机制，或至少要能量化判断本身的偏差"。
