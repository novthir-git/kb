### 1. ActBench：把 Cowork Agent 安全评估从“最终回答”推进到完整执行轨迹
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / 2026-08-10
- 摘要：ActBench 用正常任务与可达攻击载荷配对，覆盖 213 个场景、15 类风险、6 类执行空间和 48 个 Web API；研究评估了 15 个模型、6 个开源 Agent，共产生 24,000 条轨迹。固定 Agent harness 时，攻击成功率随模型从 10.1% 到 94.4%；固定模型时，不同 Agent 的结果为 73.7% 到 94.4%，说明模型差异明显，但所有受测 harness 都存在较高风险。
- 为何重要：Agent 即使“把事办成”，也可能在中间步骤泄露数据、污染记忆或越权调用 API，安全门槛必须落到可信日志、状态变化和轨迹证据上。需注意，论文称完整基准含 600 个案例，而公开仓库目前只开放 300 个任务，且不含私有的任务生成与攻击搜索流水线，复现边界并不完整。
- 原文：[ActBench 论文](https://arxiv.org/abs/2608.09476)
- 配图：![ActBench 基准构建框架（来源：ActBench 论文 Figure 1）](https://arxiv.org/html/2608.09476v1/x1.png)

### 2. SWE-Bench ProMax：大型跨文件重构仍是 AI 编码 Agent 的硬骨头
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv（COLM 2026 论文）/ 2026-08-10
- 摘要：SWE-Bench ProMax 收录 170 个专家筛选的真实重构任务，来自 70 个仓库、覆盖 Python、Java、TypeScript、Go、C、C++ 和 Rust；每个任务平均修改 11.4 个文件和 261.6 行代码。作者重写问题描述并人工审查测试范围后，用两种 Agent scaffold 评测前沿模型，最佳结果仍只有 41.2% resolve rate。
- 为何重要：它把评测重点从短小补丁转向“跨文件协调且保持行为不变”，更接近生产级技术债治理。轨迹分析显示，失败 Agent 往往探索轮次更多、实际修改文件却更少，长程协调而非单点编码仍是主要瓶颈。
- 原文：[SWE-Bench ProMax 论文](https://arxiv.org/abs/2608.09802)
- 配图：![不同基准的修改文件数与代码行分布（来源：SWE-Bench ProMax 论文 Figure 1）](https://arxiv.org/html/2608.09802v1/x1.png)

### 3. 模型审查 Python 重构 diff，找到 13 个行为变化缺陷
- 领域：软件工程
- 来源 / 发布日期：arXiv（SBES 2026 论文）/ 2026-08-10
- 摘要：研究者让 foundation model 只看重构前后的 git-style diff，判断 Python 自动重构是否悄悄改变程序行为；他们复用 1,152 次 Rope 重构尝试，并对其中 217 对转换结果运行该方法。研究找到 13 个不同根因的缺陷，涵盖五类重构，其中 12 个在 issue tracker 中被维护者接受为 bug。
- 为何重要：这为传统测试和静态规则增加了一层语义审查，尤其适合动态类型、继承和运行时名称解析造成的隐蔽回归。但样本只覆盖 Rope 和有限重构类型，结论是“可用的附加 oracle”，不是对所有 Python 重构工具缺陷率的估算。
- 原文：[Detecting Behavioral Changes in Python Refactoring Implementations with Foundation Models](https://arxiv.org/abs/2608.09919)
- 配图：![SafeRefactorPy 的 diff 审查流水线（来源：论文 Figure 1）](https://arxiv.org/html/2608.09919v1/x1.png)

### 4. Cambridge Aerospace 融资 3 亿美元，低成本反无人机进入重资本扩张期
- 领域：创业 / 商业
- 来源 / 发布日期：Axios / 2026-08-10

### 5. UnsDrive：让矿区自动驾驶显式推理“未知空间”
- 领域：汽车 / 自动驾驶
- 来源 / 发布日期：arXiv / 2026-08-10
- 摘要：UnsDrive 面向道路结构弱、遮挡多、能见度差的矿区场景，把占用空间显式分为已占用、可通行与未知三类，再用 flow-matching planner 生成多模态轨迹。它还加入轨迹—占用一致性损失、对未知区域的惩罚评分，并发布用于闭环测试的矿区模拟器 MineLoop。
- 为何重要：研究把自动驾驶中的“不知道”从感知残差变成规划约束，适合矿区等封闭但非结构化的商业场景。当前证据仍来自作者的开环与模拟闭环实验，尚不能等同于真实矿卡部署安全性。
- 原文：[UnsDrive 论文](https://arxiv.org/abs/2608.09098)
- 配图：![UnsDrive 与 MineLoop 的闭环流程（来源：UnsDrive 论文 Figure 1）](https://arxiv.org/html/2608.09098v1/x1.png)

## 今日主线

今天的共同趋势不是“Agent 又会做更多事”，而是能力正在被更难的现实约束重新计量：跨文件协调、语义保持、轨迹安全和未知空间推理都要求完整证据链。与此同时，Cambridge Aerospace 的融资显示，资本愿意为有明确采购场景的硬科技支付高估值，但从论文分数或订单信号到可验证的生产可靠性，仍隔着工程化与规模交付两道门槛。
