### 1. OpenAI 推出 Presence，把企业 Agent 的部署、评测与持续改进打成一套产品
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：OpenAI / 2026-07-22
- 摘要：OpenAI 发布面向企业语音和聊天场景的 Presence，围绕单一工作职责配置知识、系统权限、政策、获批动作、模拟评测与人工升级规则；上线后再由 Codex 根据真实会话提出可测试、可审批的更新。OpenAI 称其英文电话支持已由 Presence 处理，75% 的来电无需转人工，10 天内又把人工转接率降低了 15 个百分点；这些效果数据目前均为厂商自报。
- 为何重要：OpenAI 不再只卖模型或 Agent SDK，而是直接进入企业流程改造与长期运营层，竞争焦点转向权限、评测、升级和部署服务。它也意味着系统集成商与企业 AI 平台需要重新回答：哪些 Agent 控制面应自建，哪些可交给模型厂商。
- 原文：[Introducing OpenAI Presence](https://openai.com/index/introducing-openai-presence/)
- 配图：暂无合适的稳定公开配图。

### 2. ReSharper 2026.2 用 ACP 把可替换的编码 Agent 带进 Visual Studio
- 领域：软件工程
- 来源 / 发布日期：JetBrains / 2026-07-22
- 摘要：ReSharper 2026.2 在 Visual Studio 中预览 Junie Agent 模式，并开始接入开放的 Agent Client Protocol（ACP），目标是在同一界面发现和切换本地、远程或企业自建 Agent。新版还把 .NET 调试能力扩展到 VS Code、Cursor、Antigravity、Devin Desktop 和 Kiro 等兼容编辑器，并补充 C# / C++ 分析与性能改进。
- 为何重要：IDE 正从绑定单一助手转向“协议化 Agent 客户端”，代码智能、调试器和项目模型可能成为多个 Agent 共享的基础设施。当前 ACP 支持仍处于早期预览，开放生态的实际价值取决于后续第三方 Agent 注册、兼容性和权限隔离。
- 原文：[ReSharper 2026.2 release](https://blog.jetbrains.com/dotnet/2026/07/22/resharper-2026-2-release/)

### 3. Arrakis 获 3000 万美元 A 轮，押注工业现场的“前置部署工程”
- 领域：创业 / 商业
- 来源 / 发布日期：Arrakis / Business Wire / 2026-07-22；融资信息由 [Accel 投资组合公告](https://www.accel.com/news/portfolio) 交叉核验
- 摘要：成立于 2026 年 1 月的 Arrakis 宣布完成 Blossom Capital 领投、Accel 等参投的 3000 万美元 A 轮，加上此前 750 万美元种子轮，累计融资约 3800 万美元。公司以模型无关平台加驻场工程团队切入航空、能源、物流和制造等关键流程，并把部分收费与客户结果挂钩；本轮资金将用于扩招、强化安全能力及拓展美国和中东。
- 为何重要：资本正在从通用办公 Copilot 转向数据碎片化、系统老旧、部署摩擦更高的工业 Agent。“软件平台 + 前置部署团队 + 结果定价”可能加快落地，但公司尚未披露客户收入、续约率或可独立验证的生产指标，不能把融资规模等同于产品市场契合。
- 原文：[Arrakis funding announcement](https://via.ritzau.dk/pressemeddelelse/15058492/arrakis-comes-out-of-stealth-with-dollar38m-to-help-industrial-enterprises-compete-in-the-ai-era?publisherId=90456)

### 4. 大众与地平线深化 CARIZON 合作，目标 2027 年下半年交付 L3
- 领域：汽车 / 自动驾驶
- 来源 / 发布日期：CARIAD / Volkswagen Group China / 2026-07-22；由 [Reuters 报道](https://live.euronext.com/en/financial-news/volkswagens-carizon-and-horizon-robotics-deepen-self-driving-partnership-china) 交叉核验
- 摘要：大众在华自动驾驶合资公司 CARIZON 获得地平线自动驾驶基座模型的白盒访问权，并计划把它与自研 C7H 芯片、GAIA 世界模型数据平台及中国电子电气架构整合，开发统一的端到端驾驶模型。现有 L2++ 方案已进入量产，计划在 2026 年覆盖 7 款中国新能源车型；L3 能力目标从 2027 年下半年开始交付，后续再面向 L4 乘用车和 robotaxi。
- 为何重要：大众选择“获取模型白盒能力并保留系统所有权”，而非采购黑盒方案，反映传统车企正在把自动驾驶模型、芯片和数据闭环重新内化。L3 时间表仍是厂商目标，最终能否交付取决于安全验证、法规准入和车型级量产质量。
- 原文：[Volkswagen Group China Accelerates L3 and L4 Development](https://cariad.technology/de/en/news/stories/Volkswagen-Group-China-Accelerates-L3-and-L4-Development.html)

### 5. GitHub 把 Copilot 与原始模型 API 的差价解释为“工程工作流层”
- 领域：AI / 智能体（AI 编程工具）
- 来源 / 发布日期：GitHub / 2026-07-22
- 摘要：在 Copilot 转向按模型公开 API 费率计量 AI Credits 后，GitHub 详细拆分了两种采购层级：原始 API 适合自建提示、检索、路由、重试、日志与安全模型，Copilot 则把 Issue、仓库、终端、评审、策略和预算控制组合成编码工作流。其 BYOK 预览允许企业继续使用 Anthropic、OpenAI、Google 等既有模型合同，同时保留 Copilot 的工具与 Agent harness。
- 为何重要：Agent 产品的定价锚正在从“模型调用”转向“成功完成任务所需的上下文、工具、治理和重试成本”。GitHub 称其 harness 在多项基准中以更少 token 达到相近任务解决率，但这是厂商评测；采购方仍应按自身仓库任务核算完成率、总成本与锁定风险。
- 原文：[Copilot vs. raw API access: What are you actually paying for?](https://github.blog/ai-and-ml/github-copilot/copilot-vs-raw-api-access-what-are-you-actually-paying-for/)
