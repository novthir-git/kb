### 1. GitHub 把团队 Skills 与 MCP 上下文正式接入 Copilot 代码审查

- 领域：软件工程
- 来源 / 发布日期：GitHub Changelog / 2026-07-29
- 摘要：Copilot code review 对 Agent Skills 和 MCP Server 的支持转为正式可用，覆盖 Copilot Pro、Pro+、Business 与 Enterprise。团队可在 `.github/skills` 中用 `SKILL.md` 注入内部工具和编码规范，也可通过 MCP 引入工单、文档与服务目录；MCP 工具调用被限制为只读，审查意见会标注是否使用了 Skills 或 MCP 上下文。

### 2. 实验给 Agent 自适应“泼冷水”：静态优化 Harness 反而更稳、更省

- 领域：AI / 智能体
- 来源 / 发布日期：arXiv 预印本 / 2026-07-28
- 摘要：一项新研究把冻结模型外部的 prompt、工具、记忆、规划、验证和步数预算抽象成 729 种可审计配置，再用 contextual bandit 与 REINFORCE 在线选择。研究在 120 个可验证任务、4,620 条轨迹上的结果与预期相反：DSPy 优化的静态基线普遍追平或胜过在线控制器；例如 Bedrock Haiku 的工具任务中，静态方案成功率为 96%、每轮 285 tokens，而 REINFORCE 为 62%、680 tokens。
- 为何重要：这为“让 Agent 自动改 Harness 就会持续变好”提供了有价值的反例。对任务池小、样本预算紧的生产系统，更现实的顺序可能是先用可验证指标做静态优化，再在分布漂移或积累足够轨迹后引入在线学习；但该结论目前仅来自一篇小规模预印本。
- 原文：[arXiv:2607.25415](https://arxiv.org/abs/2607.25415)
- 配图：论文的可靠性—成本对比图（来源：arXiv 论文原文）。

### 5. Agent 开始“预执行”下一次工具调用，研究瞄准等待时间而非更多推理

- 领域：AI / 智能体
- 来源 / 发布日期：UCSB、LinkedIn / arXiv 预印本 / 2026-07-28
- 摘要：研究者提出 self-speculating agent：同一个模型一边完成任务，一边从当前轨迹预测并提前执行下一次工具调用，复用模型权重与 prefix KV cache，而不是另挂一个小模型做预测。联合 Agent–Speculator RL 将 Qwen3-4B 的下一工具调用 Hit@1 从 44.1 提升至 61.2，将 Qwen3.5-4B 从 48.9 提升至 66.3；同域测试中的任务成功率基本保持稳定。
- 为何重要：长链 Agent 的体验瓶颈越来越来自搜索、数据库和业务 API 的往返等待，而非单次 token 生成。若工程化验证成立，工具调用推测可像 speculative decoding 一样隐藏外部延迟；不过论文也显示跨域迁移会损害任务成功率，不能把更准的调用预测等同于更可靠的完整 Agent。
- 原文：[arXiv:2607.25816](https://arxiv.org/abs/2607.25816)

## 今日主线

今天的共同趋势不是“再换一个更强模型”，而是把竞争推进到 Harness、上下文、供应链安全、制造交付和工具延迟这些系统层。GitHub 与两篇 Agent 研究分别显示，可审计上下文和低成本静态基线正在变得更重要；Claros 与 Aurora 则提醒，技术跨过验证门槛后，决定商业结果的是规模化执行。关键分歧在于：系统应先追求自适应，还是先把边界、验证与成本控制做扎实。
