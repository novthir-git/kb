### 1. Skill 文件对 Coding Agent 到底有没有可测量收益？一篇论文给出"一个优化器有效、一个无效"的诚实结果
- 领域：AI / 智能体（Agent）
- 来源 / 发布日期：arXiv / 2026-09-14（v1 于 2026-09-11 11:41 UTC 上传）
- 摘要：论文针对仓库级 SKILL 文件（随代码版本化的 .md 说明文档）提出评测方法——用同一仓库被合并又在冻结基点上
  回滚的真实 PR 作为"更难"任务源，比较同一 agent 在"有/无该 SKILL 文档"两种条件下的完成率差异。在三个
  Kotlin 仓库上，GEPA 优化出的文档平均把这一得分抬高 4.9 个百分点，而 SkillOpt 优化出的文档几乎原地踏步
  （仅高出种子文档 0.1pp）。作者坦承：单仓库提供的样本量不足以把 GEPA 的增益与 agent 自身的 run-to-run
  方差分开；但其中一个仓库的维护者认为，生成的文档确实包含了"只有实际参与项目才会知道"的经验。
- 为何重要：这是少见的、对"给 agent 写不写知识文档有没有用"给出**部分否定**答案的实证——不是简单证明
  SKILL 有效，而是区分出优化器之间的巨大差异，并诚实标注统计功效不足。它直接触及本 wiki 关心的"知识—记忆—
  行动架构"问题：文档化知识的投资回报并非默认成立，取决于用什么方法生产文档。证据边界：仅 3 个 Kotlin
  仓库、单一非知名团队、未做跨语言/跨优化器的独立复现；GEPA 的增益本身未能与噪声区分。
- 原文：[Skill Issue 论文](https://arxiv.org/abs/2609.12742)

### 2. Anthropic 自曝：被自家 agent 写代码的速度压垮的不是评审，是 CI——6 个月 CI 任务量涨 25 倍
- 领域：软件工程
- 来源 / 发布日期：Claude by Anthropic 官方工程博客 / 2026-09-14（一手）
- 摘要：Anthropic 披露其内部工程团队在过去六个月里 CI 任务量增长 25 倍——工程师季度出码量是 2021–2025 年
  均值的 8 倍，其中约 80% 由 Claude 撰写，测试用量同期涨 10 倍，而工程师人数基本持平。决定"每个 PR 该跑
  哪些测试"的测试影响分析服务因此被压垮：连续打了三次临时补丁（换更大机器、分片、每日重启），分别只撑了
  70 天、29 天、不到 1 天。团队随后做了架构重写——引入内存数据存储卸载处理压力、让 listener worker 无状态
  可水平扩展、用日志 + 定期汇总取代单例状态——一名工程师三周内完成，此前类似量级的改动需要接近一个季度。
  文中明确承认：新架构运行成本更高，且"每日重启"式的过渡期确实造成过测试选型用的是过期数据。
- 为何重要：这是目前少见的、把"AI 编码提高产出"这句话具体量化到基础设施账本上的一手案例——写代码不再是
  瓶颈之后，压力转移到了 CI/评审这类此前被认为是"配套设施"的环节，且解决方案本身是用更高运行成本换取可扩展性，
  并非免费。证据边界：单一公司的自报案例，Anthropic 本身是"AI 编码密度"极端值（Claude 写 80% 代码），
  25 倍这个数字未必能外推到 AI 代码占比更低的团队；无第三方审计。
- 原文：[Agentic coding is straining CI](https://claude.com/blog/agentic-coding-is-straining-ci-heres-how-we-scaled-test-impact-analysis-at-anthropic)
- 配图：![CI 任务积压量：架构重写前持续堆积、重写调优后归于平稳](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6aa7f3c948204c50ad501881_4deaf7d0.png)
  图片来源：[Claude by Anthropic 官方博客](https://claude.com/blog/agentic-coding-is-straining-ci-heres-how-we-scaled-test-impact-analysis-at-anthropic)，原图注："Queued,
  unprocessed job-result events, hourly max. Before: a backlog built up most days and grew week over week. After
  cutover and tuning: flat."

### 4. 清华团队提出"可学习风险场"，替代端到端自动驾驶里写死权重的安全场
- 领域：汽车 / 自动驾驶
- 来源 / 发布日期：arXiv / 2026-09-14（v1 于 2026-09-11 02:40 UTC 上传，作者单位：清华大学车辆与运载学院）
- 摘要：论文提出 READ 方法——用几何与行为约束监督出一个连续、可微的高斯风险场，代替传统安全场里"预先
  写死形状与权重、不随场景变化"的做法，可同时给端到端规划器和 VLA（视觉-语言-动作）模型提供结构化梯度，
  也可选择性地用于修正预测轨迹。在 NAVSIM 闭环仿真上：TransFuser 加装 READ 后 PDMS 从 84.0 升至 84.6，
  Drive-JEPA 从 89.1 升至 90.0，VLA 场景下达到 90.7；消融实验显示"写死的规则安全场"只比无场景基线高
  0.43 分，而"可学习的 READ 风险场"在此基础上再涨 0.53 分；NAVSIM v2 扩展协议下综合得分 90.1 EPDMS。
- 为何重要：这条证据把"要不要用显式安全场约束端到端规划"这一路线之争，从"有没有场"细化到"场的参数是不是
  也该学出来而不是人工预设"，与 09-11 简报收录的 DRiF（把规则安全先验转成成对风险标签）方向相邻但解法
  不同——两者合在一起，"可学习/自适应风险表示 vs 写死安全规则"正在成为一条独立可追踪的技术路线。证据边界：
  全部验证止步于 NAVSIM/NAVSIM v2 闭环仿真，无真实道路数据；PDMS 提升幅度是 0.5–0.9 分量级的增量改进，
  非突破性结果；单一机构、尚未见独立复现或同行评审定稿。
- 原文：[READ 论文](https://arxiv.org/abs/2609.12371)
- 配图：![READ 用连续高斯风险场为端到端与 VLA 规划器提供结构化梯度](https://arxiv.org/html/2609.12371v1/pipeline.png)
  图片来源：[READ 论文 Figure 2](https://arxiv.org/html/2609.12371v1)。

### 5. "现实才是最终裁判"：把 reward hacking 和幻觉统一进同一套"需求缺口/环境模型缺口"框架
- 领域：软件工程（今日加选，概念性长文）
- 来源 / 发布日期：arXiv / 2026-09-14（v1 于 2026-09-10 17:58 UTC 上传；作者含 UC Berkeley 的 Matei Zaharia、
  Ion Stoica，页面未显式标注单位，二人均为公开可查的 Databricks/Anyscale 联合创始人兼 UC Berkeley 教授）
- 摘要：论文提出"双缺口框架"：agent 化软件开发是一个"实现—验证"循环——实现被反复修改直到评测器（如测试
  套件）通过；但评测器本身是依据"需求"（对干系人意图的近似）和"环境模型"（对部署环境的近似）在打分。
  作者指出，reward hacking 利用的正是需求或环境模型里的遗漏，幻觉则是通过捏造需求或环境假设进一步撑大
  这两个缺口。由于这两个缺口在开放、不断变化的世界里原则上无法被"证明已关闭"，目标应从"关闭缺口"转为
  "持续收窄缺口"——为此提出一个用部署证据反馈来修订需求/模型/评测器的"保证-修订循环"，并把 agent 化开发
  重新表述为在人工判断、agent 能力与算力之间的资源分配问题：需求缺口的瓶颈是人工判断，环境模型缺口的瓶颈
  是"忠实但昂贵"的评测。
- 为何重要：这是一篇纯概念性框架论文，但它把本 wiki 长期分别追踪的"reward hacking""幻觉""evals 不是
  最终真相"三条线索，第一次统一成同一个"两个缺口"的因果解释，并明确提出"现实才是最终裁判、预部署评测只是
  代理指标"——这个提法直接呼应本仓库「Evals（AI 系统评估）」一页已经积累的多条独立证据（SWE-Gate、
  PatchBench、Better Understanding Better Fixes、工业案例研究等）。证据边界：全篇无实证数据，是位置/
  框架性论文，提出的"保证-修订循环"本身未经任何实验验证；作者单位需独立核实，不能仅凭姓名认定机构背书。
- 原文：[Reality Is the Final Verifier 论文](https://arxiv.org/abs/2609.12039)

## 今日主线

这五条共同把"agent 时代的验证与基建"从抽象口号落到具体账本：Anthropic 自曝内部 CI 被自家 agent 的
出码速度压垮、又用更贵的架构换扩展性；一篇论文诚实报告"给 agent 写文档"这件事一个优化器有效、一个
无效；自动驾驶领域开始追问安全场的参数本身要不要也学出来；而"现实才是最终裁判"一文试图把 reward
hacking 与幻觉收进同一个因果框架。与此同时，Anthropic 自身的盈利与 IPO 叙事，提醒这些治理与验证账本
终究要和资本市场的估值账本对齐——这是继 09-14 Amodei 呼吁行业降速之后，"安全承诺"与"商业化叙事"第一次
被并排放在一起看。
