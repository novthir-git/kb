## 6. 补充研究 A:上下文经济性的证据分层(2026-10)
 
对"上下文经济性有没有数据支撑"的追问,结论是**三层证据、强度递减**:
 
1. **长上下文退化本身——充分且跨代际复现**。RULER(2024)区分标称与有效上下文;NoLiMa(2025)去掉字面匹配捷径后,绝大多数模型在 32k 即跌破短上下文性能的 50%;Chroma "Context Rot"(2025,18 模型)显示即使极简任务也随输入长度非均匀退化;截至 2026 年,多事实检索在 200k+ 仍有 30–60pt 可测退化,且没有任何前沿实验室公布过经第三方验证的 500k+ 多事实检索分数。
2. **对 coding agent 的退化——方向一致,样本尚少**。最直接的证据是《The Limits of Long-Context Reasoning in Automated Bug Fixing》(2026):同样的 SWE-bench 任务,agent 式分步约 30% 解决率,而把全部相关代码(召回率 100%)塞进 64k 单次上下文只有 0–7%;失败轨迹平均 token 数约为成功轨迹的 2 倍。作者结论:agent 的成功来自把任务拆成短上下文步骤,而非有效的长上下文推理。SWE-Pruner(裁剪上下文反而提升表现)、LoCoBench 同向。
3. **"代码库结构 → agent 成功率"的直接因果实验——基本缺失**。小文件、代码 SEO 等设计原则是机制推断 + 从业者观察,目前没有"同一任务、重构前后代码库、受控对比"的严格实验;AGENTS.md 是少数有实证研究的实践。此为该支柱的诚实短板。
**会被更强模型抹平吗**:拆成两个维度。质量维度在收窄但未消失——退化起点持续后移(32k→200k→更远),但 softmax attention 下"上下文越满、单位信息利用质量越低"有机制根源,曲线形状还在。经济维度不会被抹平——token 计费与 prefill 延迟下,窄读取永远比全量读取便宜一个数量级以上(读 2k 行 vs 50k 行 ≈ 25×);多 agent 并行依赖可分解的窄变更;人类 review 与 CI 的窄范围需求不随模型变强而消失。

## 7. 补充研究 B:方法论的耐久度盘点——哪些会被抹平,哪些保值(2026-10)
 
判断尺子只有一个:**每条方法论存在的理由是什么?** 补模型短板 → 会被抹平;省计算的钱 → 部分贬值(绝对成本降,相对优势长存);解决人对系统的信任、协调与责任 → 保值;与委派规模正相关 → 升值。用这把尺子过一遍本文档的全部条目:
 
### 7.1 抹平 / 大幅减弱(存在理由 = 模型现在不行)
 
- 上下文经济性的技巧层:极小文件、代码 SEO、文档精细分层
- Context engineering 机制层:compaction、外置笔记、sub-agent 压缩回传——正被 harness 与模型内建吸收,从方法论降格为基础设施
- "ARCHITECTURE.md 点名设计模式激活预训练知识"类 prompt 技巧
- Campaign 中"先 2–3 个文件调 prompt 再全量"的调参仪式
- ACI 的省 token 部分
这一组是 bitter lesson 的作用区:押注模型弱点的工程投资,折旧期可能只有一两年。
 
### 7.2 部分贬值(每条都能切成折旧半 + 沉淀半)
 
| 条目 | 折旧的一半 | 沉淀为资产的一半 |
|---|---|---|
| 上下文经济性整体 | 质量维度(退化在收窄) | 经济维度:窄读取永远便宜 ~25×,与能力无关 |
| 小步 PR / 爆炸半径 | 验证规模化后,安全变更尺寸上限提高 | 不可逆操作的风险管理是治理问题 |
| Seams / strangler fig | 接缝可以开得更大 | 新旧并行、可回退的迁移结构是风险工程 |
| 机器可消费文档 | 能从代码推断的内容会冗余化 | **代码里不存在的信息**(业务意图、历史约束、"为什么不")——不在场的知识无法被推断 |
| ACI / 为 agent 设计工具 | 省 token 动机减弱 | 幂等性、可操作的错误信息:接口工程本体 |
 
### 7.3 保值(存在理由 = 信任 · 协调 · 责任)
 
- **显式契约 / 强类型 / 边界完整性**:契约是并行行为体之间的协调装置——行为体(人 + agent)越多越强,协调装置越重要
- **验证优先架构**:验证解决的不是"模型会不会写错",而是"正确性无法由生成者自我证明"——信任结构问题;且确定性检查永远比模型调用便宜几个数量级
- **Characterization tests 先行**:捕获只存在于运行系统中的真值,模型变强不会让它获得不在场的信息
- **理解优先(逆向提取业务规则再重写)**:被更强模型增强而非淘汰的方法
- **Prompt 纳入架构评审**:单个 prompt 触发的架构决策随模型能力变大,治理需求与能力成正比
- **任务可分解性**:并行、归因、回滚、审查的共同前提,是组织工程而非模型工程
### 7.4 升值(模型越强,问题越大)
 
1. **认知债管理**:委派比例从 0–20% 往上走的过程,就是团队理解流失加速的过程——整个方法论中唯一与模型能力正相关恶化的风险。
2. **意图规格化(SDD 的内核)**:生成成本趋零后,瓶颈收敛为"把人想要什么说清楚"。Spec Kit/Kiro 的三步 markdown 流程会贬值(仪式,归 7.1),但"意图是不可约减的人类输入"随生成能力增强而愈发突出——这是 AaaS "intent architect" 判断里站得住的那一半。
### 7.5 对第 5 节优先级顺序的重审
 
原顺序"验证网 → agent 接口层 → 边界重构 → campaign"按折旧速度重新着色:验证网与边界是保值资产;接口层约一半折旧(只写代码里不存在的隐性知识);campaign 的调参仪式折旧最快。**顺序在更强模型的世界里更成立:先投折旧最慢的。** 支柱不是贬值/保值的单位,条目才是——每个支柱里都同时有折旧件和资产件。
