# 第三方工具兼容

> 按需规范，由根目录 `AGENTS.md`「按需规范索引」指向；触发条件命中时先读本文件再动手。
> `AGENTS.md` 与 `rules/` 下各文件共同构成本仓库的权威 schema，每条规则只写在一处。

本仓库布局已适配 [nashsu/llm_wiki](https://github.com/nashsu/llm_wiki) 桌面应用，使其可直接作为
project 打开（图谱可视化、社区检测、hybrid 检索）。注意：**Karpathy 原文没有规定目录结构**，
这套布局是那个实现的约定，不是"标准"——适配它买的是生态兼容性。约束：

- **Claude Code 是 `wiki/` 的唯一写手**（铁律 7）。该 App 只当阅读器与图谱/检索工具，
  **不得用它的 ingest 写 wiki**：它会用自己的 LLM 重写页面、丢弃它不认识的 frontmatter 字段，
  `overview.md` 会被整篇覆写，且它按「每源必建 source 页」工作，与铁律 4 相反。
- 若开启它的 source 文件夹自动监听：必须把 `output`、`briefs`、`rules`、`.claude`、`.agents` 加入 excludeDirs，
  并从 includeExtensions 去掉 `html`/`htm`——否则 `output/shared/` 的对外 HTML 会被当素材摄入。
- `.llm-wiki/`（它的本机项目状态与 UUID）已在 `.gitignore` 中，不入库。
- 它从**项目根**读 `purpose.md`/`schema.md`，另一条摄入路径从 `wiki/` 读——故根目录保留两个 symlink
  指向 `wiki/` 下的真身。
- 它对未知目录的处理是「目录名即页面类型」，所以 `analyses/`、`topics/` 无需改名即可被识别。

**通用 `llm-wiki` skill 的路径覆盖**：本机安装的 `llm-wiki` skill（`.claude/skills/llm-wiki/`、
`.agents/skills/llm-wiki/`）其 `SKILL.md` 仍按「`index.md` / `log.md` 在仓库根」的默认布局描述流程
（约 11 处）。**本仓库 schema 覆盖它**：在本仓库内一律读写 `wiki/index.md` 与 `wiki/log.md`，绝不在根目录
重建这两个文件。不修改已安装 skill 的文件（它是通用件，且会被升级覆盖）。
