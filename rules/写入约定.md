# 写入约定：页面类型、页面格式、index 与 log

> 按需规范，由根目录 `AGENTS.md`「按需规范索引」指向；触发条件命中时先读本文件再动手。
> `AGENTS.md` 与 `rules/` 下各文件共同构成本仓库的权威 schema，每条规则只写在一处。

## 页面类型怎么选

- 一次研究问答的深度产出 → `analyses/`（默认增长来源，拿不准时选它）
- 会跨多源、需持续追加证据（含"证据点表"）的长期论题 → `topics/`
- 你我形成的、演化中的立场与判断 → `synthesis/`
- 人物、公司、产品、工具、机构 → `entities/`；技术概念、方法论、可复用主题 → `concepts/`
- 多方案/多观点比较 → `comparisons/`
- **`sources/` 摘要页按需，不强制与 raw 1:1**：ingest 摄入的源→建摘要页；research 存档到
  `raw/sources/articles/` 的网页，仅当"被 ≥2 个 wiki 页引用"或"本身值得独立摘要（如奠基性方法论）"
  时才建页，否则由引用页内的 URL + 检索日期直接溯源——避免 `sources/` 堆满一次性存档。

## 页面约定

- 语言：正文用**中文**；术语、人名、公司名保留原文（如 RLHF、Anthropic）。
- 文件名：中文实体/主题直接用中文名（如 `微信公众号.md`）；英文术语用英文原名（如 `Codex.md`）。
- **全库文件名唯一**（跨目录也不得重名）：Obsidian `[[页面名]]` 按**文件名**解析、不含路径，
  两个同名文件（如 `entities/Codex.md` 与 `concepts/Codex.md`）会让双链歧义。新建页前先确认无重名。
- 链接：**Obsidian 双链** `[[页面名]]` 或 `[[页面名|显示名]]`。悬空链接是合法的"待写标记"，
  但必须在页面里明确标注"待写"。
- **重命名 / 合并页面必须善后**：全库 `grep` 旧页名 → 更新所有入链；或把旧页保留为一行 stub 指向
  新页（`已并入 [[新页]]`）。绝不留因合并 / 改名产生的**意外**悬空链接。改动记入 `wiki/log.md`。
- 每页开头必须有 YAML frontmatter：

```yaml
---
tags: [分析]                    # 页面类型：实体/概念/主题/对比/分析/综合/素材
created: 2026-07-03
updated: 2026-07-03
sources:                        # 用块状列表，不用行内数组
  - "[[某源摘要页]]"
  - "https://example.com （检索于 2026-07-03）"
---
```

  `sources` 必须用**块状列表**：行内数组 `["[[页]]", ...]` 会被第三方工具的解析器在第一个 `]`
  处截断（只取到 `[[页`，其余条目丢失），块状列表则解析正常。

- 每个关键论断都要可溯源：双链指向源摘要页，或 URL + 检索日期。
- 区分"源中的事实"与"你的综合推断"，后者标注"综合："。
- **矛盾必须显式标注**，不许静默覆盖。统一格式：
  `> ⚠️ 矛盾：[[源A]] 称 X，但 [[源B]] 称 Y。（发现于 2026-07-03）`
- **`topics/` 证据点表统一表头**：`| 日期 | 来源 | 信号 | 备注 |`，各页保持一致，避免格式漂移。
- **`wiki/overview.md` 的 `sources` 只列外部 URL，不罗列内部页面**（内部关联由正文双链 +
  `wiki/index.md` 承载）。理由：罗列内部页会形成"正文双链 / index 条目 / frontmatter"三份副本，
  每加一页要三处同步——正是 [[代码与文档漂移的本质]] 所述的漂移温床。无外部来源时写 `sources: []`。
- 页面保持精炼。宁可多建小页多加链接，不写万字长页。
- **`entities/` 页按时间保鲜**：新信息覆盖旧状态时，旧状态移入页内"历史"小节而非删除。
- **同一实体横跨领域**（如一家 AI 公司既是技术实体也是投资标的）→ 一个 entity 页 + 多标签，
  不建重复页面。
- **编辑任何 wiki 页面，都要同步 bump `updated`**（新建页则 created = updated）。
  **唯一例外：纯机械迁移**（批量路径改写、格式统一等不改变论断的编辑）**不 bump**——`updated` 是
  内容保鲜信号，误 bump 会让"这页有新判断"变成噪音。
  此类改动改为在 `wiki/log.md` 记一条 `schema` 条目，说明涉及范围。

## wiki/index.md 与 wiki/log.md

**`wiki/index.md`**（内容导航，每次沉淀/摄入必更新）：顶部"概览"只维护素材总数、页面总数、
最后更新日期——**不维护分类明细计数**（易漂移，需要时用 `rules/体检流程.md` 的计数命令派生）；随后按类别分节，
每页一行：`- [[页面名]] — 一句话描述`。

**`wiki/log.md`**（时间日志，只追加不修改）：每条以统一前缀开头，便于 grep：

```markdown
## [2026-07-03] research | Codex 的设计模式
联网研究，沉淀 [[codex-design-patterns]]，更新 [[Codex]]、[[agent-architecture]] 等 4 页。
```

前缀格式固定为 `## [YYYY-MM-DD] research|ingest|lint|output|schema | 标题`：

| 前缀 | 含义 | 是否必记 |
|---|---|---|
| `research` | 联网研究并沉淀 | 必记 |
| `ingest` | 摄入源 | 必记 |
| `lint` | 体检 | 必记 |
| `output` | 生成或更新 `output/shared/` 的对外 HTML | 必记 |
| `schema` | 修改维护规范（`AGENTS.md` 或 `rules/`），或纯机械迁移 | 必记 |
| `query` | 纯问答（未改动任何页面） | **默认不记**，仅用户明确要求存档时启用 |

纯 query 不记，以免 log 噪音膨胀——若某次 query 暴露了知识空白，转成 `wiki/overview.md`
「悬而未决」的一条，而非 log 条目。
