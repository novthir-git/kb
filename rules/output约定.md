# output/ HTML 呈现层约定（派生视图层）

> 按需规范，由根目录 `AGENTS.md`「按需规范索引」指向；触发条件命中时先读本文件再动手。
> `AGENTS.md` 与 `rules/` 下各文件共同构成本仓库的权威 schema，每条规则只写在一处。

`output/` 是**给人读的 HTML 交付层**：把知识渲染成可直接打开、可直接发出去的单文件网页。
**它是交付物，不是知识资产**——不计入页面数、不进索引、**不进 lint**，你不为它的新鲜度负责。
它对 wiki 只有一条义务，方向朝内不朝外：遵循 [[代码与文档漂移的本质]] 的原则一，
**可以重复展示，不能让知识只住在这里**。

## 两类用途，两套约束

| | `output/personal/`（自用） | `output/shared/`（对外分享） |
|---|---|---|
| 读者 | 只有用户自己 | 同事、客户、公开链接 |
| 文件名 | `<slug>.html`，稳定名 | `<slug>-YYYY-MM-DD.html`，日期即版本 |
| 修订 | 直接覆盖重渲染 | **不得原地覆盖**：另存新日期文件，旧文件保留 |
| 内容 | 无限制：可含内部代号、未定稿判断、粗略数据 | 不得含内部代号、客户名、内部路径、未核实数据；不确定的判断标注置信度 |
| 引用 | 可保留 `[[双链]]` | 双链必须展开为标题或外部 URL（外部环境解析不了双链） |

冻结理由：文件一旦发出，链接与副本已在别人手里，原地改写会造成"同一文件名指向不同内容"——
这就是表达漂移的对外版本。

personal → shared 是一次**显式动作**，不是移个目录：过一遍脱敏与可溯源检查，再另存为带日期的新文件。
方向不可逆——内部件误发为对外件不可撤回，反之无损。因此**存量或来源不明的 HTML 一律按"已对外发出"
处理：不覆盖、不删除、不改写，先问用户**。

## 不得成为第二事实源

- **原创稿必须回灌 wiki。**（本节唯一的硬要求）若一份 HTML 的内容量超出现有 wiki 沉淀
  （典型：对外方案稿），那份判断事实上已成了权威产物却只住在交付物里。必须把可复用的**论点**
  回写成 wiki 页面，`output/` 只保留渲染结果。
  注意方向：这保护的是 **wiki 的完整性**（别让知识只存在于一份没人维护的交付物里），
  不是把 output 纳入知识管理。
- **不手改 HTML。** 要改内容 → 改对应 wiki 页 → 重新渲染。直接改 HTML 会让同一份内容出现两个版本。
  这是为了你手上不出现自相矛盾的两份文件，不是对 output 的维护义务。
- **建议（不强制、不校验）**：页内写清来源与生成日期——机器可读的
  `<meta name="canonical-source">` / `<meta name="generated">`，页脚给人读的一行来源 + 生成日期 +
  外部引用。纯粹方便日后自己回溯，缺了不算问题，lint 不检查。
- **不写入 `wiki/index.md`，不计入 wiki 页面数**，不建索引，**wiki 页也不登记 `renders:`**。
  `renders:` 字段自 2026-08-31 起废止：不再新增、不再校验、不再据其触发重渲染；
  存量字段留着无害，下次编辑该页时顺手删掉即可。

## 技术约定（单文件自包含）

- 单个 `.html`：**inline CSS/JS，零 CDN，零构建**，图片走 data URI——断网可读、可直接当附件发出。
- `<html lang="zh-CN">` + `<title>` + viewport meta；宽内容（表格、代码块）自带横向滚动容器，
  页面本体不横向滚动。
- 视觉沿用现有 editorial 风格（ivory/slate/clay/olive/rust + ui-serif/system-ui），由 `thariq-html`
  skill 承载；换风格先说明理由，避免风格漂移。
- 交付前自查：本地打开无 console 报错、无外部网络请求、移动端宽度不溢出。

## 日志与删除

- **`shared/` 的生成与更新必记 `wiki/log.md`**（前缀 `output`），因为已对外发出、需要可追溯；
  `personal/` 不记（可随时重生成，无对外后果）。
- **删除**：本仓库是 git 仓库（主分支 `main`），已提交内容可恢复；未提交改动与 `.gitignore` 内
  文件不可恢复。`output/` 下任何删除仍必须先问用户。
